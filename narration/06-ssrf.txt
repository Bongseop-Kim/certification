정보보안기사 실기 궁금증 6편. 이미지 주소 하나로 내부 서버를 불러낼 수 있을까?

메신저나 게시판에 인터넷 주소를 붙여 넣으면, 잠시 뒤 그 페이지의 제목과 대표 이미지가 미리보기로 뜹니다. 우리 브라우저가 그 주소에 다녀온 것이 아닙니다. 서버가 대신 그 주소에 요청을 보내 내용을 받아 온 겁니다. 이렇게 서버가 대신 요청을 보내는 기능에서 주소를 검증하지 않으면 문제가 생깁니다. 공격자가 서버를 통해 내부망 자원에 접근하게 되는 이 취약점을 서버 측 요청 위조, 에스에스알에프라고 합니다.

그런데 정말 주소 하나만 바꿔 넣어서 바깥에서는 들어갈 수 없는 내부 서버를 열어 볼 수 있을까요?

이 궁금증을 풀려면 먼저 서버가 어디에 서 있는지부터 알아야 하는데, 웹 서버는 바깥 인터넷과 내부망의 경계에 걸쳐 있습니다. 공격자가 이미지 주소 대신 내부 관리 서버 주소를 넣었다고 하겠습니다. 백이십칠 점 영 점 영 점 일 같은 서버 자신의 주소를 넣을 수도 있습니다. 그러면 서버는 그 주소로 요청을 보내고 결과를 보여 줍니다. 바깥에서는 방화벽에 막힌 주소라도, 내부망 안에 있는 서버는 접근할 수 있습니다. 즉 공격자는 서버를 대리인으로 삼아 방화벽을 넘는 겁니다.

실제로 실기에는 서버가 클라이언트 요청을 통해 내부 네트워크 자원에 접근하게 되는 공격의 이름을 묻는 단답형이 나왔습니다. 에스에스알에프는 몇 회차 뒤에 같은 소재로 다시 출제되는 단골이기도 합니다.

지난 편의 씨에스알에프와 헷갈리기 쉽습니다. 씨에스알에프는 사용자의 브라우저가, 에스에스알에프는 서버가 원치 않는 요청을 보냅니다. 즉 속는 쪽이 사용자냐 서버냐로 갈리는 겁니다.


그렇다면 에스에스알에프는 왜 클라우드 환경에서 특히 위험하다고 할까요?

이 궁금증을 풀려면 메타데이터 서비스를 알아야 하는데, 클라우드 가상 서버는 특별한 주소로 자기 정보를 조회할 수 있습니다. 백육십구 점 이백오십사 점 백육십구 점 이백오십사라는 주소입니다. 이를 인스턴스 메타데이터 서비스, 아이엠디에스라고 합니다. 여기에는 서버에 부여된 아이엠 롤의 임시 자격 증명도 들어 있습니다. 클라우드 자원을 조작할 수 있는 키입니다. 공격자가 에스에스알에프로 이 경로를 요청하게 만들면, 서버가 그 키를 받아 공격자에게 보여 줍니다.

그래서 나온 방식이 아이엠디에스 버전 투입니다. 버전 원은 겟 요청 한 번이면 바로 정보를 줬습니다. 버전 투는 먼저 풋 요청으로 세션 토큰을 발급받고, 그 토큰을 헤더에 넣어야만 정보를 줍니다. 에스에스알에프 공격자는 대개 주소만 조작할 수 있고, 요청 방식이나 헤더는 바꾸기 어렵습니다. 그래서 버전 투를 강제하면 자격 증명 탈취가 어려워집니다.

애플리케이션에서는 서버가 요청할 수 있는 대상을 좁힙니다. 첫째, 허용할 도메인이나 주소를 화이트리스트로 정합니다. 둘째, 사설 아이피 대역, 루프백 주소, 메타데이터 주소로 가는 요청을 차단합니다. 셋째, 리다이렉트를 따라가지 않습니다. 외부 주소가 리다이렉트로 내부 주소를 가리키는 우회가 있기 때문입니다. 넷째, 주소를 문자열이 아니라 실제로 해석된 아이피로 검사합니다. 같은 주소를 십진수나 다른 표기로 바꿔 필터를 우회하는 방법이 있기 때문입니다. 그리고 아이엠 롤의 권한은 꼭 필요한 만큼만 줍니다.


그런데 서버가 사용자 입력으로 운영체제 명령까지 대신 실행해 준다면 어떻게 될까요?

관리자 페이지에 아이피를 넣으면 서버가 핑 명령을 실행해 결과를 보여 준다고 하겠습니다. 코드가 핑 명령 뒤에 입력값을 그대로 붙여 셸에서 실행한다면 어떨까요? 공격자는 아이피 뒤에 세미콜론을 붙이고, 캣 슬래시 이티씨 슬래시 패스워드를 이어 씁니다. 세미콜론은 앞 명령이 끝나면 다음 명령을 실행하라는 뜻입니다. 그래서 핑 다음에 패스워드 파일을 읽는 명령이 실행됩니다. 세로 막대 기호인 파이프, 앰퍼샌드 두 개, 백틱도 명령을 잇는 데 쓰입니다.

이처럼 외부 입력값이 운영체제 명령의 일부로 실행되는 취약점을 운영체제 명령어 삽입이라고 합니다. 기존 실기 문항에서는 자바의 런타임 점 익젝으로 외부 입력을 실행하는 코드를 주고, 취약점 이름과 보완 대책을 쓰게 했습니다.

대응은 외부 입력을 명령으로 직접 실행하지 않는 것입니다. 가능하면 같은 기능의 라이브러리 함수를 씁니다. 꼭 필요하다면 허용할 값만 화이트리스트로 정하고, 세미콜론, 파이프, 앰퍼샌드 같은 연결 문자를 걸러 냅니다.


이번에는 첨부 파일 기능입니다. 파일 이름만 바꿔서 서버의 다른 파일도 내려받을 수 있을까요?

다운로드 점 제이에스피 물음표 파일 이퀄 공지 점 피디에프처럼, 파일 이름을 파라미터로 받는 기능이 있다고 하겠습니다. 공격자는 파일 값에 점점 슬래시를 여러 번 반복한 뒤 이티씨 슬래시 패스워드를 붙입니다. 그러면 첨부 파일 폴더에서 최상위 디렉터리까지 올라가 시스템 파일을 내려받게 됩니다. 이처럼 상위 디렉터리를 뜻하는 점 두 개로 허용된 폴더 밖에 접근하는 공격을 경로 조작이라고 합니다. 패스 트래버설이라고도 합니다. 이렇게 파일이 새어 나가는 취약점을 파일 다운로드 취약점이라고 합니다. 기존 실기 문항에서도 로그를 주고 이 취약점과 조작된 파라미터를 찾게 했습니다.

그렇다면 점점 슬래시라는 글자만 걸러 내면 될까요? 공격자는 필터를 피하려고 유알엘 인코딩을 씁니다. 슬래시는 퍼센트 이에프, 점은 퍼센트 이이로 바꿔 보냅니다.

그래서 대응은 파일 이름 대신 데이터베이스에 저장한 파일 번호로 받는 겁니다. 경로를 받아야 한다면 경로 문자를 걸러 내고, 최종 경로가 다운로드 폴더 안에 있는지 검사합니다.


그런데 불러온 파일을 서버가 실행까지 해 버린다면 어떨까요?

피에이치피는 인클루드나 리콰이어 함수로 다른 파일을 불러와 코드로 실행합니다. 이때 불러올 파일 이름을 외부 입력으로 받아 생기는 취약점을 파일 인클루전이라고 합니다. 페이지 값에 점점 슬래시를 붙여 서버 안의 다른 파일을 불러오게 하면 로컬 파일 인클루전, 엘에프아이입니다. 페이지 값에 공격자 서버 주소를 넣어 외부 스크립트를 불러오게 하면 리모트 파일 인클루전, 알에프아이입니다.

즉 다운로드는 파일 내용을 내주기만 하지만, 인클루전은 불러온 파일을 코드로 실행하는 겁니다.

그럼 외부 파일을 못 부르는 엘에프아이는 덜 위험할까요? 그렇지 않습니다. 사용자 에이전트 헤더에 피에이치피 코드를 넣어 요청하면, 그 코드가 액세스 로그에 기록됩니다. 엘에프아이로 그 로그 파일을 불러오면 기록된 코드가 실행됩니다.

대응은 불러올 파일을 화이트리스트로 정하는 겁니다. 그리고 피에이치피 점 아이엔아이에서 얼라우 유알엘 인클루드와 얼라우 유알엘 에프오픈을 오프로 둡니다. 기존 실기 문항에 인클루드, 리콰이어, 피에이치피 점 아이엔아이, 오프를 빈칸으로 채우는 문제가 있었습니다.


그렇다면 이 취약점들은 왜 한 편에 묶였을까요?

사용자가 준 값을 서버가 그대로 믿었다는 같은 실수에서 나오기 때문입니다. 에스에스알에프는 주소를, 명령어 삽입은 명령 인자를, 경로 조작과 인클루전은 파일 경로를 믿었습니다. 그래서 서술형 대응에는 세 가지 공통 원칙을 함께 적으면 좋습니다.

첫째, 검증은 반드시 서버에서 합니다. 브라우저의 자바스크립트 검사는 웹 프록시로 쉽게 우회됩니다. 둘째, 막을 값을 나열하는 블랙리스트보다 허용할 값만 정하는 화이트리스트가 안전합니다. 블랙리스트는 인코딩, 대소문자 변형, 새로운 기호로 우회되기 쉽기 때문입니다. 셋째, 웹 서버 프로세스에 최소 권한만 줍니다. 취약점이 뚫리더라도 읽을 수 있는 파일과 실행할 수 있는 명령이 줄어들어 피해가 작아집니다.

이 원칙은 지난 편들의 에스큐엘 인젝션, 엑스에스에스, 파일 업로드에도 그대로 적용됩니다. 소프트웨어 개발 보안 가이드에서는 이 취약점들을 모두 같은 유형으로 묶습니다. 입력 데이터 검증 및 표현이라는 유형입니다.


정리해 보면, 이미지 주소 하나로 내부 서버를 불러낼 수 있는 이유는 서버가 공격자 대신 내부 주소로 요청을 보내기 때문입니다. 이를 에스에스알에프라고 하고, 위조당하는 쪽은 서버입니다. 클라우드에서는 아이엠디에스의 자격 증명이 표적이고, 버전 투는 풋 요청으로 세션 토큰을 먼저 받아야 합니다. 대응은 허용 주소 화이트리스트, 내부 대역과 메타데이터 주소 차단, 리다이렉트 금지입니다. 명령어 삽입은 세미콜론과 파이프로 명령을 잇고, 외부 입력을 명령으로 직접 실행하지 않는 것이 대응입니다. 경로 조작은 점점 슬래시로 상위 폴더에 올라가고, 파일 번호로 받아 막습니다. 엘에프아이는 서버 안의 파일을, 알에프아이는 외부 파일을 불러와 실행합니다. 얼라우 유알엘 인클루드는 오프로 둡니다. 공통 원칙은 서버 측 검증, 화이트리스트, 최소 권한입니다.
