- 치환 암호(대치 암호): 비트, 문자 또는 문자의 블록을 다른 비트, 문자 또는 블록으로 대체, 교환하는 규칙
- 전치암호: 비트, 문자 또는 블록이 원래 의미를 감추도록 재배열, 자리를 바꾸는 규칙

블록 암호와 스트림 암호
- 블록 암호: 특정 비트 수의 「집합」을 한 번에 처리하는 암호 알고리즘의 총칭
- 스트림 암호: 한번에 1비트 혹은 1바이트의 데이터 흐름(스트림)을 순차적으로 처리해가는 암호 알고리즘의 총칭

위치에 따른 암호화 구분
- 링크 암호화: 모든 정보는 암호화되고, 패킷은 라우터나 다른 중간에 있는 장비가 이 패킷을 다음에 어디로 보내야 하는지 알아야 하기 때문에 각 홉(hop)에서 해독됨
- 종단간 암호화: 종단간 암호화에서는 헤더와 트레일러가 암호화되지 않기 때문에 패킷을 각 홉에서 해독하고 암호화할 필요가 없음

HW 암호와 SW 암호
- 하드웨어 암호: 하드웨어로 실현하기 위해 컴퓨터와 통신기기의 내부버스와 외부 인터페이스에 전용 암호처리용 하드웨어를 설치하여 데이터를 암호화
- 소프트웨어 암호: 소프트웨어로 실현하기 위해 암호처리용 소프트웨어를 사용하여 데이터를 암호화

## IMG_5133 — 암호분석의 분류 (COA/KPA/CPA/CCA), 케르히호프의 원리 (textbook)

④ 암호분석의 분류

구분        | 영어                              | 개념                                                                 | 비고
암호문 단독공격 | COA, Ciphertext Only Attack        | 단지 암호문 C만을 갖고 이로부터 평문 P나 키 K를 찾아내는 방법으로 평문 P의 통계적 성질, 문장의 특성 등을 추정하여 해독하는 방법 | 암호해독자에게는 가장 불리한 방법
기지 평문공격  | (KPA, Known Plaintext Attack)      | 암호문 C와 평문 P의 관계로부터 키 K나 평문 P를 추정하여 해독하는 방법        | 암호문에 대응하는 일부 평문이 사용가능한 상황에서의 공격
선택 평문공격  | (CPA, Chosen Plaintext Attack)     | 암호기에 접근할 수 있어 평문 P를 선택하여 그 평문 P에 해당하는 암호문 C를 얻어 키 K나 평문 P를 추정하여 암호를 해독하는 방법 | 평문을 선택하면 대응하는 암호문을 얻을 수 있는 상황에서의 공격
선택 암호문공격 | (CCA, Chosen Ciphertext Attack)    | 암호 복호기에 접근할 수 있어 암호문 C에 대한 평문 P를 얻어내 암호를 해독하는 방법 | 암호문을 선택하면 대응하는 평문을 얻을 수 있는 상황에서의 공격

Mentor's Know-how
- 암호방식의 정규 참여자가 아닌 제3자가 암호문으로부터 평문을 찾으려는 시도를 암호해독(암호분석)이라고 한다.
- 암호해독자는 평문과 키를 찾아내는 것을 목표로 한다.
- 케르히호프의 원리(Kerckhoff's principle): 암호학에서 암호해독자는 현재 사용되고 있는 암호방식을 알고 있다는 전제하에 암호해독을 시도하는 것으로 간주한다.

① 확산(Diffusion)과 혼돈(Confusion)

확산(Diffusion)
- 암호문과 평문 사이의 관계를 숨기는 것
- 암호문에 대한 통계 테스트를 통하여 평문을 찾고자 하는 공격자를 좌절시킴

혼돈(Confusion)
- 암호문과 키의 관계를 숨기는 것
- 암호문을 이용하여 키를 찾고자 하는 공격자를 좌절시킴
- 키의 단일 비트가 변하면 암호문의 거의 모든 비트가 변함

<> Mentor's Know-how
- 확산(Diffusion)과 혼돈(Confusion), 페이스텔(Feistel)과 SPN 구조는 현대 대칭키 블록암호에 중요하게 사용되는 것으로 둘의 차이점을 정확히 알고 있어야 합니다.

▶ CFB(Cipher-FeedBack) 모드

[그림: <암호화> IV를 암호화하여 평문블록1과 XOR(⊕) → 암호문블록1, 그 암호문블록1을 다시 암호화하여 평문블록2와 XOR → 암호문블록2, 이런 식으로 이전 암호문블록을 암호화하여 다음 평문블록과 XOR하는 과정을 반복하여 암호문블록3, 4까지 생성]

[그림: <복호화> IV를 암호화하여 암호문블록1과 XOR → 평문블록1, 이전 암호문블록을 암호화하여 다음 암호문블록과 XOR하는 과정을 반복하여 평문블록2~4 복원]

▶ OFB(Output-FeedBack) 모드

[그림: <암호화> IV를 암호화한 출력을 평문블록1과 XOR → 암호문블록1, 이전 암호화 출력을 다시 암호화하여 그 출력을 평문블록2와 XOR → 암호문블록2, 이런 식으로 암호화 출력 체인을 이어가며(평문블록과는 무관하게 키스트림 생성) 암호문블록3, 4까지 생성]

[그림: <복호화> 동일하게 IV를 암호화한 출력 체인을 생성하여 각 암호문블록과 XOR하여 평문블록1~4 복원]

▶ CTR(CounTeR) 모드

[그림: <암호화> CTR, CTR+1, CTR+2, CTR+3 값을 각각 암호화한 후 평문블록1~4와 XOR하여 암호문블록1~4 생성]

[그림: <복호화> CTR, CTR+1, CTR+2, CTR+3 값을 각각 암호화한 후 암호문블록1~4와 XOR하여 평문블록1~4 복원]

## IMG_5141 — 키 배송 문제 해결 방법, Diffie-Hellman 키 교환 (textbook)

Chapter 03 비대칭키 암호

① 키 배송 문제 해결 방법

키의 사전 공유에 의한 해결
키 관리기관(TA, trusted authority)이 사전에 임의의 두 사용자 (A, B)에게 비밀 경로를 통하여 임의 키 K_A,B = K_B,A를 선택하여 전달하는 방법

키배포 센터에 의한 해결(온라인 키 분배)
암호 통신이 필요해질 때마다 통신용 키를 키배포 센터(KDC, Key Distribution Center)라는 신뢰받는 제3자에 의뢰해서 개인과 키배포 센터 사이에서만 키를 사전에 공유하는 것

Diffie-Hellman 키 교환에 의한 해결
공개키 암호방식의 개념을 이용하여 두 사용자 간에 공통의 암호화키를 안전하게 공유할 수 있는 방법을 제시(최초의 비밀키 교환 프로토콜)

공개키 암호에 의한 해결
송신자는 암호화키를 사용하여 메시지를 암호화하고, 수신자는 복호화키를 사용하여 암호문을 복호화함

<> Mentor's Know-how
- 대칭키 암호통신을 위해서는 대칭키를 송/수신자가 공유해야 합니다. 이때 키 배송 문제(key distribution problem)가 발생하게 됩니다.
- 키 배송 문제를 해결하기 위해 4가지 방법이 나오게 되는데, 종류 및 특징을 이해해야합니다.
- 대칭키의 키 배송 문제는 비대칭키(공개키) 암호의 등장 배경이 됩니다.

② Diffie-Hellman 키 교환에 의한 해결

[그림: Alice와 Bob의 Diffie-Hellman 키 교환 시퀀스도
The values of p and g are public.
① Alice: R1 = g^x mod p
① Bob: R2 = g^y mod p
② Alice → Bob: R1 전달
③ Bob → Alice: R2 전달
④ Alice: K = (R2)^x mod p
④ Bob: K = (R1)^y mod p
Shared secret key: K = g^xy mod p]

<> Mentor's Know-how
- Diffie-Hellman 알고리즘은 1976년에 공개키 암호방식을 최초로 제안한 휘트필드 디피(Whitfield Diffie)와 마틴 헬먼(Martin Hellman)이 발명한 알고리즘입니다.
- Diffie-Hellman 알고리즘은 양쪽 통신주체가 KDC(Key Distribution Center) 없이 대칭 세션키를 생성합니다.
- Diffie-Hellman 알고리즘은 이산대수 문제(G^d mod P에서 수 A를 구하는 문제)에 기반하고 있습니다.
- Diffie-Hellman 알고리즘은 인증 단계가 없기 때문에 중간자 공격(Man-in-the-middle attack)에 취약합니다. 이런 공격을 막기 위해 전자서명과 공개키 인증서 등을 이용하면 됩니다 (STS, Station-To-Station Protocol)

⌄ 모듈러 연산의 성질
- (성질 1) : (a + b) mod n = ((a mod n) + (b mod n)) mod n
- (성질 2) : (a - b) mod n = ((a mod n) - (b mod n)) mod n
- (성질 3) : (a x b) mod n = ((a mod n) x (b mod n)) mod n

⑥ RSA 암호시스템
- RSA는 공개키 암호 알고리즘의 중의 하나, 사실상의(de facto) 표준
- RSA라는 이름은 개발자 이름 Rivest-Shamir-Adleman의 첫 글자를 따서 붙여짐
- 인수분배 문제(Prime factorization) 난이도를 이용
- SSL 프로토콜을 가진 많은 웹 브라우저, PGP 그리고 공개키 암호시스템을 사용하는 정부시스템 등이 RSA를 사용

⑦ RSA의 키 생성과 암호화/복호화 알고리즘

키 생성
- p, q 선택 (p와 q는 모두 소수이다(p ≠ q))
- N = p × q를 계산
- φ(N) = (p-1)(q-1)를 계산
- 정수 e를 선택 (gcd(φ(N), e) = 1 : 1 < e < φ(N))
- d를 계산 (de mod φ(N) = 1)
- 공개키 PU = {e, n}
- 개인키 PR = {d, n}

암호화
- 평문: P
- 암호문: C = P^e mod n

복호화
- 암호문: C
- 평문: P = C^d mod n

⌄ RSA 알고리즘 예
① 두 소수 p = 17과 q = 11을 선택한다
② N = p × q = 17×11 = 187을 계산한다.
③ φ(N) = (p-1)(q-1) = 16×10 = 160을 계산한다.
④ φ(N) = 160보다 작으면서 φ(N)과 서로소인 e를 선택한다. 여기서는 e = 7을 선택한다.
⑤ d < 1600면서 de mod 160 = 1인 수 d를 결정한다. 여기에 적합한 수는 d = 23이다. 왜냐하면 23×7 = 161 = 1×160 + 1이기 때문이다.
⑥ 결과로 얻어지는 공개키 PU = {7, 187}이고, 개인키는 PR = {23, 187}이다.

## IMG_5148 — 변경 감지 코드(MDC)와 메시지 인증 코드(MAC) (textbook)

(5) 변경 감지 코드(MDC, Modification Detection Code)

[그림: Alice가 Message를 Hash function에 넣어 Digest Sent를 생성 → Insecure channel로 Message M을 Bob에게 전송, 별도로 Channel immune to change(변경 불가능한 채널)로 Digest를 Bob에게 전송 → Bob은 수신한 M을 Hash function에 넣어 Created Digest 생성 → 수신한 Digest(Ciphertext)와 비교(Same?) → yes면 Keep the message, no면 Discard]

> Mentor's Know-how
- 변경감지 코드는 메시지의 무결성을 보장하는 메시지 다이제스트입니다. 즉, 해당 메시지가 변경되지 않았다는 것을 보장해주게 됩니다.
- 메시지의 무결성은 물론 송신자가 메시지의 원래 전송자이며 다른 사람이 송신자인 척 하는 것이 아니라는 것을 말해주는 데이터 출원지 인증을 보장하기 위해 변경 감지 코드를 메시지 인증코드(MAC)로 바꿀 필요가 있습니다.
- MDC와 MAC의 차이점 : MAC은 송신자와 수신자 사이에 비밀값(비밀키)이 포함됩니다.

(6) 메시지 인증 코드(MAC, Message Authentication Code)

[그림: Alice는 Message M과 공유 비밀키 K를 Hash에 넣어 MAC 생성 → M + MAC을 Insecure channel로 Bob에게 전송 → Bob은 수신한 M과 자신이 가진 K로 Hash 계산 → 수신한 MAC과 비교(Same?) → no면 Discard, yes면 Keep the message]
M: Message
K: A shared secret key
MAC: Message authentication code

## IMG_5149 — MAC의 종류와 MAC에 대한 공격 (textbook)

(7) MAC의 종류

MAC의 종류
- 축소 MAC
  - 해시가 두 단계로 이루어짐
  - 1단계에서는 키에 메시지를 이어 붙이고 해시하여 중간 단계의 다이제스트를 생성하고, 2단계에서는 키에 중간단계 다이제스트를 이어 붙이고 최종적인 다이제스트를 생성함
- HMAC
  - SHA-1과 같은 일방향 해시함수를 이용하여 메시지 인증코드를 구성하는 방법
  - HMAC의 H는 Hash를 의미함
  - TLS(Transport Layer Security), IPSec(IP Security), SET(Secure Electronic Transaction) 프로토콜에서 사용
- CBC-MAC
  - 대칭키 암호시스템에 대한 암호 블록체인(CBC)모드와 유사한 방법
  - 대칭키 암호를 N번 사용하여 N개의 평문블록에서 하나의 MAC을 생성

MAC에 대한 공격
- 재전송 공격
  - 공격자는 전송중인 메시지와 메시지 인증코드를 스니핑한 다음 수신자에게 전송하더라도 수신자는 이를 구별할 수 없음
  - 재전송 공격을 막을 수 있는 방법은 순서번호, 타임스탬프, 비표, 시도/응답 등이 있음
- 제3자에 대한 증명
  - MAC은 공유키를 사용하기에 MAC 값을 계산한 것은 서로 상대방(송신자/수신자)이라고 말할 수 있음
  - 제3자에게 MAC 값을 계산한 것은 자신이 아니라 상대방이라고 증명할 방법이 없음
  - 전자서명을 사용하면 제3자에 대한 증명이 가능함
- 부인 방지
  - MAC에서는 송신자와 수신자 중 어느 쪽 주장이 맞는지를 판단할 수 없기 때문에 부인방지(nonrepudiation)를 할 방법이 없음
  - 전자서명을 사용하면 부인방지가 가능함

> Mentor's Know-how
- MAC의 종류는 해시함수(MD5, SHA2 등)의 종류와 구분해서 정리해야 합니다. HMAC은 많이 사용되는 알고리즘입니다.
- MAC은 복사한 값을 구별하지 못하기 때문에 재전송 공격이 가능합니다. 이를 해결하기 위해 순서번호, 타임스탬프, 비표, 시도/응답 등이 이용됩니다.
- MAC은 대칭키를 사용하기 때문에 제3자에 대한 증명과 부인방지 서비스를 제공하지 못합니다. 이를 해결하기 위해 전자서명을 사용할 수 있지만 MAC에 비해 전자서명이 속도가 느립니다.

(2) 전자서명의 주요 기능

위조 불가(Unforgeable)
합법적인 서명자만이 전자서명을 생성 하는 것이 가능해야한다.

서명자 인증(User authentication)
전자서명의 서명자를 불특정 다수가 검증할 수 있어야 한다.

부인 방지(Non-repudiation)
서명자는 서명행위 이후에 서명한 사실을 부인할 수 없어야 한다.

변경 불가(Unalterable)
서명한 문서의 내용을 변경할 수 없어야 한다.

재사용 불가(Not reusable)
전자문서의 서명을 다른 전자문서의 서명으로 사용할 수 없어야 한다.

- 전자서명은 기밀성 서비스를 제공하지 않습니다.

## IMG_5151 — 전자서명 종류 (RSA, ElGamal, Schnorr, DSS, ECDSA, KCDSA, EC-KCDSA) (textbook)

(3) 전자서명 종류

| 구분 | 이론 근거 | 특징 |
|---|---|---|
| RSA | 소인수분해 | RSA 아이디어 이용, 송신자 개인키/공개키 이용 (∵ 공개키와 다름) |

## IMG_5152 — 메시지 복원형 전자서명과 메시지 부가형 전자서명 (textbook)

(4) 메시지 복원형 전자서명

[그림: 송신자(앨리스) - 수신자(밥)
① 앨리스는 자신의 개인 키로 메시지를 암호화한다 (메시지 → 앨리스의 개인 키로 암호화 → 서명)
② 앨리스는 메시지와 서명을 밥에게 송신한다 (메시지 전송 / 서명 전송)
③ 밥은 수신한 서명을 앨리스의 공개 키로 복호화한다 (수신된 서명 → 앨리스의 공개 키로 복호화 → 수신한 서명으로부터 얻어진 메시지)
④ 밥은 지금 복호화한 메시지와 앨리스로부터 직접 수신한 메시지를 비교한다 (비교해서 같으면 서명의 검증이 성공)]

(5) 메시지 부가형 전자서명

[그림: 송신자(앨리스) - 수신자(밥)
① 앨리스는 일방향 해시 함수로 메시지의 해시값을 계산한다 (메시지 → 해시 함수 → 해시 값)
② 앨리스는 자신의 개인 키로 해시 값을 암호화한다 (해시 값 → 앨리스의 개인 키로 암호화 → 서명)
③ 앨리스는 메시지와 서명을 밥에게 송신한다 (메시지 전송 / 서명 전송)
④ 밥은 수신한 서명을 앨리스의 공개 키로 복호화한다 (수신된 서명 → 앨리스의 공개 키로 복호화 → 복호화한 해시값)
   밥은 수신한 메시지를 해시 함수에 넣어 해시 값을 얻는다 (메시지 → 해시 함수 → 해시 값)
⑤ 밥은 수신한 서명으로부터 얻어진 해시 값과 앨리스로부터 직접 수신한 메시지의 해시 값을 비교한다 (비교해서 같으면 서명의 검증이 성공)]

> Mentor's Know-how
- 전자서명 방식에는 메시지 복원형과 메시지 부가형이 있습니다.
- 메시지 복원형 전자서명 방식은 기존의 공개키 암호방식을 이용합니다. 많은 시간이 소요되어 많이 사용되지 않습니다.
- 메시지 부가형 전자서명은 해시 알고리즘을 이용합니다. 효율적이어서 실제로 많이 사용되는 방법입니다.

## IMG_5153 — 특수 전자서명 (부인방지, 의뢰부인방지, 수신자지정, 은닉, 위임, 다중서명) (textbook)

(6) 특수 전자서명

부인방지 전자서명
서명을 검증할 때 반드시 서명자의 도움이 있어야 검증이 가능한 전자 서명 방식

의뢰 부인방지 서명
임의의 검증자가 부인 과정을 수행하지 못하고 특정한 자, 예를 들어 분쟁이 일어났을 때 해결해 주는 사람 혹은 재판관만이 부인 과정을 수행하는 서명방식

수신자 지정 서명
서명의 검증 시 특정 검증자만이 서명을 확인할 수 있도록 하되, 만일 그 서명이 문제가 되는 경우라도 검증자의 비밀서명 생성정보를 노출시키지 않고 제3자에게 서명의 출처를 증명함으로써 본쟁 해결 기능을 제공하는 서명 방식

은닉 서명(블라인드 서명)
서명자가 서명문 내용을 알지 못하는 상태에서 서명토록 한 방식

위임 서명
위임 서명자(proxy signer)로 하여금 서명자(original signer)를 대신해서 대리로 서명할 수 있도록 구성한 서명 방식

다중서명
동일한 전자문서에 여러 사람이 서명하는 것

> Mentor's Know-how
- 공개키 방식을 이용한 전자서명은 검증키를 공개하고 있어 누구나 서명의 진위를 검증할 수 있으나 전자서명을 제한적으로 사용하려고 하는 경우는 사용이 곤란합니다.
- 따라서 다양한 형태에 맞는 전자서명이 필요할 때 사용하는 것이 특수 전자서명입니다.

## IMG_5154 — PKI(공개키 기반구조) 개념과 구성요소 (textbook)

(7) PKI(Public Key Infrastructure)

- PKI는 공개키 알고리즘을 위한 키 관리 구조
- PKI는 공개키 암호시스템에 기초하여 인증서를 생성·관리·저장·분배·취소하는데 필요한 하드웨어, 소프트웨어, 사람, 정책 및 절차
- PKI는 인증기관, 등록기관, 사용자, 신뢰 당사자, 저장소 등의 요소로 구성

> Mentor's Know-how
- 인증기관(CA)은 일종의 행정관청이고, 공인인증서는 주민등록증과 같은 신분증이라고 불 수 있습니다.

(8) PKI 구성요소

| 구성요소 | 내용 |
|---|---|
| 인증기관 | • 인증기관은 인증서를 발급해 주는 역할을 하며, 인증서는 최종 객체를 인증하는 전자 증명서 역할을 수행하여 사용자가 합법적인 사용자임을 입증한다.<br>• 정책승인기관(PAA, Policy Approving Authority) : PKI 전반에 사용되는 정책과 절차를 생성하고 PKI 구축의 루트 CA 역할을 수행한다.<br>• 정책인증기관(PCA, Policy Certification Authority) : PAA 아래 계층으로 자신의 도메인 내의 사용자와 인증기관(CA)이 따라야 할 정책을 수립하고 인증기관의 공개키를 인증하고 인증서, 인증서 폐지 목록 등을 관리한다.<br>• 인증기관(CA, Certification Authority) : 공개키 인증서를 발급하고 또 필요에 따라 취소한다. 공개키를 사용자에게 전달, 인증서/인증서 취소목록 등을 보관한다. |
| 등록기관 | • 인증기관과 멀리 떨어져 있는 사용자들을 위해 인증기관과 사용자 사이에 등록기관을 두어 인증기관 대신 사용자들의 인증서 신청 시 그들의 신분과 소속을 확인하는 기능을 수행한다. 사용자들의 신분을 확인한 후, 등록기관은 인증서 요청에 서명하여 인증기관에 제출한다. 인증기관은 등록기관의 서명을 확인하여 사용자의 인증서를 발행한 후 등록기관에게 되돌리거나 사용자에게 직접 전달한다.<br>- 인증 요청을 승인하고 정당성을 확인한다.<br>- 인증기관에게 인증 요청서를 전송한다.<br>- 디렉터리에서 인증서와 인증서 취소목록을 검색한다.<br>- 인증서 취소를 요청한다. |
| 저장소 | • 인증서와 사용자 관련 정보, 상호 인증서 쌍 및 인증서 취소 목록 등을 저장 및 검색하는 장소로 응용에 따라 이를 위한 서버를 설치하거나 인증기관에서 관리한다. 디렉터리를 관리하는 서버는 LDAP를 이용하여 디렉터리 서비스를 제공한다. |
| 사용자 | • PKI 내의 사용자는 사람뿐만 아니라 사람이 이용하는 시스템 모두를 의미한다.<br>- 자신의 비밀키와 공개키 쌍을 생성한다.<br>- 인증기관에 공개키 인증서를 요청하고 인증서를 받는다.<br>- 전자서명을 생성 및 검증한다.<br>- 특정 사용자의 인증서를 획득하고 그 상태를 확인한다.<br>- 인증 경로를 해석하고, 디렉터리를 이용하여 인증서를 타 사용자에게 제공한다.<br>- 인증서 취소목록을 이용하여 인증서 상태를 검증한다. |

## IMG_5156 — 인증서 프로파일 (X.509 v3) 필드 설명 (textbook)

인증서 프로파일(X.509 v3)

| 요소 | 구분 | 설명 |
|---|---|---|
| 버전(Version) | 필수 | 인증서의 X.509 버전을 정의한다. |
| 일련번호(Serial Number) | 필수 | 인증기관(CA)에 의해 각 인증서에 부여되는 번호이다. 일련번호는 인증기관에서 발행한 각 인증서에 대해 반드시 유일해야 한다(즉, 발행 이름과 일련번호를 이용하여 인증서를 유일하게 구분해 낼 수 있어야 한다) |
| 서명 알고리즘 식별자(Signature Algorithm ID) | 필수 | 인증기관이 인증서를 서명하기 위한 알고리즘과 알고리즘 식별자를 포함한다. 이 정보는 인증서 끝 부분에 있는 서명 필드에도 포함되기 때문에 이 필드는 거의 쓸모가 없다. |
| 발행자 이름(Issuer name) | 필수 | 인증서 발행자(통상적으로 인증기관)의 이름을 명기한다. 발행자의 이름은 국가명(Country), 조직명(organization), 부서명(organizational-unit), 그리고 일반 이름(common name, 예를 들어 "홍길동") 등의 속성으로 정의된다. |
| 유효기간(Validity period) | 필수 | 이 필드는 두 개의 날짜로 구성되며, 각각 인증서 유효 기간이 시작되는 날짜(notBefore)와 인증서 유효 기간이 종료되는 날짜(notAfter)이다. |
| 주체 이름(Subject name) | 필수 | 인증서에 대한 사용자(피발급자)의 이름을 나타낸다. 사용자 이름은 사용자(subject) 필드와/나 사용자 대체 이름(subjectAltName) 필드에 들어갈 수 있다. 상위 인증기관이 하위 인증기관에게 인증서를 발행하는 경우 사용자(피발급자)는 인증기관이 된다. |
| 주체의 공개키 정보(Subject Public Key) | 필수 | 소유자의 공개키를 나타내며 인증서의 핵심이다. 이 필드는 사용자의 공개키에 대한 정보(공개키 및 관련 알고리즘)가 들어 있다. |
| 발행자 유일 식별자(Issuer Unique Identifier) | 선택 | 발급자나 사용자의 이름이 중복되는 경우 이를 구별하기 위한 수단을 제공한다. 통상적으로 고유 식별자는 사용하지 않을 것을 권장한다. |
| 주체 유일 식별자(Subject Unique Identifier) | 선택 | 비트열 필드로서 선택사항이다. 다른 개체가 X.500 이름을 재사용 할 경우, 주체를 유일하게 구별하는 데 사용한다. |
| 확장(Extensions) | 선택 | 이 필드를 이용하여 발행자가 인증서에 추가적으로 사적인 정보를 넣을 수 있다. 버전 3에서 확장을 추가했다. |
| 서명(Signature) | 필수 | 인증서에 대한 서명값이 들어가는데, 이 필드는 인증서의 나머지 필드 전체를 보호한다. 다른 필드 전체에 해시함수를 적용해서 얻어진 해시코드를 포함한다. 이 코드를 CA의 개인키로 암호화한다. |

> 계층 구조와 네트워크 구조 (제목만 이전 페이지와 동일하게 표시됨, 내용은 X.509 관련)
- X.509v3 인증서의 확장 영역은 사용자의 공개키 정보와 연관된 추가적인 정보를 제공하며, 인증서 계층 구조를 관리할 수 있는 방법을 제공함
① 키와 정책 정보 : 기관키 식별자(authority key identifier), 사용자 키 식별자(subject key identifier), 키 사용(key usage), 인증서 정책(certificate policies)
② 사용자와 발행자 속성 : 사용자 대체 이름(subject alternative name), 발행자 대체 이름(issuer alternative name)
③ 인증 경로 제약조건 : 기본 제한(basic constraints), 이름 제한(name constraints), 정책 제한(policy constraints)

## IMG_5158 — 키(Key)와 솔트(Salt) (textbook)

# Chapter 06 키와 난수

## ① 키(Key)

- 키의 종류
  - 대칭키와 공개키
    - 대칭키 : 대칭키 암호에서는 암호화와 복호화에 공통의 키를 사용
    - 공개키 : 공개키 암호에서는 암호화와 복호화에 서로 다른 키를 사용, 공개키와 개인키는 서로 수학적으로 깊이 관련된 파트너이기 때문에 키쌍이라 불림
  - 세션키와 마스터 키
    - 세션키(session key) : 통신 때마다 한 번만 사용되는 키
    - 마스터 키(master key) : 반복적으로 사용되는 키
  - CEK와 KEK
    - CEK(Contents Encrypting Key) : 사용자가 직접 이용하는 정보(콘텐츠)가 암호화의 대상이 됨
    - KEK(Key Encrypting Key) : 키를 암호화하는 키

- 솔트(Salt)
  - 요리에 소금을 뿌려 맛을 바꾸는 것처럼, 솔트는 의사난수 생성기로 만들어지는 랜덤한 수
  - 키를 만들 때 패스워드와 함께 일방향 해시함수에 입력
  - 솔트는 사전공격, 레인보우 테이블을 이용한 공격을 막기 위해 존재

## IMG_5159 — 난수와 의사난수 생성기 (textbook)

## ② 난수

- 난수의 성질
  - 무작위성 : 통계적인 편중 없이 수열이 무작위로 되어 있는 성질
  - 예측 불가능성 : 과거의 수열로부터 다음 수를 예측할 수 없다는 성질
  - 재현 불가능성 : 같은 수열을 재현할 수 없다는 성질
  - 난수의 3가지 성질 사이 관계
    [그림: 무작위성(randomness) 안에 예측 불가능성(unpredictability) 안에 재현 불가능성(reconstruction is impossilbe)이 중첩된 벤 다이어그램]

- 의사난수 생성기
  - 의사난수 생성기는 내부상태를 가지며, 외부에서 주어진 종자(seed)를 기초로 의사난수열을 생성
  - 내부상태는 의사난수 생성기가 관리하고 있는 메모리 값
  - 의사난수 생성기 구조
    [그림: 종자(Seed) → 내부 상태 초기화 → 내부 상태 → 의사난수열(pseudo random number), 내부 상태 박스 아래 라벨 "의사난수 생성기(PRNG : pseudo random number generator)"]

## IMG_5160 — 접근통제 개요 (textbook)

# PART 03 접근통제

## Chapter 01 접근통제 개요

### ① 접근통제

- 기본 개념
  - 허가되지 않은 사용자에 의한 자원 접근이나 정당한 사용자가 허가되지 않은 방법으로 자원에 접근하는 것을 제한하고, 정당한 사용자가 허가된 방식으로만 자원에 접근하도록 하는 것
  - 주체로 불리는 외부에서 접근하는 사람이나 시스템 등이 객체라고 불리는 시스템에 접근 할 때 보안상의 위협, 변조 등과 같은 위험으로부터 객체와 제반 환경을 보호하기 위한 보안대책

- 접근통제의 구성 용어
  - 주체(Subject)
    - 객체나 객체 내의 데이터에 대한 접근을 요청하는 능동적인 개체(주체는 행위자라고 볼림)
    - 사용자, 프로그램 혹은 프로세스가 될 수 있으며 작업을 수행하기 위해 객체에 접근
  - 객체(Object)
    - 접근대상이 될 수동적인 개체 혹은 행위가 일어날 아이템(객체는 제공자라고 볼림)
    - 컴퓨터, 데이터베이스, 파일, 컴퓨터 프로그램, 디렉터리가 될 수 있음
  - 접근(Access)
    - 주체와 객체 사이의 정보 흐름
    - 읽고, 만들고, 삭제하거나 수정하는 등의 행위를 하는 주체의 활동

- 접근통제 3단계
  [그림: 아이디(ID) → 식별(Identification) → 패스워드,토큰,스마트카드(Password, Token, Smartcard) → 인증(Authentication) → 접근제어목록(Access control list) → 인가(Authorization), 3단계가 화살표로 순서대로 연결됨]

> Mentor's Know-how
> 식별은 본인이 누구라는 것을 시스템에 밝히는 것입니다.
> 인증은 주체의 신원을 검증하기 위한 사용 증명(verify, prove) 활동입니다.
> 인가는 인증된 주체에게 접근을 허용하고 특정 업무를 수행할 권리를 부여하는 과정입니다.

## IMG_5162 — 지식 기반 인증(Type Ⅰ) / 소유 기반 인증(Type Ⅱ) (textbook)

### ② 지식 기반 인증(Type Ⅰ)

- 정의
  - 사용자가 알고 있는 어떤 것에 의존하는 인증기법
- 장점
  - 다양한 분야에서 사용 가능함
  - 검증 확실성
  - 관리비용의 저렴함
  - 편리성
- 단점
  - 소유자가 패스워드를 망각할 수 있음
  - 공격자에 의한 추측이 가능함
  - 사회 공학적 공격에 취약함
  - 사용자에 의한 관리 부주의
- 종류
  - 패스워드 : 사용자가 시스템의 자원을 활용하기 위해 시스템에 접속하고자 할 때 사용(가장 널리 사용되는 인증방법이면서 또한 가장 안전성이 떨어지는 메커니즘)
  - i-PIN : 인터넷상에서 주민번호 대신에 아이디와 패스워드를 이용하여 본인 확인을 하는 수단

> Mentor's Know-how
> 지식기반 인증기법은 검증에 애매모호함이 없습니다. 패스워드를 알고 있으면 검증되고 모르면 검증되지 않습니다.
> 또한 사용자의 이름과 비밀번호만 입력하면 되므로 사용상의 용이성을 제공하고 비용이 들지 않습니다.

### ③ 소유 기반 인증(Type Ⅱ)

- 정의
  - 실생활에서 사용하는 다양한 매체를 사용자를 인증하는 방안으로 활용하는 것
- 장점
  - 일반적임(다양한 수단 사용)
  - 입증된 기술
  - 비용 측면에서 생체 인식방식보다 더 경제적임
- 단점
  - 사용이 불가능한 경우 인증 불가능
  - 소유물이 없을 경우 인증이 어려움
  - 복제가 가능함
  - 사회 공학적 공격이 가능함
  - 자산 관리 기능이 요구됨
- 종류
  - 메모리 카드 : 저장할 수 있지만, 처리는 불가능
  - 스마트카드 : 실질적으로 정보를 처리할 수 있다는 점에서 메모리 카드보다 발전된 기술
  - 일회용 패스워드(OTP, One-Time Password) : OTP용 프로그램에서 사용자 비밀번호와 일회용 비밀번호 생성용 입력값을 입력하면 암호 알고리즘을 사용해서 일회용 패스워드를 생성하는 사용자 인증 방법

> Mentor's Know-how
> OTP는 시도응답 형식의 비동기화 방식이 있고, 시간 또는 카운터를 이용 하는 동기화 방식이 있습니다. 또한 해시 체인을 이용하는 S/KEY 방식이 있습니다.
> OTP는 장치를 공유 혹은 분실했을 경우 악용될 소지가 있습니다. 또한 장치의 배터리 방전 혹은 오류로 성공적인 인증이 어려울 수 있습니다.

## IMG_5163 — 개체(생물학적) 특성 기반 인증(Type Ⅲ) (textbook)

### ④ 개체(생물학적) 특성 기반 인증(Type Ⅲ)

- 정의
  - 지문(fingerprints), 홍채(iris), 장문(handgeometry), 성문(voice), 얼굴이미지 등의 다양한 기법들을 이용
- 장점
  - 사용하기가 쉽다. 사용자는 인증을 위하여 리더 장치를 만지거나, 보거나, 말함으로써 인증받는다.
  - 잊어버리거나 손실될 수도 없으며 도난당할 수도 없다.
  - 위조가 어렵다. 생체 정보는 위조될 수 없다.
  - 대여가 불가능하다.
- 단점
  - 잘못 판단할 영역(판단 모호성)이 존재한다.
  - 관리가 어렵다. 사용자는 자신의 생체 정보를 미리 저장소에 등록을 해야 하고, 저장소는 사용자의 생체 템플릿을 비밀스럽게 보관해야 한다.
  - 인증을 위한 임계치 설정이 어렵다.
- 종류
  - 생체적 특징: 지문, 얼굴, 손모양, 홍채, 망막, 정맥
  - 행동적인 특징: 서명, 키보드 입력, 음성(생체적 특징으로 구분하기도 함)

> 생체인증기술의 평가항목
> 보편성(Universality) : 모든 사람이 가지고 있는 생체 특징인가?
> 유일성(Uniqueness) : 동일한 생체 특징을 가진 타인은 없는가?
> 지속성(영구성, Permanence) : 시간에 따른 변화가 없는 생체 특징인가?
> 획득성(Collectability) : 정량적으로 측정이 가능한 특성인가?
> 성능(Performance) : 환경변화와 무관하게 높은 정확성을 얻을 수 있는가?
> 수용성(Acceptability) : 사용자의 거부감은 없는가?
> 반기만성(Anti-Circumvention) : 고의적인 부정사용으로부터 안전 한가?

## IMG_5164 — 생체인증의 정확성 / 생체인증 기술의 도입 시 선결과제 (textbook)

### ⑤ 생체인증의 정확성

[그림: 인식율(x축)에 대한 % 그래프. FAR 곡선은 좌측에서 시작해 우하향(인식율 증가에 따라 감소), FRR 곡선은 좌측 낮은 값에서 우상향(인식율 증가에 따라 증가), 두 곡선이 교차하는 지점이 CER로 표시됨]

| 정확성 | Type Ⅰ error: FRR(False Rejection Rate) : 오거부율<br>・FRR은 등록된 사용자를 거부하는 인식 오류율을 의미한다.<br>・FRR이 높으면 보안수준이 높은 것이다. |

| 속도 및 처리량 | ・일반적인 생체인식 기술 처리 속도는 느리며, 처리량은 낮은 수준이다.<br>・생체인식 기술의 확산을 위해서는 속도 향상과 처리량 증가가 필요하다. |

> Mentor's Know-how
> Type Ⅲ 생체인증 도입 시에 고려할 중요한 요소는 정확성입니다. 이는 Type Ⅰ, Ⅱ에는 없는 Type Ⅲ만의 고려사항입니다.

> 인증의 강도는 Type Ⅰ < Type Ⅱ < Type Ⅲ 순입니다.

> 사용자 편의성을 요구하는 경우는 FAR이 높아지고 FRR은 낮아집니다.
> 반대로 보안성을 강화할 경우에는 FRR은 높아지고, FAR은 낮아집니다.

## IMG_5165 — SSO(Single Sign On) / 커버로스(Kerberos) (textbook)

### ⑦ SSO(Single Sign On)

- 정의
  - 한 번의 시스템 인증을 통하여 접근하고자 하는 다양한 정보시스템에 재인증 절차 없이 접근할 수 있도록 하는 통합 로그인 솔루션
- 장점
  - 운영비용 감소
  - 이중 인증 등을 사용할 경우 보안성 향상
  - 사용자 편의성 증가(PW 암기/분실 위험 감소)
  - 중앙 집중 관리를 통한 효율적 관리 가능
- 단점
  - SSO 서버가 단일실패지점(SPoF, Single Point of Failure)
  - SSO 서버 침해 시 모든 서버의 보안 침해 가능

> Mentor's Know-how
> 싱글사인온(SSO, Single Sign-On)은 단 한 번의 로그인만으로 기업의 각종 시스템이나 인터넷 서비스에 접속하게 해주는 보안 응용 솔루션입니다.
> 각각의 시스템마다 인증 절차를 밟지 않고도 1개의 계정만으로 다양한 시스템에 접근할 수 있어 ID, 비밀번호에 대한 보안 위험 예방과 사용자 편의 증진, 인증 관리비용의 절감 효과가 있습니다.

### ⑧ 커버로스(Kerberos)

- 정의
  - 대칭키 암호기법에 바탕을 둔 티켓 기반 인증 프로토콜이며 동시에 KDC(Key Distribution Center)임
- 특징

## IMG_5166 — 커버로스(Kerberos) 장단점 및 동작절차 (textbook)

- 장점
  - 데이터의 기밀성과 무결성 보장
  - 재생공격 예방
  - 개방된 이기종 간의 컴퓨터에서 자유로운 서비스 인증이 가능(SSO)
  - 대칭키를 사용하여 도청으로부터 보호

- 단점
  - 패스워드 사전공격에 약함
  - 비밀키, 세션키가 임시로 단말기에 저장되어 침입자에 의해 탈취당할 수 있음
  - TimeStamp로 인해 시간동기화 프로토콜이 필요
  - 비밀키 변경 필요
  - KDC가 단일실패지점(SPoF)이 될 수 있음
  - KDC는 많은 수의 요청을 처리 가능해야 함(즉, 확장 가능성이 있어야 함)
  - TGS & AS는 물리적 공격 및 악성코드의 공격에 취약

### ⑨ 커버로스의 동작절차

[그림: 사용자(워크스테이션) ↔ Kerberos(인증서버(AS), 티켓발행서버(TGS)) ↔ 서비스(서버) 간의 티켓 교환 흐름도]

1. 사용자는 워크스테이션에 로그인하고 호스트의 서비스를 요청한다.
2. AS는 사용자가 데이터베이스에 접근권한이 있는지 확인한다. 그리고 티켓-승인 티켓과 세션키를 생성한다. 그 결과물을 사용자의 패스워드로부터 유도한 키를 사용하여 암호화한다.
3. 워크스테이션은 사용자에게 프롬프트를 통해 패스워드를 묻고, 그것으로 수신되는 메시지를 복호화한 다음 사용자 이름, 네트워크 주소, TGS의 시간이 기록된 티켓과 인증자를 보낸다.
4. TGS는 티켓과 인증자를 복호화하고, 요청을 확인하고 요청된 서버에 사용할 티켓을 생성한다.
5. 워크스테이션은 티켓과 인증자를 서버에 보낸다.
6. 서버는 티켓과 인증자가 일치되는지를 확인하고, 서비스에 대한 접근을 허락한다. 만약 쌍방 인증이 필요한 경우라면 서버는 인증자를 반환한다.

[그림 라벨: 사용자 로그온 세션마다 한번 / 티켓-승인 티켓용 요청 / 티켓+세션키 / 서비스-승인 티켓용 요청 / 티켓+세션키 / 서비스 유형마다 한 번 / 서비스 요청 / 서비스 인증지를 제공 / 서비스 세션마다 한 번]

### ② 접근통제 보안 모델

| 모델 | | 설명 |
|---|---|---|
| 벨라파듈라 모델 | 정의 | ・기밀성을 집행하는 상태머신 모델(State Machine Model)이며, 정보흐름 모델(Information Flow Model)<br>・다중등급 보안 정책(Multilevel Security Policy)에 대한 최초의 수학적 모델<br>・벨-라파듈라가 메인 프레임을 사용하는 환경에서 「정보 유출 발생을 어떻게 차단할 수 있을까」하는 고민에서 고안해낸 MAC 모델 |

| 만리장성 모델 | 정의 | ・Chinese Wall 모델이라고 부르는 브루어-내시 모델(Brewer and Nash Model)은 사용자의 이전 동작에 따라 변화할 수 있는 접근 통제를 제공<br>・정보 흐름 모델을 기반(주체와 객체 사이에서 이해 충돌을 야기하는 방식으로 정보가 흐르지 않도록 함) |
