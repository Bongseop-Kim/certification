> Mentor's Know-how

## IMG_5171 — 보안 운영체제 보호방법 및 보안 기능 (textbook)

### ② 보안 운영체제 보호방법
- 물리적 분리(Physical separation) : 사용자별로 별도의 장비만 사용하도록 제한하는 방법
- 시간적 분리(Temporal separation) : 프로세스가 동일 시간에 하나씩만 실행되도록 하는 방법
- 논리적 분리(Logical separation) : 각 프로세스가 논리적인 구역을 갖도록 하는 방법
- 암호적 분리(Cryptographic separation) : 내부에서 사용되는 정보를 외부에서는 알 수 없도록 암호화하는 방법

### ③ 파일 보호기법
- 파일의 이름 명명(naming) : 다른 사용자 파일의 이름을 알 수 있는 기법이 없고 그 이름을 추측하기도 힘들다는 가정에 근거
- 패스워드(password) : 각 사용자마다 서로 다른 패스워드(password)를 제공하여 그 패스워드를 알아야만 파일을 이용할 수 있게 하는 방법
- 암호화(cryptography) : 파일 내용 자체를 암호화(encryption)하여 누구나 공유할 수 있지만 인가된 사용자만 그 내용을 파악 가능토록 함

### ④ 보안 운영체제의 보안 기능
- 사용자 식별 및 인증 : 개별 사용자의 안전한 식별을 요구하며, 각각의 사용자는 고유하게 식별될 수 있어야 함
- 임의적/강제적 접근 통제 : 주체나 소속 그룹의 신분(identity)에 근거하여 객체에 대한 접근을 제한하는 DAC(Discretionary Access Control) 또는 객체의 비밀등급과 주체가 갖는 권한에 근거하여 객체에 대한 접근을 제한하는 MAC(Mandatory Access Control)을 제공해야 함
- 객체 재사용(Object Reuse) 보호 : 보안 운영체제는 재할당되는 모든 기억장치 공간을 깨끗하게 지워야 함
- 완전한 조정 : 보안 운영체제는 모든 접근을 통제하는 완전한 조정을 수행하여야 함
- 신뢰 경로(Trusted Path) : 패스워드의 설정 및 접근 허용의 변경 등과 같은 보안 관련 작업을 수행할 때 사용자는 안전한 경로라고 불리는 안전한 통신을 원하는데 보안 운영체제는 이러한 안전한 경로를 제공
- 감사 및 감사 기록 축소 : 모든 보안 관련 사건은 감사 기록부(audit log)에 반드시 기록되어야 하고 감사 기록부는 명백하게 보호되어야 함

> Mentor's Know-how
- 보안 운영체제의 보안 기능이란 보안 운영체제가 갖추어야할 기능을 말합니다.
- 보안 운영체제의 보안 기능은 보안제품평가(CC, TCSEC, ITSEC)의 평가항목에 들어가는 개념들입니다.

## IMG_5172 — 참조모니터, 보안커널, TCB, TPM (textbook)

### ⑤ 참조모니터, 보안커널, TCB
- 참조 모니터 : 주체의 객체에 대한 모든 접근통제를 담당하는 추상머신
- 보안커널 : TCB 내에 있는 하드웨어, 소프트웨어, 펌웨어로 구성되며, 참조 모니터 개념을 구현하고 집행
- TCB : 하나의 컴퓨터 시스템(H/W, F/W, S/W) 내의 모든 보호 메커니즘의 총체로서, 시스템과의 조화를 통하여 보안 정책을 적용할 책임을 가짐

### ⑥ 참조모니터 및 보안커널의 3가지 특징
- 격리성(Isolation) : 분리되고, 부정조작을 방지한다.
- 검증가능성(Verifiability) : 크기가 작아야 한다.
- 완전성(Completeness) : 우회 불가능해야 한다.

> Mentor's Know-how
- 참조모니터는 승인되지 않은 접근으로부터 객체를 보호하기 위해 객체에 대한 모든 주체의 접근을 통제하는 추상적인 개념으로서 이를 실제로 구현한 하드웨어, 펌웨어, 소프트웨어로 구성된 것이 보안커널입니다.
- 이러한 보안커널로 구성된 것이 TCB이며, 이것은 조직 내에서 보안 정책을 집행하는 역할을 하는 컴퓨터 시스템의 일부분을 의미하기도 합니다. TCB는 국제 공통 평가 기준(CC, Common Criteria)과 같은 평가기준에 의해 평가됩니다.

### ⑦ 신뢰 플랫폼 모듈(TPM, Trusted Platform Module)
정의
- 신뢰 플랫폼 모듈(TPM)은 신뢰 컴퓨팅 그룹(Trusted Computing Group)이라는 산업체 컨소시엄에 의해 표준화된 개념
- TPM은 신뢰 컴퓨팅을 위한 하드웨어/소프트웨어 방법에서 핵심이 되는 하드웨어 모듈

기본 서비스
- 인증된 부트 서비스 : 전체 운영체제를 단계적으로 부팅하고, 운영체제가 적재될 때 운영체제의 각 부분이 사용을 위해 승인된 버전임을 보장
- 인증 서비스 : 일단 TPM에 의해 설정이 완성되고 로그인되면, TPM은 다른 부분의 설정을 인증할 수 있음
- 암호화 서비스 : 특정 기계가 특정 설정으로 되어 있을 때만 그 기계에서 데이터의 복호화를 수행하는 방식으로 데이터의 암호화를 지원

(정보보안기사 핵심요약 노트, page 46)

## IMG_5174 — 악성 소프트웨어의 분류 (textbook)

### ② 악성 소프트웨어의 분류

| 구분 |  | 설명 | 종류 |
|---|---|---|---|
| 독립형과 기생형 | 독립형 | 자체적으로 구동될 수 있는 프로그램으로 운영체제에 의해 스케줄되어 구동 | 웜, 좀비 |
| 독립형과 기생형 | 기생형 | 프로그램 단편으로 다른 실제 응용프로그램이나 유틸리티나 시스템 프로그램 없이 독립적으로 존재할 수 없음 | 바이러스, 논리폭탄, 백도어 |

> Mentor's Know-how
- 악성 소프트웨어는 호스트 프로그램(숙주)이 필요한 경우[기생형]와 아닌 경우[독립형]로 나눌 수 있고, 자기 복제 여부에 따라서 나눌 수도 있습니다.
- 트로이목마와 백도어는 기밀성에 대한 위협요인이고, 바이러스와 논리폭탄은 무결성에 대한 위협요인이며, 웜은 가용성에 대한 위협요인 입니다

> 보안 용어
- 좀비 PC(zombie PC) : 악성코드에 감염된 컴퓨터를 말하며 주로 공격자의 명령을 받아 특정 서비스를 방해할 목적으로 DDoS 공격 등을 수행한다.
- 논리폭탄(Logic Bomb) : 보통의 프로그램에 오류를 발생시키는 프로그램 루틴을 무단으로 삽입하여 특정한 조건의 발생이나 특정한 데이터의 입력을 기폭제로 컴퓨터에 부정한 행위를 실행시키는 것이다.
- 백도어(Back Door) : 트랩도어(Trap Door)라고도 불리는 백도어는 원래 시스템 관리자나 개발자가 유사시 트러블슈팅이나 유지보수 등을 할 관리적 목적으로 필요에 의해 시스템에 고의로 남겨 둔 보안 헛점의 일종이다.

## IMG_5175 — 바이러스의 세대별 분류 (textbook)

### ③ 바이러스의 세대별 분류

| 구분 |  | 설명 |
|---|---|---|
| 제1세대 | 원시형 바이러스(Primitive Virus) | 실력이 뛰어나지 않은 프로그래머가 만들어 프로그램 구조가 단순하고 분석이 상대적으로 쉬움 |
| 제2세대 | 암호화 바이러스(Encryption Virus) | 백신 프로그램이 진단할 수 없도록 바이러스 프로그램의 일부 또는 대부분을 암호화시켜 저장 |
| 제3세대 | 은폐형 바이러스(Stealth Virus) | 백신 프로그램이 감염된 부분을 읽으려고 할 때 감염되기 전의 내용을 보여줘 바이러스가 없는 것처럼 백신 프로그램이나 사용자를 속임 |
| 제4세대 | 갑옷형 바이러스(Armour Virus) | 바이러스 분석을 어렵게 하고 백신 프로그램 개발을 지연시킴 |
| 제5세대 | 매크로 바이러스(Macro Virus) | 데이터 파일 중에 명령어를 실행시키는 MS 워드나 엑셀 등에 붙어서 그 파일이 열릴 때 실행됨 |

> Mentor's Know-how
- 제5세대 매크로 바이러스는 다음과 같은 특징을 가지고 있습니다.
- 매크로 바이러스는 플랫폼과 무관하게 사용
- 대부분의 바이러스는 문서를 감염시키고 코드의 실행부분은 감염시키지 않음
- 매크로 바이러스는 쉽게 퍼짐(가장 보편적인 방법은 전자메일)
- 실행 파일(확장자가 COM이나 EXE)을 다룰 때보다 주의를 덜 하기 때문에 피해가 더 큼

## IMG_5176 — 악성 소프트웨어 정리 (용어) (textbook)

### ④ 악성 소프트웨어 정리

- 모바일 코드 : 스크립트, 매크로나 다른 이동성 명령어 같은 소프트웨어로, 서로 성격이 다른 많은 플랫폼으로 옮겨서 실행될 수 있고 똑같은 기능을 수행
- Exploit : 하나 혹은 여러 개의 취약점을 노리는 코드
- Downloaders : 공격을 받는 컴퓨터에 다른 아이템을 설치하는 프로그램(보통 전자우편을 통해 전달)
- Auto-rooter : 악성 해커 도구로 새로운 시스템에 원격으로 침입할 때 사용하는 툴
- Kit(virus generator) : 바이러스를 자동으로 생성하는 도구모음
- 스패머 프로그램 : 원하지 않는 대량의 전자우편물을 보내는 데 사용
- 플러더(Flooders) : 네트워크 컴퓨터 시스템에 대량의 자료를 보내어 서비스 거부 공격을 감행 하는 데 사용하는 코드
- Keyloggers : 피해를 입은 시스템의 키 입력을 갈취
- Rootkit : 컴퓨터 시스템에 침입 후 루트 수준의 접근허락을 얻기 위해 사용하는 해커 도구모음
- 공격 킷(Attack kit) : 다양한 번식방법과 payload 기술을 사용하는 새로운 악성코드를 자동으로 만들어 주는 툴의 모음
- 좀비(Zombie) : 감염된 컴퓨터에서 활성화되는 프로그램으로 다른 컴퓨터에 대한 공격을 시작하는 데 사용
- 스파이웨어 : 컴퓨터에서 정보를 수집해서 다른 시스템으로 전송하는 소프트웨어
- 애드웨어 : 소프트웨어에 내장된 광고, 감염 시 팝업 광고가 뜨거나 브라우저가 광고 사이트로 연결
- 크라임웨어(Crimeware) : 온라인을 통해 불법적인 행동(범죄)을 하기 위해 만들어진 프로그램
- 브라우저 하이재커(Browser Hijacker) : 브라우저를 하이재킹하여 홈페이지와 검색 페이지, 툴바를 통제하고 조작하는 프로그램(잘못된 주소를 입력하면 자동으로 해커가 만들어 놓은 사이트로 이동하게 됨)
- 다이얼러(Dialers) : 모뎀이 특정 번호(1-900)로 연결되도록 하여 전화를 걸 때마다 공격자가 수익을 얻게 만드는 프로그램
- 조크(Joke) : 실제 바이러스는 아니지만 사용자에게 심리적인 위협이나 불안을 조장하는 프로그램
- Hoax : 남을 속이거나 장난을 목적으로 퍼트리는 가짜 바이러스로, 일반적으로 허위 바이러스 경고 메일형태

## IMG_5181 — 윈도우 파일시스템, 기본 사용자/그룹 (textbook)

### ② 윈도우 파일시스템
- FAT32 : 총 32비트(2^32개)의 클러스터를 가짐, 호환성이 좋아 리눅스나 다른 운영체제에 정보를 옮길 때 유용, 접근제어 설정이 힘들며 보안과는 거리가 먼 파일시스템
- NTFS(New Technology File System) : 개별 폴더와 파일에 사용권한 설정 가능하며 암호화도 가능, 감사(Auditing) 기능을 제공, 강력한 보안 기능 제공

> Mentor's Know-how
- NTFS에는 볼륨/파일시스템에 존재하는 모든 파일과 폴더에 대한 정보를 담고 있는 MFT(Master File Table)라는 가장 중요한 영역이 있습니다.
- 윈도우 부팅은 POST(Power On Self Test) 실행 → 기본 부팅 관련 설정사항(CMOS) 로드 → MBR(Master Boot Record) 로드 → 윈도우 부트 서브 시스템(Window Boot Manager) 실행[운영체제 목록 보여줌] → 윈도우 OS 로더(Winload.exe) 실행[각종 드라이버 로드, ntoskrnl.exe 실행]의 순서를 가집니다.

### ③ 윈도우 기본 사용자
- Administrator : 관리자 권한의 계정으로 사용자가 가용 가능한 계정 중 가장 강력한 권한을 가짐
- SYSTEM : 시스템에서 최고 권한을 가진 계정으로 로컬에서 관리자보다 상위 권한을 가짐, 원격 접속이 불가능하며, 사용자가 이 계정을 사용하여 시스템에 로그인 할 수 없음
- Guest : 매우 제한적인 권한을 가진 계정으로, 기본 설정은 사용 불능

### ④ 윈도우 기본 그룹
- Administrators : 도메인 자원이나 로컬 컴퓨터에 대한 모든 권한을 가짐
- Account Operators : 사용자나 그룹 계정을 관리하는 그룹
- Backup Operators : 시스템 백업을 위해서 모든 시스템의 파일과 디렉터리에 접근할 수 있음
- Guests : 도메인 사용 권한이 제한된 그룹으로 시스템의 설정 변경 권한이 없음
- Print Operators : 도메인 프린터에 접근할 수 있음
- Power Users : 디렉터리나 네트워크 공유, 공용 프로그램 그룹 생성, 컴퓨터의 시계 설정 권한이 있음
- Replicator : 도메인에 있는 파일을 복제할 수 있는 권한을 가지고 있는 그룹이며, 디렉터리 복사 서비스에 이용됨
- Server Operators : 도메인의 서버를 관리할 수 있는 권한을 가진 그룹으로 로컬 로그인과 시스템 재시작 및 종료 권한이 있음
- Users : 도메인과 로컬 컴퓨터를 일반적으로 사용하는 그룹, 개개인에 할당된 사용자 환경을 직접 만들 수 있지만, 설정할 수 있는 항목에는 한계가 있음, 시스템 서비스의 시작 및 종료 권한이 없으며, 디렉터리 공유 설정을 할 수 없음

> Mentor's Know-how

- Administrator는 유닉스의 root와 유사합니다.
- 기본 그룹인 Administrators와 Users가 권한에서 어떤 차이점을 가지고 있는지 알고 있어야 합니다.

## IMG_5182 — 윈도우 인증의 구성요소 (LSA, SAM, SRM) (textbook)

## ⑤ 윈도우 인증의 구성요소

[그림: Winlogon → LSA(Local Security Authority) 서버 시스템 { LSA 서버 서비스, NTLM, SAM(Security Account Manager), Netlogon } ↔ SRM(Security Reference Monitor) → 이벤트 로거 → 보안 로그, 커널모드 쪽에 "사용자 인증 정보" 박스가 SAM과 연결됨]

**LSA(Local Security Authority) 서버 시스템**
- 모든 계정의 로그인에 대한 검증
- 시스템 자원 및 파일 등에 대한 접근 권한을 검사
- SRM이 생성한 감사 로그를 기록
- NT 보안의 중심 요소이며, 보안 서브시스템(Security Subsystem)이라 불림

**SAM(Security Account Manager)**
- 사용자/그룹 계정 정보에 대한 데이터베이스를 관리
- 사용자의 로그인 입력 정보와 SAM 데이터베이스 정보를 비교해 인증 여부를 결정

**SRM(Security Reference Monitor)**
- SID(Security Identifier)를 부여
- SID에 기반하여 파일이나 디렉터리에 대한 접근(access)을 허용할지를 결정하고, 이에 대한 감사 메시지를 생성

### Mentor's Know-how
- 접근통제가 식별, 인증, 인가의 3단계를 거치듯이, 윈도우는 LSA, SAM, SRM의 구성요소를 거치면서 사용자가 시스템에 접근할 수 있게 됩니다.
- LM 해시 vs NTLM 해시
  ① LM(Lan Manager) 해시: 네트워크를 통한 파일 및 프린터 공유 등과 같은 작업 시 인증을 담당하는 서비스이다. 윈도우 2000, XP의 기본 알고리즘으로 구조적으로 취약한 알고리즘이다.
  ② NTLMv2 해시: 윈도우 비스타 이후 윈도우 시스템의 기본 인증 프로토콜로 기존 인증알고리즘과는 전혀 다른 알고리즘으로 해시값을 생성하며 현재까지 복잡도가 충분해 크래킹이 어렵다.

## IMG_5183 — 디렉터리/파일 접근 권한, 윈도우 공유 폴더 (textbook)

## ⑥ 디렉터리 및 파일에 대한 접근 권한 설정

- 접근 권한은 누적: 개별 사용자가 여러 그룹에 속한 경우 특정 파일이나 디렉터리에 대한 접근 권한 없음
- 파일에 대한 접근 권한이 디렉터리에 대한 접근 권한에 우선: 파일이 포함된 디렉터리의 권한보다 우선
- 다 파일에 대한 권한 설정이 우선함
- 「허용, 보다 거부가 우선」: 중첩 권한 중 명백한 「허용」보다 「거부」가 우선 적용됨
- 선하여 적용됨

### Mentor's Know-how
- NTFS 접근 권한은 누적이란 예를들어 그룹을 A와 그룹 B에 속하는데 그룹 A에서 읽기 권한을 할당받고 그룹 B에서 쓰기 권한을 할당받았다면, 읽기와 쓰기 권한이 모두 있는 것을 의미합니다.

## ⑦ 윈도우 공유 폴더

**C$, D$ 등**
- 드라이브 문자로 관리목적 공유 폴더
- 드라이브에 있는 하드 드라이브 등만큼 공유되어 있음, 만약 하드 드라이브가 C, D, E드라이브까지 있다면, C$, D$, E$까지 표시됨

**ADMIN$**
- 윈도우 설치 폴더에 접근하는 관리목적 공유 폴더

**IPC$(Inter Process Communication)**
- 네트워크 등에서 프로세스 간의 통신을 위해서 사용하는 통로 같은 것
- 널 세션(아이디와 패스워드 없이 세션을 연결)의 취약점 존재 가능

### Mentor's Know-how
- 기본 공유 폴더 설정과 동시에 생성되어 숨겨져 있습니다. 숨긴 공유를 보려면 「net share」를 명령 프롬프트에서 입력한 후 Enter 키를 누릅니다.
- 기본 공유 폴더는 침입자가 네트워크를 통해 액세스할 수 있는 위협성이 있으므로 비활성화(중지)하는 것이 좋습니다. 하지만 운영체제가 재시작되면 다시 만들어지기 때문에 완전히 제거하려면 레지스트리를 편집해야 합니다.(HKLM\ ... \parameters에서 「가 다시 만들어지기 때문에」 제거하려면 레지스트리를 완전히 (?) 설정하는 것이 DWORD를 새로 만들어 0으로 설정)

## IMG_5184 — 윈도우 암호화 기능(EFS, BitLocker), 레지스트리 루트 키 (textbook)

page: 58

## ⑧ 윈도우 암호화 기능

**폴더 및 파일 암호화(EFS)**
- EFS(Encrypting File System)는 윈도우 운영체제(Windows XP 및 Windows Server 2000 이상)에서 개별 파일의 모든 특정 폴더 안에 들어 있는 파일을 암호화할 수 있는 기능을 제공함

**볼륨 암호화(BitLocker)**
- BitLocker는 윈도우 운영체제(Windows Vista Ultimate/Enterprise, Windows 7 Ultimate/Enterprise, Windows Server 2008 이상)에서 제공하는 볼륨 단위의 데이터 암호화 기능이며, 여기서 볼륨은 논리적 드라이브(파티션 드라이브)를 의미함
- BitLocker가 활성화되면 해당 볼륨에 저장된 모든 파일이 자동으로 암호화됨
- 단, 컴퓨터를 시작하는데 필요한 시스템 파티션은 암호화되지 않음

### Mentor's Know-how
- BitLocker는 컴퓨터 단위의 데이터 암호화 기능을 제공하고, EFS는 폴더 또는 파일단위의 데이터 암호화 기능을 제공합니다.

## ⑨ 레지스트리 루트 키

- **HKEY_CLASSES_ROOT(HKCR)**: 파일 확장명과 응용프로그램의 연결정보가 들어있고, 윈도우 시스템에 등록되어 있는 개체들을 응용프로그램과 그 앞부분에 대한 정보
- **HKEY_CURRENT_USER(HKCU)**: 현재 로그인 되어 있는 사용자에 따라 달리 적용되는 제어판 설정, 네트워크 연결, 응용 프로그램 등을 저장
- **HKEY_LOCAL_MACHINE(HKLM)**: 이와 응용 프로그램 어와 시스템 전체에 적용되는 하드웨어
- **HKEY_USERS(HKU)**: 사용자 프로필을 만들 때 적용할 기본 설정(.DEFAULT 키)과 사용자별 프로파일에서
- **HKEY_CURRENT_CONFIG(HKCC)**: 정의한 그룹 정책 등
  저장

### Mentor's Know-how
- 레지스트리는 윈도우 시스템이 운영되는데 필요한 정보를 담고 있습니다.
- 설치된 소프트웨어 정보부터 환경설정, 임시 저장값, 시스템의 거의 모든 정보를 담고 있습니다.
- HKLM(HKEY_LOCAL_MACHINE), HKU(HKEY_USERS)는 Master Key이, 나머지는 Master Key로 유도된 키(Derived Key)입니다.
- HKCR은 특정 확장자 실행 시에 원하는 악성 프로그램을 실행시키는 데 악용될 수 있으며, HKLM(전체)과 HKCU(개별)에 변형된 시스템 재부팅에 이용될 수 있습니다.(Run[지워짐], RunOnce(일회용))

# Chapter 04 유닉스/리눅스 서버 보안

## ① UNIX 시스템의 특징

- 대화식 운영체제: 사용자와 운영체제 간의 상호작용은 명령어 해석기인 셸(Shell)에 의해 이루어짐

## IMG_5187 — 파일 접근권한 변경(chmod) (textbook)

page: 61

## ④ 파일 접근권한 변경(chmod)

| 문법 | chmod [-R] permission file_name1 \| directory_name1 [file_name2 \| directory_name2...] |
|---|---|
| 옵션 -R | 하위 디렉터리와 파일의 권한까지 변경한다. |
| permission | 기호나 8진수로 접근권한을 지정한다. |
| 예문 | $ chmod o-w daemon.c  /* daemon.c에 대한 other의 쓰기권한을 제거 */ |
| | $ chmod 664 daemon.c  /* daemon.c의 접근권한은 664(rw-rw-r--) */ |
| 설명 | 해당 파일의 소유주나 슈퍼 유저 root만 실행할 수 있다. |

### Mentor's Know-how
① 접근권한을 기호로 기술하는 방법
- 대상: u(user), g(group), o(other), a(all)
- 연산자: +(추가), -(제거), =(지정)
- 접근권한: r(읽기), w(쓰기), x(실행)
- (예) chmod go-w daemon.c : daemon.c의 group, others에 w 권한 제거
  chmod a=rw daemon.c : daemon.c의 모든 사용자에 rw 권한 설정
  chmod g+x,o-x daemon.c : daemon.c의 group에 x 권한을 추가하고 others에 x 권한을 제거

② 접근권한을 숫자로 기술하는 방법
- 파일의 접근권한을 세 개의 8진수로 기술
- r(읽기)=4, w(쓰기)=2, x(실행)=1
- (예) mod 777 daemon.c : 모든 사용자에 rwx 권한 설정
  chmod 664 daemon.c : user, group에 rw 권한, others r 권한 설정
  chmod 600 daemon.c : user에게 rw 권한 설정

## IMG_5188 — passwd 파일 (textbook)

## ⑤ passwd 파일

**/etc/passwd 파일 형식**

`[user_account]:[user_password]:[user_ID]:[group_ID]:[comment]:[home_directory]:[login_shell]`
① ② ③ ④ ⑤ ⑥ ⑦

예시: `root:x:0:1:Super-User:/root:/bin/sh`

① root: 사용자 계정 또는 로그인 이름
② x: 사용자의 패스워드(실제 사용 안하고, /etc/shadow에 저장)
③ 0: 사용자 ID로 특정 사용자를 나타내는 숫자로 된 ID(UID)
④ 1: 기본 그룹 ID로 사용자가 소속된 그룹을 나타내는 숫자로 된 ID(GID)
⑤ Super-User: 사용자 관련 기타 정보
⑥ root: 로그인에 성공한 후에 사용자가 위치할 홈 디렉터리명
⑦ /bin/sh: 명령어를 처리하는 셸의 종류를 지정

### Mentor's Know-how
- /etc/passwd 파일은 UNIX 시스템에 등록된 사용자 계정마다 정보가 담겨 있는 파일입니다.
- 과거에는 사용자의 패스워드를 암호화된 텍스트를 /etc/passwd 파일의 두 번째 필드에 저장하였지만 최근 UNIX 시스템에서는 /etc/shadow 파일에 암호화된 패스워드를 저장하고 있습니다.

## ⑥ shadow 파일

**/etc/shadow 파일 형식**

`[user_account]:[encrypted_password]:[last_change]:[minlife]:[maxlife]:[warn]:[inactive]:[expires]`
① ② ③ ④ ⑤ ⑥ ⑦ ⑧

예시: `root:$1$VE59oY1q$z74b9wxdTyB88oUenreT9g/:13115:0:99999:7:10::`

사용자 정보를 서로 연계한다.
② `$1$VE59oY1q$z74b9wxdTyB88oUenreT9g/`: 암호화된 패스워드(복호화가 불가하하 며, 사용자가 입력한 패스워드를 암호화하여 이 필드와 비교한다.)
③ 13115: 마지막으로 패스워드를 변경한 날(1970년 1월 1일부터 며칠이 지났는지 그 일수로 표기한다.)
④ 0: 최소 변경 일수(패스워드를 변경할 수 없는 기간)
⑤ 99999: 최대 변경 일수(현재 사용 중인 패스워드를 변경하지 않고 사용할 수 있는 기간의 일수를 지정한다.)
⑥ 7: 경고 일수(max 필드에 지정한 일수 남지 않았음을 알리는 필드로 로그인 할 때마다 경고 메시지를 출력하는 유효로 사용한다.)
⑦ 10: 최대 비활성 일수(로그인을 자주하지 않는 사용자의 경우 사용자 계정을 비활성화 시켜서 로그인이 되지 않도록 하는 기능이다.)
⑧ 사용자 계정이 만료되는 날(1970년 1월부터 며칠이 지났는지 그 일수로 표기한다.)

### Mentor's Know-how
- /etc/shadow 파일은 UNIX 시스템에서 사용자 계정을 인덱스로 하여 사용자의 패스워드와 관련된 정보를 담고 있습니다.

## ① 접근권한 마스크(umask)

**특징**
- chmod 명령은 기존 파일의 접근권한을 변경할 때 사용하고, umask 명령은 앞으로 새로 생성될 파일에 영향을 미치는 명령으로, 명령 시에 지정한 8진 수새로 만들어질 파일이 갖지 말아야 할 권한을 설정
- 시스템 관리자는 /etc/profile에 umask를 설정(보통 group과 other의 쓰기 권한에 제한을 두는 022를 많이 사용)
- 접근권한은 일반적으로 파일을 생성할 때는 666에서 umask로 지정한 값 값을 빼고, 디렉터리의 경우 777에서 umask로 지정한 값을 빼게 됨

| 문법 | umask [mask] |
|---|---|
| 옵션 mask | 파일이나 디렉터리의 접근권한으로 갖지 말아야 할 권한을 8진수로 지정한다. |
| 예문 | # umask 000 |
| 설명 | 접근권한을 명시하지 않으면 기존에 설정된 umask 값을 출력한다. /* umask 값을 000으로 재지정 */ |

## IMG_5192 — 권한 상승(SetUID, SetGID) (textbook)

## ① 권한 상승(SetUID, SetGID)

[그림 (a) Test에 SetUID 비트가 있는 경우: Test 실행 전 → Test를 소유자의 권한 범위(Test 실행 시 root 계정으로 권한 전환) → Test를 실행한 일반 계정의 권한 범위 → Test 종료 시 권한 전환 → Test 실행 후, Test 실행 중 root 권한 획득]

[그림 (b) Test에 SetUID 비트가 없는 경우: Test 실행 전 → Test를 소유자인 root 계정의 권한 범위(Test 실행 시 권한 전환 없음) → Test를 실행한 일반 계정의 권한 범위 → Test 종료 시 권한 전환 없음 → Test 실행 후]

### Mentor's Know-how
① 최초로 로그인 할 때는 RUID와 EUID, RGID와 EGID가 각각 같은 값을 갖습니다. 일반적인 프로그램을 실행할 때는 이 값이 동일하며, SetUID 비트를 가진 프로그램을 실행했을 때만 프로세스 안에서 일치하지 않는 상태가 발생합니다.
- RUID(Real User ID): 프로세스를 실행시킨 사용자의 UID
- RGID(Real Group ID): 프로세스를 실행시킨 사용자의 GID
- EUID(Effective User ID): 프로세스가 실행중인 동안에만 부여되는 UID로 자원 접근권한 등에 대한 접근권한을 판단하기 위한 UID
- EGID(Effective Group ID): 프로세스가 실행중인 동안에만 부여되는 GID로 자원(파일 등)에 대한 접근권한을 판단하기 위한 GID
② SetUID 비트가 설정된 파일은 모두 접근권한을 판단할 수 있습니다, 즉, 이 파일은 백도어 및 버퍼오버플로우 등 여러 공격에 이용되므로 그래서 SetUID 비트가 설정된 파일을 목록화하여 관리하는 작업이 필요합니다.
③ UNIX 시스템은 sticky-bit를 이용하여 디렉터리에 특별한 접근권한을 부여할 수 있습니다. sticky-bit가 설정된 디렉터리를 생성하거나 있는 모든 사용자가 파일이나 디렉터리를 생성할 수 있지만 해당 디렉터리를 삭제하는 것은 소유자나 root인 경우에만 가능합니다.(예: /tmp와 같은 공용 디렉터리에서 주로 사용)

## ① 데몬 실행모드 비교

| 구분 | standalone 서비스 | xinetd 환경 서비스(리눅스) |
|---|---|---|
| 의미 | 독립적으로 실행되는 서비스들의 데몬 | xinetd 슈퍼데몬이라고도 불리는데, 이 데몬을 관리하는 데몬 |

### Mentor's Know-how
① inetd 데몬은 슈퍼 데몬이라고도 불리는데, 이는 데몬을 관리하는 데몬이라하여 붙은 이름입니다. xinetd 데몬은 기존의 inetd 슈퍼데몬의 비효율적인 리소스 관리와 보안 문제를 극복하기 위해 나온 것으로 서비스별 다양한 설정 옵션을 가지고 있습니다.
② Stand-Alone 방식 vs inetd(xinetd) 방식
- Stand-Alone 방식: 개별 서비스별 서버 프로세스(데몬)가 동작하는 방식으로 빠른 속도가 장점이지만 서버 자원도 많이 점유하고 있는 단점이 있음
- inetd(xinetd) 방식: 슈퍼 데몬(inetd 데몬)을 이용하여 개별 서비스를 동작시키는 방식으로 속도가 상대적으로 느리지만 서버 자원을 절약할 수 있음

## ① 시스템 관리의 6가지 주제

- 로그 관리 : 시스템에 영향을 미치는 관련 사항을 기록
- 취약점 관리 : 시스템 자체의 결함에 대한 관리

### Mentor's Know-how
- 시스템을 적절하게 구축하여 보호하고 배치하였다면 서버관리자는 지속적으로 보안 유지 관리를 해야 합니다. 왜냐하면 환경의 변화, 새로운 취약점의 발견, 새 위협에 대한 노출 때문입니다.

### Mentor's Know-how
- 윈도우와 유닉스의 로그 체계는 상당히 다릅니다. 윈도우는 이벤트(Event)라는 중앙 집중화된 로그를 수집하여 저장하지만, 유닉스는 로그를 여러 곳에 산발적으로 저장합니다.
- 윈도우는 로그가 중앙 집중화되어 관리하기 편합니다. 하지만 공격자가 한 로그만 삭제하면 되므로 위험하고, 로그에 대한 보안 수준 역시 낮은 편입니다.
- 이에 반해 여러 곳에 저장된 유닉스 로그는 초보자의 경우 찾는 것조차도 쉽지 않습니다. 또한 공격자도 로그를 모두 찾아 지우기가 쉽지 않습니다.
- 윈도우와 유닉스/리눅스의 로그의 종류, 특징, 확인방법은 출제빈도가 높습니다.

## IMG_5197 — 이벤트 뷰어 표시 내용, 리눅스/유닉스 시스템 로그 정리 (textbook)

## ④ 이벤트 뷰어에 표시되는 내용

- 종류 : 정보(Information), 경고(Warning), 오류(Error), 성공 감사(Sucess Audit), 실패 감사(Failure Audit)가 있음. 성공 감사는 감사대상으로 설정된 대상에 대한 접근 시도가 성공했을 때, 실패 감사는 접근 시도가 실패했을 때 남기는 로그
- 날짜, 시간 : 로그를 남긴 날짜와 시간
- 원본, 범주 : 로그와 관계 있는 영역
- 이벤트 ID : 윈도우에서는 각 로그별로 고유한 번호를 부여, 로그를 분석할 때 이 번호를 알고 있으면 빠르고 효과적인 분석이 가능
- 사용자 : 관련 로그를 발생시킨 사용자
- 컴퓨터 : 관련 로그를 발생시킨 시스템

## ⑤ 리눅스/유닉스 시스템 로그 정리

- wtmp : 사용자 로그인, 로그아웃 정보 및 시스템의 shutdown, booting 정보를 가진 파일. last 명령어로 정보 확인
- utmp : 현재 로그인한 사용자 정보를 담고 있는 DB 파일. who, w, whodo, users, finger 등의 명령어로 정보 확인
- btmp : 로그인 실패를 했을 경우에 로그인 실패 정보를 기록. lastb 명령어로 정보 확인(솔라리스는 loginlog로 5회 이상 실패 기록)
- pacct : 사용자가 로그인한 후부터 로그아웃할 때까지 입력한 명령과 시간, 작동된 tty 등에 대한 정보를 수집. lastcomm, acctcom 명령어를 이용하여 분석
- history : 사용자별로 실행한 명령을 기록하는 로그. vi 편집기, history 명령어로 로그분석
- lastlog : 각 사용자들의 최근 로그인 시각(마지막 로그인 시각)과 접근한 소스 호스트에 대한 정보를 가진 파일. lastlog, finger 명령어로 분석
- sulog : su 명령어를 사용한 경우, 변경 전 사용자 계정과 변경 후 사용자 계정 및 시간 정보가 저장되는 파일. vi 에디터 활용
- dmesg : 리눅스가 부팅될 때 출력되는 모든 메시지를 기록. 부팅 시의 에러나 조치사항을 살펴보려면 이 파일을 참조
- cron : 시스템의 정기적인 작업에 대한 로그, 즉 시스템 cron 작업에 대하여 기록하고 있는 파일
- messages : 시스템의 가장 기본적인 시스템 로그파일로서 시스템 운영에 대한 전반적인 메시지를 저장. 주로 시스템 데몬들의 실행상황과 내역, 사용자들의 접속정보, TCP Wrapper 접근 제어 정보 등을 저장
- secure : 주로 사용자들의 원격접속 즉, 원격로그인 정보를 기록하고 있는 로그파일로 서버보안에 아주 민감하고 중요한 파일. 특히, tcp_wrapper(xinetd)의 접속제어에 관한 로그파일은 언제, 누가, 어디에서, 어떻게 접속했는가에 대한 로그를 기록

## IMG_5199 — 버퍼 오버플로우(Buffer Overflow) 공격 (textbook)

## ③ 버퍼 오버플로우(Buffer Overflow) 공격

- 기본 개념 : 프로그램의 복귀주소를 조작 하여, 궁극적으로 해커가 원하는 코드가 실행되게 하는 공격 방법
- 종류
  - 스택 오버플로우 : 저장된 데이터는 인접한 변수영역까지 침범하여 포인터 영역까지 침범하므로 해커가 원하는 특정 코드가 실행
  - 힙 오버플로우 : malloc 같은 메모리 할당 함수를 이용하여 프로그램을 사용할 때 할당하며 힙 영역을 오버플로우 시켜서 특정 코드를 실행
- 대응책
  - 경계값 체크나 파라미터 체크를 통해 방지
  - 언어 확장과 안전한 라이브러리의 사용
  - 스택 보호 메커니즘(Stack Guard) : 함수의 진입(entry)과 종료(exit) 코드를 조사하고 함수의 스택 프레임에 대해 손상이 있는지를 검사
  - 스택 쉴드(Stack Shield) : 리턴 주소를 안전한 공간에 복사해 두고, 함수가 종료될 때 현재 스택의 리턴 주소와 복사해둔 리턴 주소를 비교하여 변조되었는지 확인
  - 실행가능 주소 공간의 보호 : 스택과 힙을 실행불능(Non-Executable Stack)으로 만듦
  - 주소 공간의 임의 추출(ASLR, Address Space Layout Randomization) : 공격을 막는 다른 실행 시간 기법으로는 프로세스 주소 공간에 있는 중요 데이터 구조의 위치를 조작
  - 벤더에서 제공하는 소프트웨어 관련 패치를 적용

### Mentor's Know-how
- 많은 버퍼 오버플로우 공격의 핵심 요소는 오버플로우가 발생하는 버퍼에 저장되는 공격자의 코드로 실행 제어를 이동시키는 것입니다. 이 코드를 셸코드(shellcode)라고 합니다.

## IMG_5201 — 최신 보안 주제 - 블록체인(BlockChain) 기본개념 (textbook)

# Chapter 07 최신 보안 주제들

## ① 블록 체인(BlockChain)

- 기본 개념
  - 온라인 금융 거래 정보를 블록으로 연결하여 피투피(P2P) 네트워크 분산 환경에서 중앙 관리 서버가 아닌 참여자(피어, peer)들의 개인 디지털 장비에 분산저장시켜 공동으로 관리하는 방식(디지털 공동분산원장(mutual distributed ledger))
- 기반 기술
  - 분산 네트워크
    - 블록체인 정보는 네트워크에 참여하는 노드들이 가지고 있으며 동일한 거래 내역이 분산 저장되어 관리
  - 암호 기술
    - 공개키 암호와 전자서명
    - 해시 함수
- 이중거래 방지
  - 두 곳 이상의 계좌로 송금하는 행위를 방지하기 위해서 총 통화량, The Longest Chain Wins 메커니즘을 이용
    - 총 통화량 : 이중 거래 발생 시 총 통화량(2,100만개)이 초과됨
    - The Longest Chain Wins : 중복 지출에 의해 블록체인이 분기(Fork)될 경우 길이가 길어지는 체인을 옳은 것으로 간주
- 합의 기법
  - 작업증명(PoW, Proof of Work) : 새로 만든 블록을 앞 블록에 연결하는데 필요한 해시를 만들고 해시 연결성을 검증하여 데이터가 중간에 위변조가 되지 않았음을 확인
  - 지분증명(PoS, Proof of Staking) : 컴퓨팅 파워가 아닌 자신이 가진 가상통화의 양, 즉 지분(stake)에 따라 블록을 생성하고 추가적으로 발행되는 코인을 받음

### [박스: 블록체인과 비트코인]
비트코인(bitcoin)은 블록체인 기술을 기반으로 만들어진 온라인 암호화폐이다. 비트코인의 화폐 단위는 BTC 또는 XBT로 표시한다. 2008년 10월 사토시 나카모토라는 가명을 쓰는 프로그래머가 개발하여 2009년 1월 프로그램 소스를 배포했다. 중앙은행 없이 전 세계적 범위에서 P2P 방식으로 개인들 간에 자유롭게 송금 등의 금융거래를 할 수 있게 설계되어 있다. 거래장부는 블록체인 기술을 바탕으로 전 세계적인 범위에서 여러 사용자들의 서버에 분산하여 저장하기 때문에 해킹이 사실상 불가능하다. SHA-256 기반의 암호 해시 함수를 사용한다.

## IMG_5202 — 블록 헤더 구조, 블록체인 작동 원리, 블록체인 유형별 주요 특징 (textbook)

## ② 블록 헤더 구조

| 구분 | 크기(bytes) | 설명 |
|---|---|---|
| Version | 4 | 블록 버전 숫자 |
| Previous block hash | 32 | 이전 블록헤더를 sha256 해시함수를 이용하여 2번 해시한 해시값 sha256(sha256()) |
| Merkle hash root | 32 | 현재 블록에 포함된 거래정보의 거래 해시를 2진 트리 형태로 구성할 때 트리의 루트에 위치하는 해시값 |
| Timestamp | 4 | 블록의 생성시간, 1970년 1월 1일 이후의 초단위 시간 |
| Bits | 4 | 블록의 작업증명 알고리즘에 대한 난이도 목표 |
| Nonce | 4 | 특정 목표값보다 낮은 값을 구하기 위한 카운터 |

## ③ 블록체인의 작동 원리

[그림: 블록 연결 다이어그램. previous Block header → h(.) → Block 0 header(h(previous Block header), Time stamp, Nonce, Merkle root hash) → h(Block 0 header) → Transaction list → Block 0. 이어서 h(.) → Block 1 header(h(Block 0 header), Time stamp, Nonce, Merkle root hash) → h(Block 1 header) → Transaction list → Block 1. 이어서 h(.) → Block 2 header(h(Block 1 header), Time stamp, Nonce, Merkle root hash) → h(Block 2 header) → Transaction list → Block 2. 하단에 시간(time) 축 표시.
Merkle root hash = h(H4,H5) 트리 구조: H4 = h(H0,H1), H5 = h(H2,H3); H0 = h(Tx 0), H1 = h(Tx 1), H2 = h(Tx 2), H3 = h(Tx 3); 각각 Tx 0, Tx 1, Tx 2, Tx 3에서 도출]

## ④ 블록체인 유형별 주요 특징

| 구분 | 퍼블릭 블록체인 | 프라이빗 블록체인 |
|---|---|---|
| 속도 | 느림 | 빠름 |
| 권한 | 모든 참여자가 읽기, 쓰기, 합의 등 권한 보유 | 구성원에 따라 사용 가능한 권한 지정 가능 |
| 사례 | 비트코인(가상통화), 이더리움(가상통화/스마트계약) | 코다(금융), 하이퍼레저(범용) |

### Mentor's Know-how
- 누구나 참여할 수 있는 블록체인을 퍼블릭 블록체인이라고 하는데, 이는 퍼미션리스(permissionless) 블록체인 혹은 비허가형(공개형) 블록체인이라고 불립니다. 말 그대로 블록체인을 유지·관리하는 합의 과정에 누구나 참여할 수 있는 시스템을 말합니다.
- 프라이빗 블록체인의 합의 과정에 참여하려면 사전 승인이 필요합니다. 그 과정에서 신원이 모두 밝혀져서 익명성도 없습니다. 그리고 시스템 전체를 관리하는 중앙 관리 주체가 존재하며 이 주체가 참가자의 범위를 결정합니다.

- 컨테이너는 호스트 OS 자원을 공유하기 때문에 격리된 공간마다 게스트 OS를 설치할 필요가 없습니다. 따라서 가상머신 환경에 비해 오버헤드가 적으며, 가상 하드디스크 용량이 GB 단위인 가상머신에 비해 이미지 용량이 수백 MB로 작고 설치가 빠르다는 이점을 지닙니다.

## IMG_5205 — 일반 악성코드와 랜섬웨어의 차이점, APT(Advanced Persistent Threat) (textbook)

## ⑨ 일반 악성코드와 랜섬웨어의 차이점

| 구분 | 일반 악성코드 | 랜섬웨어 |
|---|---|---|
| 유포 | 웹사이트, 이메일, 네트워크 취약점 등 유포방식 동일 | (동일) |
| 감염 | SW 취약점 또는 피해자의 실행으로 악성코드 감염 동일 | (동일) |
| 동작 | 정보 및 파일 유출, DDoS 공격 등 | 문서, 사진, MBR 등 데이터 암호화 |
| 치료 | 백신 등을 통해 악성코드 치료 | 백신 등을 통해 악성코드 치료 → 암호화된 파일은 복구 어려움 |
| 피해 | 개인, 금융 정보 유출 및 이를 이용한 2차 공격으로 피해 발생 | 암호화된 파일에 대한 복호화를 빌미로 가상통화(비트코인 등)로 금전을 요구 |

### Mentor's Know-how
- 랜섬웨어는 이용자의 데이터(시스템 파일, 문서, 이미지, 동영상 등)를 암호화하고 복구를 위한 금전을 요구하는 악성코드 입니다
- 랜섬웨어는 몸값(Ransome)과 소프트웨어(Software)의 합성어 입니다

## ⑩ APT(Advanced Persistent Threat)

- 기본 개념
  - 특정 대상을 겨냥해 다양한 공격 기법을 이용하여 장기간 지속적으로 공격하는 것
  - 제로데이 공격과 같이 기존에 알려지지 않았던 취약점을 이용한 공격
- 공격 단계
  - 목표 대상에 대한 선행조사 끝에 이뤄지는 침투, 프로파일링을 통한 전반적인 기업 정보 검색, 정보를 내려받을 수 있는 새로운 악성코드를 유포해 기밀 정보 수집, 수집한 정보를 몰래 빼내오는 유출 등 4단계
- 주요 침투 기법
  - 스피어 피싱(Spear Phishing) 공격 : 불특정 다수가 아닌 특정인(조직)을 표적으로, 신뢰할 만한 발신인이 보낸 것처럼 위장한 메일을 이용해 악성 웹사이트로 유도 또는 악성 첨부 파일로 악성코드에 감염시키는 방식
  - 드라이브-바이-다운로드 공격(drive-by-download attack) : 목표로 삼은 조직의 구성원이 방문할 가능성이 높은 사이트를 미리 알아서 침해한 뒤 접속 즉시 악성 코드가 다운로드 되도록 하는 공격
  - 워터링 홀(Watering Hole) 공격 : 사자가 먹이를 습격하기 위해 물웅덩이(watering hole) 근처에서 매복하고 있는 형상을 빗댄 것으로 「표적 공격」의 일종
