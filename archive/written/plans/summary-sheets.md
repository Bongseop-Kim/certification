- 소스에서 **"계층화하면 안 되는 것 — 병렬 관계 경고 목록" 섹션은 뺀다**(사용자 지시).

## 3. 데이터 — 마크다운을 그대로 쓴다

JSON으로 옮기지 않는다. 문서가 이미 구조화돼 있고(##=시트, ###=소제목, 표, 목록, 함정 포인트, 📍), 앞으로도 마크다운으로 고치는 게 편하다.

```
sheets/
  1-system.md    # 1과목 (5장)
  2-network.md   # 2과목 (7장)
  3-app.md       # 3과목 (5장)
  4-general.md   # 4과목 (9장)
  5-law.md       # 5과목 (6장)
  9-final.md     # 부록 시험 직전 덤프 시트 (1장)
```

- 첫 줄 `# `이 묶음 제목, `## `마다 시트 하나. 파일명 앞 숫자가 순서.
- `import.meta.glob('../sheets/*.md', { query: '?raw', eager: true })`로 번들. `questions/*.json`과 같은 방식이다.
- 파서는 `scripts/md.mjs` 하나. 지원 문법은 문서에 실제로 나오는 것만: `#`/`##`/`###`, `|` 표, `-`/`1.` 목록(중첩 포함), `>` 인용, ``` 코드, 단락, 인라인 `**굵게**`와 `` `코드` ``. 그 외는 단락으로 떨어진다(깨지지 않고 덜 예쁠 뿐).
- 특수 줄 세 가지를 블록으로 승격한다: `**함정 포인트**` 뒤의 목록 → 함정 콜아웃, `📍 …` → 범위 태그, `🟡 …` → 경계 콜아웃.
- 파서를 `.mjs`로 두는 이유: `scripts/check.mjs`(Node)와 `src/`(Vite) 양쪽에서 같은 파일을 import한다. 타입은 옆의 `scripts/md.d.mts`에 둔다.

### 소스를 옮기면서 손으로 고칠 것

1. **ASCII 트리(코드 블록의 `├ └ │`) → 중첩 목록.** 지도 0-1·0-4·0-5·0-6(UTM/ESM/SIEM)·0-7(개인정보 유형 상자 그림, 처리 주체 트리), 5-1 위험 구성. 폰 폭에서 `<pre>`는 한 줄 60자를 못 담아 가로 스크롤 + 작은 글자가 되고, 스크린리더는 기호를 읽어준다. 중첩 `<ul>`은 글이 줄바꿈되고 의미도 남는다(§5).
2. **평행 목록 표 → 두 목록.** 5-1의 `| 정량적 분석 | 정성적 분석 |` 표는 행이 key→value가 아니라 두 열이 각각 독립 목록이다. 이대로 두면 "과거 자료 분석법 → 델파이법"처럼 읽힌다. `**정량적**` / `**정성적**` 소제목 아래 목록 둘로 바꾼다. 같은 유형이 더 있으면 같이 고친다(0-2·0-3의 축 나열 코드 블록도 표나 목록으로).
3. **화살표 절차(`① → ② → ③`, `SYN → SYN/ACK → ACK`) → 번호 목록.** 한 줄 화살표는 폰에서 어정쩡하게 꺾인다. 부록 "순서" 절도 동일.
4. **코드 블록으로 남기는 것**: Snort 룰 구조, `Risk = 자산 × 위협 × 취약점`, HMAC 식. 진짜 코드·수식이고 짧다. `overflow-x: auto`.
5. 경고 목록 섹션 삭제. 문서 맨 위 "사용법"과 목차는 뺀다(앱 목차가 대신한다). "출처 및 범위 기준"은 부록 끝에 남긴다.

## 4. 표를 폰에서 보이는 방법 (조사 결론)

조사에서 일관되게 나온 것: 폰에서 표는 **첫 열(식별자)을 고정하고 나머지는 한 번에 적게 보이거나 세로로 쌓는다**. 가로 스크롤은 잘린 셀로 존재를 알려야 하고, 회전 강제는 하지 않는다. 행이 많은 표를 카드로 쌓으면 행 경계가 사라져 오히려 나쁘다. 열이 많은 비교표는 열을 하나씩 돌려 보는(carousel) 방식이 폰에서 가장 낫다(UX Movement, NN/G).

문서의 표는 701행이고 열 수로 성격이 갈린다. **파서가 열 수와 셀 길이로 모드를 자동 결정**한다. 작성자가 표시를 달 필요 없다.

| 모드 | 조건 | 렌더링 | 해당 표 예 |
|---|---|---|---|
| `kv` | 2열 | 왼쪽 키(34%, 굵게) / 오른쪽 값. 줄바꿈 허용. 스크롤 없음 | 용어 정의, 플래그↔의미, 위험 대응 4가지, 루트키 |
| `grid` | 3열이고 첫 열 외 셀 평균 ≤ 12자 | 3열 표 그대로. `<th>` 헤더 sticky | 포트 번호, 키 개수 공식, IPSec 프로토콜 번호 |
| `stack` | 3열이고 셀이 길다 | 행 = 카드. 첫 셀이 제목, 나머지는 `헤더: 값` 줄로 쌓음 | DoS 공격/원리/대응, 방화벽 유형/계층/특징, 접근통제 3축 |
| `pick` | 4열 이상 | 첫 열 고정 + **속성 열 하나만** 표시. 상단 칩(`블록 크기 · 키 크기 · 라운드 · 구조 …`)으로 열 전환 | 4-1 대칭키 스펙(6열), 4-2 운영 모드(8열), 4-3 해시(6열), 2-3 스캔 응답(4열), 무선 LAN(4열) |

`pick`은 문서 자신이 권하는 학습법과 같다("블록 / 키 / 라운드 / 출력을 뒤섞어 낸다. 열을 반드시 분리해서 인출한다"). 8열 표를 폰에서 가로 스크롤로 보는 대안은 만들지 않는다. 필요해지면 `전체` 칩 하나 추가.

`stack`이 27행짜리 표에 걸리면 안 된다(행 경계 붕괴). 그래서 `grid` 판정을 평균 길이로 한다. 포트 표는 "DNS (질의 UDP, 존 전송 TCP)" 같은 긴 셀이 몇 개 있어도 평균이 짧아 `grid`로 간다. 판정이 어긋나는 표가 나오면 그때 표 앞 `<!-- stack -->` 주석 오버라이드를 파서에 넣는다. 지금은 안 만든다.

2×2 매트릭스(탐지 4분면: 빈 헤더 + 2열)는 `stack`으로 떨어진다: "공격이라 판단 — 실제 공격: TP / 실제 정상: FP". 읽힌다.

## 5. 트리·다이어그램

중첩 `<ul>`에 CSS로 연결선을 그린다(iamkate.com 방식): `li`의 `border-left`가 세로선, `li::before`가 가로 가지. `<details>` 접기는 넣지 않는다. 트리가 최대 20노드고 접을 이유가 없다.

- 글은 자연 줄바꿈. `word-break: keep-all`(한국어 단어 중간 끊김 방지) + `overflow-wrap: anywhere`(긴 영문 토큰 대비).
- 가지 끝 항목 나열(`DES · 3DES · SEED`)은 소스 그대로 한 노드 텍스트. 노드를 더 쪼개지 않는다.
- 지도 0-7의 벤 다이어그램은 SVG로 그리지 않는다. "개인정보 보호법 적용 대상 > 개인정보 > 일반 / 민감 / 고유식별 / 가명" 중첩 목록 + 형제로 "익명정보 (법 적용 ✗)". 경계 안/밖이라는 정보는 들여쓰기 깊이로 남는다.

## 6. 가독성 규칙 (폰)

- 본문 15px/1.65(기존). 표·카드 13.5px. 첫 열·키 `font-weight: 600`. 숫자 `tabular-nums`.
- 소스 `**굵게**`는 `<b>`(ink 색). 강조색을 쓰지 않는다. 시트 하나에 굵게가 수십 개라 색을 주면 전부 튄다.
- 함정 포인트 콜아웃은 `--fail` 왼쪽 테두리, 🟡 경계는 `--warn`, `>` 인용은 기존 `.callout`. 세 가지 이상 톤은 만들지 않는다.
- 📍 태그는 시트 맨 아래 `.label` 톤의 작은 글. 본문에서 눈에 안 띄어야 한다.
- 다크 모드는 토큰이 이미 있어 추가 작업 없음. 표 sticky 헤더 배경은 `--surface`.
- 페이지 가로 스크롤 금지. 스크롤이 필요한 것은 코드 블록만, 그 안에서 `overflow-x: auto`.
