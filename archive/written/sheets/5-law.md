# 5과목. 정보보안 관리 및 법규 — 6장

## 시트 5-1. 위험관리

### 2개의 독립된 축 (계층 아님)

| 축 | 묻는 질문 | 구성원 |
|---|---|---|
| **① 접근법** | 분석을 **어느 범위·깊이로** 할 것인가 | 기준선(Baseline) / 비정형(전문가 판단) / 상세 위험 분석 / **복합(권장)** |
| **② 방법론** | 위험을 **어떻게 측정·표현**할 것인가 | **정량적**: 과거자료·수학공식·확률분포·점수법 / **정성적**: **델파이**·시나리오·순위결정·질문서 |

- **DoA**는 위험 평가 단계의 비교 기준값이고, **잔여 위험**은 대책 선정 이후에 남는 값이다. 등장 시점이 다르다.

### 위험 구성 관계

**위험(Risk) = 자산(Asset) × 위협(Threat) × 취약점(Vulnerability)** − 정보보호 대책

- **자산**: 보호 대상의 가치 / **위협**: 손실을 유발하는 원인 / **취약점**: 위협이 이용하는 약점
- **DoA (Degree of Assurance / 수용 가능 위험 수준)**: 이 수준을 초과하는 위험에 대해서만 대책을 선정
- **잔여 위험(Residual Risk)**: 대책 적용 후 남는 위험 → DoA 이하로 관리

### ① 접근법 4

| 접근법 | 내용 |
|---|---|
| **기준선(Baseline) 접근법** | 표준·체크리스트 기반 일괄 적용. 빠르고 저렴, 조직 특성 반영 미흡 |
| **비정형(전문가 판단) 접근법** | 전문가 경험에 의존. 빠름, 일관성·객관성 부족 |
| **상세 위험 분석** | 자산·위협·취약점을 모두 식별·평가. 정확하나 시간·비용 과다 |
| **복합(통합) 접근법** | 고위험 영역은 상세, 나머지는 기준선. **실무 권장** |

### ② 방법론 — 정량적 vs 정성적

| 비교 | 정량적 | 정성적 |
|---|---|---|
| 결과 표현 | **금액·수치** | 고/중/저 등급, 서술 |
| 객관성 | 높음 | 낮음(주관 개입) |
| 비용·시간 | 많이 소요 | 적게 소요 |
| 비용/효익 분석 | **용이** | 어려움 |

- **정량 계산식**: `SLE = 자산가치 × EF(노출계수)` / `ALE = SLE × ARO(연간발생률)`

### 위험관리 절차

1. 위험관리 **전략 및 계획 수립** (범위·조직·방법론 결정)
2. **위험 분석** (자산 식별·평가 → 위협·취약점 평가 → 위험 산정)
3. **위험 평가** (DoA와 비교해 우선순위 결정)
4. **정보보호 대책 선정**
5. **정보보호 계획서 작성** (구현 계획)

### 위험 대응 4가지

| 대응 | 내용 |
|---|---|
| **위험 감소(완화)** | 보호대책 구현으로 위험 수준 낮춤 |
| **위험 수용** | DoA 이하이거나 대책 비용이 손실보다 클 때 그대로 감수 |
| **위험 회피** | 위험을 유발하는 자산·업무를 **제거·중단** |
| **위험 전가(전이)** | 보험 가입, **아웃소싱** 등으로 제3자에게 이전 |

**함정 포인트**
- **델파이법은 정성적**이다. 정량/정성 소속을 바꿔 내는 것이 단골이다.
- ALE = SLE × ARO. SLE와 ALE를 뒤집어 낸다.
- 보험 가입은 회피가 아니라 **전가**다. 서비스 중단은 **회피**다.
- 복합 접근법이 실무 권장안이며, 기준선 단독은 조직 특성 반영이 어렵다는 점이 정답 근거다.
- 위험 = 자산 × 위협 × 취약점. 여기에 "대책"이 곱셈 항으로 들어간 선지는 오답.
- **"다음 중 위험분석 방법론이 아닌 것"에 기준선 접근법을 끼워 넣는다.** 접근법과 방법론은 다른 축이다.
- 위험 대응 4종(감소·수용·회피·전가)은 방법론이 아니라 **대책 선정 단계의 선택지**다.

## 시트 5-2. 보호대책 3분류

> 이 축 하나가 **대책 구현 / 안전성 확보 조치 / ISMS 보호대책 요구사항**에 반복 적용된다. 개별 항목을 외우기 전에 바구니를 먼저 세우면, 새 항목이 나올 때 넣을 자리가 생긴다.

- **정보보호 대책**
  - **관리적** (사람·절차·문서)
    - 내부관리계획 · 정책·지침 수립 · 인력보안(내·외부) · 교육·훈련
    - 내부감사 · 침해사고 예방·대응 · 업무연속성관리(BCP) · 위탁 관리·감독
  - **물리적** (공간·설비)
    - 출입통제 · 시설 잠금 · 보호구역 지정 · 반출입 통제
    - 항온항습·소화설비 · 재해·재난 대비 · 개인 및 공용 환경 보안
  - **기술적** (시스템·데이터)
    - 접근권한 관리·최소 부여 · 접근통제(방화벽·IDS/IPS) · 암호화
    - 접속기록 보관·위·변조 방지 · 악성프로그램 방지 · 백업
    - 시스템·SW개발 보안 · 서버·네트워크·DB·어플리케이션 보안

**경계가 헷갈리는 항목의 소속**

| 항목 | 소속 | 근거 |
|---|---|---|
| 내부관리계획 수립·시행 | **관리적** | 문서·절차 |
| 접근 **권한** 관리 | **기술적**(권한 부여 실행) + 관리적(승인 절차) | 문항 문맥에 따름 |
| 접속기록 보관 | **기술적** | 시스템 로그 |
| 교육·훈련 | **관리적** | 사람 |
| 출입통제 장치(카드리더) | **물리적** | 공간 |
| BCP·재해복구 계획 | **관리적**(계획) / 복구센터 구축은 **물리적** | 계획과 설비를 구분 |

**함정 포인트**
- "다음 중 **기술적** 보호조치에 해당하는 것"에 내부관리계획·교육훈련을 끼워 넣는다.
- 물리적 조치를 관리적으로 옮긴 선지가 흔하다. **출입통제는 물리적**이다.
- 개인정보 안전성 확보 조치 문항도 이 3분류로 나누면 선지 판별이 빨라진다.

## 시트 5-3. BCP · 재해복구

### BCP 수립 4단계

1. **사업 영향 분석(BIA)**
2. 복구 전략 개발
3. 복구 계획 수립
4. **시험 및 유지보수**

- BIA에서 도출하는 것: 핵심 업무 식별, 중단 시 영향도, **MTD(최대 허용 중단 시간)**, 복구 우선순위

### 핵심 지표

| 지표 | 정의 | 방향 |
|---|---|---|
| **RTO** (Recovery Time Objective) | **목표 복구 시간** — 언제까지 서비스를 재개할 것인가 | 짧을수록 비용 ↑ |
| **RPO** (Recovery Point Objective) | **목표 복구 시점** — 언제 시점의 데이터까지 복구할 것인가 (허용 데이터 손실량) | 짧을수록 백업 빈도 ↑ |
| **MTD** | 최대 허용 중단 시간 | RTO ≤ MTD |
| RSO | 복구 수준 목표(어느 범위까지 복구) | |
| MTBF / MTTR | 평균 고장 간격 / 평균 수리 시간 | |

### 재해복구센터 유형

| 유형 | 복구 소요 시간 | 구성 | 비용 |
|---|---|---|---|
| **미러 사이트 (Mirror)** | **즉시 (0)** | 주센터와 동일 구성, 실시간 이중 운영 | 최고 |
| **핫 사이트 (Hot)** | **수 시간 내** | 동일 설비 + 데이터 실시간/준실시간 동기화, 대기 상태 | 높음 |
| **웜 사이트 (Warm)** | **수 일 ~ 수 주** | 중요 설비만 부분 구비, 주기적 백업 | 중간 |
| **콜드 사이트 (Cold)** | **수 주 ~ 수 개월** | 공간·전원·통신 회선만 확보, 장비 없음 | 최저 |
| 상호 협정(Reciprocal) | 협의에 따름 | 타 기관과 상호 지원 협약 | 저렴, 실효성 논란 |

### 백업 방식

| 방식 | 대상 | 복구 |
|---|---|---|
| 전체(Full) | 전체 데이터 | 가장 빠름 |
| **증분(Incremental)** | 직전 **백업** 이후 변경분 | 백업 빠름, **복구 느림** (모든 증분 필요) |
| **차등(Differential)** | 직전 **전체 백업** 이후 변경분 | 백업 느려짐, **복구 빠름** (전체 + 최종 차등) |

- RAID: 0(스트라이핑, 내결함성 없음) / 1(미러링) / 5(패리티 분산, 디스크 1개 장애 허용) / 6(패리티 2중) / 10(1+0)

**함정 포인트**
- **RTO(시간) ↔ RPO(시점/데이터 손실량)** 를 바꿔 낸다. "허용 가능한 데이터 손실"은 RPO다.
- 복구센터 4종의 **순서와 소요 시간 구간**을 섞어 낸다. 미러 → 핫 → 웜 → 콜드 순으로 고정.
- **증분(백업 빠름·복구 느림) ↔ 차등(백업 느림·복구 빠름)** 을 뒤집어 낸다.
- BCP의 첫 단계는 복구 전략이 아니라 **BIA**다.

## 시트 5-4. 침해사고 대응 · 디지털 포렌식

### 침해사고 대응 7단계

1. **사고 전 준비** (조직·절차·도구 준비)
2. **사고 탐지** (이상 징후 인지)
3. **초기 대응** (초기 조사, 피해 확산 차단, 증거 보존)
4. **대응 전략 체계화** (법적·업무적 고려해 대응 방향 결정)
5. **사고 조사** (데이터 수집 → 분석, 포렌식)
6. **보고서 작성**
7. **해결** (복구, 재발 방지 대책 적용)

### 디지털 포렌식 5원칙

| 원칙 | 내용 |
|---|---|
| **정당성의 원칙** | 적법한 절차로 수집한 증거만 인정 (독수독과) |
| **무결성의 원칙** | 수집 후 위·변조 없음 입증 → **해시값** 비교 |
| **재현의 원칙** | 동일 조건에서 같은 결과가 재현되어야 함 |
| **신속성의 원칙** | 휘발성 정보 소실 방지를 위해 지체 없이 수행 |
| **연계 보관성의 원칙 (Chain of Custody)** | 수집–이송–분석–보관–제출 전 과정의 **담당자·시각 기록**이 연속되어야 함 |

### 증거 수집 순서 (휘발성 높은 순)

1. 레지스터·캐시
2. **메모리(RAM)**
3. 네트워크 연결 상태·라우팅 테이블
4. 실행 중 프로세스
5. 임시 파일
6. **디스크**
7. 원격·백업 로그
8. 물리적 매체

- 원본 보존 원칙: **사본(이미지)** 을 만들어 분석하고 원본은 **쓰기 방지 장치(Write Blocker)** 로 보호
- 무결성 입증: 수집 시점과 분석 시점의 **해시값(MD5/SHA)** 일치 확인
- **안티 포렌식**: 데이터 완전 삭제(Wiping), 암호화, 스테가노그래피, 타임스탬프 조작

**함정 포인트**
- **연계 보관성(CoC)** 이 정답이 되는 문제가 가장 많다. "증거 이동 경로와 담당자 기록"이 키워드다.
- 무결성 입증 수단은 **해시값**이다. 전자서명·암호화로 바꾼 선지가 오답.
- 휘발성 순서에서 **메모리가 디스크보다 먼저**다. 순서를 뒤집어 낸다.
- 초기 대응 단계에서 성급한 시스템 종료·재부팅은 **휘발성 증거 소실**을 야기한다는 점이 자주 출제된다.

## 시트 5-5. 개인정보 보호법

> ⚠️ **수치는 백지 대상에서 제외한다.** 유출 통지·신고 기한, 과태료·과징금 액수, 보관 기간은 개정이 잦다. 시험 2주 전에 최신 조문으로 한 번만 확인한다.

### 개인정보 유형 — 포함 관계

- **개인정보 보호법 적용 대상**
  - **개인정보** — 살아 있는 개인 + 식별 가능
    - 일반 개인정보
    - **민감정보** — 별도 동의
    - **고유식별정보** — 4종, 별도 동의. 주민등록번호는 원칙적 처리 금지 + 암호화 의무
    - **가명정보** — 추가 정보 없이는 식별 불가. 여전히 개인정보 ✓ (법 적용)
- **적용 대상 아님**
  - **익명정보** — 결합해도 식별 불가 → 개인정보 ✗
  - 법인·단체 정보 / 사망자 정보 → 개인정보 ✗

### 처리 주체의 관계 (계층)

- **개인정보처리자** — 업무 목적으로 파일을 운용하는 자 = 법적 책임 주체
  - **개인정보취급자** — 지휘·감독을 받아 실제로 처리하는 임직원
  - **개인정보 보호책임자(CPO)** — 지정 의무
  - **수탁자** — 위탁받아 처리 (위탁자에게 관리·감독 의무)

### 핵심 용어 정의

| 용어 | 정의 요지 |
|---|---|
| **개인정보** | 살아 있는 **개인**에 관한 정보로 특정 개인을 알아볼 수 있는 정보. 다른 정보와 **쉽게 결합**하여 알아볼 수 있는 것 포함 |
| **처리** | 수집, 생성, 연계, 기록, 저장, 이용, 제공, 파기 등 |
| **정보주체** | 정보에 의해 알아볼 수 있는 사람 |

### 개인정보 보호 원칙

목적에 필요한 **최소 수집** / 목적 범위 내 적법·정당 처리 / **정확성·완전성·최신성** 보장 / 위험에 따른 안전한 관리 / **처리방침 공개** 등 투명성 / 정보주체 권리 보장 / **익명·가명 처리 우선** / 책임과 신뢰 확보

### 정보주체의 권리

1. 처리 여부를 확인하고 **열람**을 요구할 권리 (사본 발급 포함)
2. **정정·삭제**를 요구할 권리
3. **처리 정지**를 요구할 권리
4. 동의 여부·범위를 **선택하고 결정**할 권리
5. 처리에 관한 **정보를 제공받을** 권리
6. 피해를 신속·공정하게 **구제받을** 권리 (손해배상)
7. 자동화된 결정에 대한 **거부·설명 요구권**, 개인정보 **전송요구권** (최근 도입 — 최신 조문 확인 필요)

### 수집·이용의 법적 근거

정보주체의 **동의** / **법률의 특별한 규정** 또는 법령상 의무 준수 / 공공기관의 **소관 업무 수행** / **계약의 체결·이행**에 불가피 / 명백히 정보주체·제3자의 **급박한 생명·신체·재산 이익** / 처리자의 **정당한 이익** (정보주체 권리보다 명백히 우선하는 경우)

- 동의 요건: 자유로운 의사, 구체적 사항 고지, 명확한 인식, 명확한 의사표시
- 필수·선택 항목 구분 고지, **선택 동의 거부만으로 서비스 거부 금지**

### 민감정보 vs 고유식별정보

| 구분 | 항목 |
|---|---|
| **민감정보** | 사상·신념, 노동조합·정당 가입·탈퇴, 정치적 견해, 건강, 성생활, 유전정보, 범죄경력, **생체인식정보(식별 목적)**, 인종·민족 |
| **고유식별정보** | **주민등록번호, 여권번호, 운전면허번호, 외국인등록번호** (4종) |

- **고유식별정보 4종을 먼저 못 박고**, 나머지 특별 항목은 민감정보로 처리하면 분류 문항이 정리된다.
- 둘 모두 **별도 동의** 또는 법령 근거가 있어야 처리 가능
- **주민등록번호**는 원칙적으로 처리 금지 → 법령에 구체적 근거가 있는 경우 등으로 한정, **암호화 저장 의무**, 대체 수단(아이핀 등) 제공

### 처리 위탁 · 제3자 제공 · 국외 이전

| 구분 | 요건 |
|---|---|
| **위탁** | 위탁 업무 내용·수탁자를 **공개**. 원칙적으로 별도 동의 불필요, 위탁자에게 **관리·감독 의무** |
| **제3자 제공** | 제공받는 자, 목적, 항목, 보유기간, 거부 권리를 알리고 **별도 동의** |
| **국외 이전** | 원칙적으로 동의. 계약 이행에 필요·인증·상당한 수준 보호 인정 국가 등의 예외 |

### 파기

보유 기간 경과·처리 목적 달성 시 **지체 없이 파기**. 다른 법령에 따른 보존 시에는 **분리 보관**.
- 전자적 파일: 복원 불가능한 방법으로 영구 삭제 / 그 외 기록물: 파쇄·소각

### 안전성 확보 조치

→ 항목 구성은 **시트 5-2 보호대책 3분류**와 동일하다. 개인정보 문항에서는 **고유식별정보·비밀번호 암호화**와 **접속기록 보관·위·변조 방지**가 추가 강조된다.

### 관련 제도

| 제도 | 내용 |
|---|---|
| **개인정보 영향평가 (PIA)** | 대규모·민감 개인정보 파일 운용 시 위험 요인 분석·개선. 공공기관은 일정 요건에서 의무 |
| **개인정보 처리방침** | 수립·공개 의무 |
| **개인정보 보호책임자(CPO)** | 지정 의무 |
| **유출 통지·신고** | 정보주체 통지 + 보호위원회·전문기관 신고 (**기한·기준 인원은 최신 조문 확인**) |
| 손해배상 | 법정손해배상, 징벌적 손해배상 제도 |

**함정 포인트**
- **가명정보는 개인정보, 익명정보는 개인정보가 아니다.** 최다 출제 지점.
- **민감정보 ↔ 고유식별정보** 항목을 섞어 낸다. 고유식별정보는 **4종으로 고정**이므로 이것부터 외우고 나머지를 민감정보로 처리한다.
- **위탁은 공개, 제3자 제공은 동의**. 요건을 바꿔 낸다.
- 개인정보처리자(책임 주체)와 취급자(실제 처리자)의 정의를 바꿔 낸다.
- "사망한 사람의 정보", "법인·단체의 정보"는 개인정보가 **아니다**.

## 시트 5-6. 정보통신망법 · 인증제도 · 정보보안 윤리

### 정보통신망 이용촉진 및 정보보호 등에 관한 법률

| 항목 | 내용 |
|---|---|
| **목적** | 정보통신망의 **이용 촉진** + 정보통신서비스 이용자의 **개인정보 보호** + 정보통신망의 **안전한 이용 환경** 조성 |
| **적용 대상** | **정보통신서비스 제공자** 및 이용자 |

**핵심 용어**

| 용어 | 정의 요지 |
|---|---|
| **정보통신망** | 전기통신설비를 이용하거나 이와 컴퓨터·컴퓨터 이용 기술을 활용하여 정보를 수집·가공·저장·검색·송수신하는 정보통신체제 |
| **정보통신서비스 제공자** | 전기통신사업자 및 이를 이용해 영리 목적으로 정보 제공·매개하는 자 |
| **침해사고** | 해킹, 악성프로그램, 서비스거부공격 등으로 정보통신망·정보시스템에 발생한 사태 |
| **불법정보** | 음란, 명예훼손, 공포심·불안감 유발, 해킹·악성프로그램 유통 등 유통 금지 정보 |

**주요 규율 사항**
- **영리 목적 광고성 정보 전송**: 사전 동의 원칙(**옵트인**), 수신 거부 의사 표시 방법 명시, 야간 전송 제한, 제목에 광고 표기
- **접근권한 동의**: 이동통신 앱의 접근권한을 필수/선택 구분 고지 후 동의
- **침해사고 신고**: 침해사고 발생 시 과학기술정보통신부·KISA 등에 신고
- **정보보호 최고책임자(CISO)** 지정·신고
- **ISMS 인증**의 법적 근거
- **주민등록번호 사용 제한**, 본인확인기관 제도

> ⚠️ 개인정보 보호 조항 상당수는 개인정보 보호법으로 **이관**되었다. 현행 정보통신망법은 **망의 안전성·침해사고 대응·불법정보·광고성 정보** 중심이라는 역할 구분이 출제 포인트다.

### 정보보호 관리체계 인증 — ISMS / ISMS-P

| 항목 | 내용 |
|---|---|
| **ISMS** | 정보보호 관리체계 인증 |
| **ISMS-P** | 정보보호 **및 개인정보보호** 관리체계 인증 (개인정보 흐름까지 포함) |
| 인증 체계 | **정책기관** (과기정통부·개인정보보호위원회) — **인증기관** (KISA 등) — **심사기관** |
| 인증 기준 구성 | ① **관리체계 수립 및 운영** ② **보호대책 요구사항** ③ **개인정보 처리단계별 요구사항** (③은 ISMS-P만) |
| 유효기간·사후관리 | 인증 유효기간 내 **연 1회 이상 사후심사**, 만료 전 **갱신심사** |
| 심사 종류 | 최초심사 / 사후심사 / 갱신심사 |

🟡 경계: 인증기준 세부 **항목 수**는 개정 이력이 있어 특정 숫자를 외우지 않는 것이 안전하다. **인증 체계·대상·심사 종류·기준의 3영역 구성** 개념까지만 정리한다.

### 제품 인증

| 제도 | 내용 |
|---|---|
| **CC 인증 (Common Criteria)** | 정보보호 제품의 보안 기능을 국제 공통 기준으로 평가. **EAL 등급**으로 표현, **PP(보호 프로파일) / ST(보안목표명세서)** 개념 |
| 암호모듈 검증 (KCMVP) | 암호 모듈의 구현 적합성 검증 |

### 정보보안 윤리

| 영역 | 내용 |
|---|---|
| **디지털 저작권** | 저작권 침해 유형 / 보호기술 **DRM**(사용 권한 통제), **워터마킹**(소유권 표시 삽입), **포렌식 마킹**(구매자 정보 삽입 → 유출자 추적), CAS |
| **유해정보 유통** | 음란·폭력물, 청소년 유해 매체물 → 필터링·등급 분류 |
| **사이버 폭력** | 명예훼손, 모욕, 스토킹, 사이버 불링 |
| **사이버 사기** | 피싱(위조 사이트 유도) / **파밍**(DNS·호스트 조작) / **스미싱**(문자 + 악성 앱) / **큐싱**(QR) / **보이스피싱** / **스피어 피싱**(특정 대상 표적) / **BEC**(업무 메일 침해) |
| 이용자·취급자 금지행위 | 비인가 접근·정보 훼손, 악성프로그램 전달·유포, 대량 신호 전송으로 장애 유발, 업무 목적 외 개인정보 이용·제공·누설, 권한 없는 자의 열람·변경 |

**함정 포인트**
- **워터마킹(소유권 증명) ↔ 포렌식 마킹(구매자 식별 → 유출 경로 추적)** 을 바꿔 낸다.
- **피싱(유도) / 파밍(DNS·호스트 조작) / 스미싱(문자)** 의 구분이 반복 출제된다.
- ISMS와 ISMS-P의 차이는 **개인정보 처리단계별 요구사항** 영역의 유무다.
- 정보통신망법의 목적에는 "이용 촉진"이 들어간다. 정보보호만 적힌 선지는 불완전하다.
- 광고성 정보 전송은 **옵트인(사전 동의)** 원칙이다. 옵트아웃으로 바꾼 선지가 오답.
