# Part 0. 관계 지도 — 7개 영역

> **왜 7개만인가**
> 계층 트리는 **실재하는 포함 관계가 있을 때만** 효과가 있다. 포트 번호, 라운드 수, ICMP 타입, 8진수 권한처럼 논리적 이유 없이 짝지어진 값에 억지로 계층을 씌우면 없는 관계를 발명하게 되고, 잘못된 계층 하나가 여러 문항에 전파되어 표를 잘못 외우는 것보다 해롭다. 그런 항목은 각 과목 시트의 **규칙 압축 + 반복 인출**로 처리한다.
>
> **판단 기준**: 상위 개념의 정의로 하위를 설명할 수 있으면 **계층**, 안 되면 **병렬**이다.
>

## 지도 0-1. 암호 기술 전체 트리 — 4과목의 척추

- **암호 기술**
  - **대칭키** — 키 1개, 빠름, 키 배송 문제 有, 부인방지 ✗
    - **블록 암호**
      - Feistel 구조 — DES · 3DES · SEED · HIGHT · Blowfish
      - SPN 구조 — AES · ARIA
      - ARX — LEA · HIGHT
      - 운영 모드 — ECB · CBC (패딩 필요) / CFB · OFB · CTR (스트림형, 패딩 불필요)
    - **스트림 암호** — RC4 · A5/1 · LFSR 기반
  - **공개키** — 키 쌍, 느림, 키 배송 해결, 부인방지 ✓
    - 소인수분해 기반 — RSA(암호+서명) · Rabin
    - 이산대수 기반 — DH(키교환만) · ElGamal · DSA(서명만) · KCDSA(서명만)
    - 타원곡선 기반 — ECC · ECDSA · ECDH (짧은 키로 동일 안전성)
  - **해시 함수** — 일방향, 고정 길이 출력
    - **MDC** (키 ✗) — MD5 · SHA-1 · SHA-2 · SHA-3 · HAS-160 → 무결성만
    - **MAC** (키 ✓, 대칭키 공유) — HMAC(해시 기반) · CMAC/CBC-MAC(블록암호 기반) · GMAC → 무결성 + 송신자 인증, 부인방지 ✗

### 이 트리에서 곧바로 도출되는 정답 근거

| 트리상의 위치 | 도출되는 결론 |
|---|---|
| MAC이 해시 아래에 있으면서 **키를 쓴다** | 무결성 + 인증은 되고, 양측이 키를 공유하므로 **부인방지는 불가** |
| MDC는 키가 없다 | 무결성만. 송신자 인증도 불가 |
| CMAC이 **블록암호 기반** 가지에 있다 | 이름에 MAC이 있지만 해시 기반이 아니다 |
| DH가 이산대수 가지의 **키교환 전용** 노드 | "암호화 알고리즘"으로 분류한 선지는 오답 |
| 운영모드가 **블록 암호의 하위** | AES와 CBC는 같은 층이 아니다 (층 어긋남 함정) |
| 대칭키 가지에 부인방지 ✗ | 부인방지가 필요하면 공개키/전자서명으로 올라가야 한다 |

### 하이브리드 구조 (두 가지가 만나는 지점)

- 데이터 본문은 **대칭키**로 암호화한다 (빠름)
- 세션키는 **수신자 공개키**로 암호화해 전달한다 (키 배송 문제 해결)
- 전자서명: 메시지 **해시** → 해시값을 **송신자 개인키**로 서명 (해시 + 공개키의 결합)
- 인증 암호(AEAD): **CCM = CTR + CBC-MAC**, **GCM = CTR + GMAC** (대칭키 모드 + MAC의 결합)

**함정 포인트**
- 층 어긋남 선지가 전형이다. "AES는 스트림 암호", "CBC는 블록 암호의 한 종류" 같은 형태로 한 층을 건너뛴다.
- 말단 노드 하나만 바꿔 오답을 만든다. **ElGamal을 소인수분해 가지에**, **Rabin을 이산대수 가지에** 옮긴 선지를 확인한다.
- 암호화는 **수신자 공개키**, 서명은 **송신자 개인키**. 공개키 가지에서 방향이 반대임을 트리에 표시해둔다.

📍 [4과목 정보보안일반] 2. 암호학 > 암호 알고리즘(용어 및 암호시스템 구성, 대칭키, 공개키, 인수분해 기반, 이산로그 기반) / 해시함수(MAC의 원리·구조)

## 지도 0-2. 접근통제 — 3개의 독립된 축 (계층 아님)

> 여기가 축 혼합 함정의 최대 발생 지점이다. 표로 나열하면 세 축이 같은 층처럼 보인다.

| 축 | 묻는 질문 | 구성원 |
|---|---|---|
| **① 정책** | 누가 권한을 **결정**하나 | **DAC**(소유자·신분 기반) / **MAC**(관리자·보안등급 기반) / **RBAC**(직무 기반) |
| **② 기법** | 어떻게 **구현**하나 | 접근통제 행렬 / **ACL**(객체 기준) / **CL**(주체 기준) |
| **③ 모델** | 무엇을 **지키나** | **BLP**(기밀성) / **Biba·Clark-Wilson**(무결성) / **Chinese Wall**(이해충돌 방지) / Lattice |

- **ACL은 DAC의 하위가 아니다.** 다른 축의 구현 수단이며, MAC 환경에서도 사용될 수 있다.
- MAC(강제적 접근통제)과 MAC(메시지 인증 코드)은 **약어 충돌**이다. 같은 트리에 절대 넣지 않는다.
- 원칙(최소 권한 / 직무 분리 / 알 필요성)은 축이 아니라 **모든 축에 걸쳐 적용되는 요구사항**이다.

**함정 포인트**
- "DAC과 ACL 중 상위 개념은?"에 막히면 축을 섞은 상태다. 답은 "상하 관계가 아니다".
- "다음 중 접근통제 **정책**이 아닌 것"에 ACL이나 BLP를 끼워 넣는다.
- BLP↔Biba는 계층이 아니라 **방향이 정반대인 대립 짝**이다. (BLP = No Read Up + No Write Down)

📍 [4과목 정보보안일반] 1. 보안요소 기술 > 접근통제(정책의 이해 및 구성요소 / 특징 및 적용 범위 / 기법과 각 모델의 특징)

## 지도 0-3. 위험분석 — 2개의 독립된 축 (계층 아님)

| 축 | 묻는 질문 | 구성원 |
|---|---|---|
| **① 접근법** | 분석을 **어느 범위·깊이로** 할 것인가 | 기준선(Baseline) / 비정형(전문가 판단) / 상세 위험 분석 / **복합(권장)** |
| **② 방법론** | 위험을 **어떻게 측정·표현**할 것인가 | **정량적**: 과거자료·수학공식·확률분포·점수법 / **정성적**: **델파이**·시나리오·순위결정·질문서 |

**절차상의 위치도 구분한다** (축이 아니라 순서)

1. 전략·계획 수립
2. 위험 분석 (측정)
3. 위험 평가 (DoA와 비교)
4. 대책 선정 (감소·수용·회피·전가)
5. 계획서 작성

- **DoA**는 ③에서 비교 기준으로 쓰이는 값이고, **잔여 위험**은 ④ 이후에 남는 값이다. 등장 시점이 다르다.

**함정 포인트**
- **"다음 중 위험분석 방법론이 아닌 것"에 기준선 접근법을 끼워 넣는다.** 접근법과 방법론은 다른 축이다.
- **델파이법은 정성적**이다. 정량/정성 소속 뒤집기가 단골.
- 위험 대응 4종(감소·수용·회피·전가)은 방법론이 아니라 **④단계의 선택지**다.

📍 [5과목 정보보안관리및법규] 1. 정보보호 관리 > 정보보호 위험평가(위험분석 및 계획수립 / 위험분석 및 평가)

## 지도 0-4. 보호대책 3분류 — 5과목을 관통하는 바구니

> 이 축 하나가 **대책 구현 / 안전성 확보 조치 / ISMS 보호대책 요구사항**에 반복 적용된다. 개별 항목을 외우기 전에 바구니를 먼저 세우면, 새 항목이 나올 때 넣을 자리가 생긴다.

- **정보보호 대책**
  - **관리적** (사람·절차·문서)
    - 내부관리계획 · 정책·지침 수립 · 인력보안(내·외부) · 교육·훈련
    - 내부감사 · 침해사고 예방·대응 · 업무연속성관리(BCP) · 위탁 관리·감독
  - **물리적** (공간·설비)
    - 출입통제 · 시설 잠금 · 보호구역 지정 · 반출입 통제
    - 항온항습·소화설비 · 재해·재난 대비 · 개인 및 공용 환경 보안
  - **기술적** (시스템·데이터)
    - 접근권한 관리·최소 부여 · 접근통제(방화벽·IDS/IPS) · 암호화
    - 접속기록 보관·위·변조 방지 · 악성프로그램 방지 · 백업
    - 시스템·SW개발 보안 · 서버·네트워크·DB·어플리케이션 보안

**경계가 헷갈리는 항목의 소속**

| 항목 | 소속 | 근거 |
|---|---|---|
| 내부관리계획 수립·시행 | **관리적** | 문서·절차 |
| 접근 **권한** 관리 | **기술적**(권한 부여 실행) + 관리적(승인 절차) | 문항 문맥에 따름 |
| 접속기록 보관 | **기술적** | 시스템 로그 |
| 교육·훈련 | **관리적** | 사람 |
| 출입통제 장치(카드리더) | **물리적** | 공간 |
| BCP·재해복구 계획 | **관리적**(계획) / 복구센터 구축은 **물리적** | 계획과 설비를 구분 |

**함정 포인트**
- "다음 중 **기술적** 보호조치에 해당하는 것"에 내부관리계획·교육훈련을 끼워 넣는다.
- 물리적 조치를 관리적으로 옮긴 선지가 흔하다. **출입통제는 물리적**이다.
- 개인정보 안전성 확보 조치 문항도 이 3분류로 나누면 선지 판별이 빨라진다.

📍 [5과목 정보보안관리및법규] 1. 정보보호 관리 > 정보보호 대책 구현 및 사고대응(관리적·물리적·기술적 보호대책)

## 지도 0-5. DoS/DDoS — 3계층 분류 트리

- **DoS / DDoS**
  - **① 취약점 기반** — 단일·소량 패킷 조작, 구형
    - 헤더 조작 — Land (출발지=목적지)
    - 단편 조작 — Teardrop (Fragment Offset 중첩) · Ping of Death (Total Length 초과) · Bonk / Boink (순서번호 조작)
  - **② 자원 소진** — 대량 트래픽 / 연결 고갈
    - 연결 자원 — SYN Flooding (backlog 큐 고갈)
    - 대역폭 — UDP/ICMP Flooding
    - 반사·증폭 — Smurf (ICMP+브로드캐스트) · Fraggle (UDP) · DRDoS (DNS·NTP 리졸버). 공통 전제는 출발지 IP 위조
  - **③ 애플리케이션 계층** — L7, 소량 트래픽·정상 요청 형태
    - 느린 전송 — Slowloris (미완성 헤더) · RUDY (POST 본문) · Slow Read (Window 축소)
    - 반복 요청 — HTTP GET Flooding · Cache-Control 공격 · HULK (URL 무작위화)

### 계층 → 대응 수단이 그대로 따라 나온다

| 계층 | 대응 위치 |
|---|---|
| ① 취약점 기반 | **패치**, 비정상 패킷 폐기 |
| ② 자원 소진 | 방화벽·라우터, SYN Cookie, **출발지 IP 필터링(ingress)**, ISP 협조 |
| ③ L7 | **WAF**, 웹서버 타임아웃·동시연결 제한, 이상행위 기반 탐지 |

- 트리의 가치: 공격 이름만 보고도 **어느 계층인지 → 어떤 대응인지**가 도출된다. 개별 암기 항목이 절반으로 줄어든다.
- ②의 반사·증폭 3종은 **출발지 IP 위조**라는 공통 전제를 공유한다. 이 전제가 곧 공통 대응(ingress filtering)이다.

**함정 포인트**
- **Smurf(ICMP) ↔ Fraggle(UDP)** 프로토콜 뒤집기.
- ③의 세 가지는 **조작 대상이 각각 다르다**: 헤더 / POST 본문 / Window 크기.
- SYN Flooding을 대역폭 소진으로 분류한 선지가 오답. 대상은 **backlog 큐**다.

📍 [2과목 네트워크보안] 2. 네트워크 기반 공격기술의 이해 및 대응 > DoS/DDoS(유형별 동작원리·특징, 각각의 대응 방법)

## 지도 0-6. 보안 솔루션 — 기능 축 × 배치 축

> 솔루션은 단순 나열보다 **"무엇을 보나 / 어디에 놓이나"** 두 축으로 정리하면 비교 문항에 바로 대응된다.

| 솔루션 | 판단 기준 | 동작 | 배치 |
|---|---|---|---|
| **Firewall** | 정책(IP·포트) | 허용/차단 | 인라인 |
| **IDS** | 공격 패턴·이상 행위 | **탐지·경보만** | **미러링(passive)** |
| **IPS** | 공격 패턴·이상 행위 | 탐지 + **차단** | **인라인** |
| **WAF** | HTTP 요청 내용 | 웹 공격 차단 | 인라인/프록시 |
| **NAC** | 단말 인증·무결성 | 접근 허용 여부 | 접속 지점 |
| **VPN** | — | 터널링+암호화 | 경계 |
| **Honeypot** | — | 유인·정보 수집 | 격리망 |

**"통합" 계열은 통합 대상이 서로 다르다 — 계층 아님, 병렬**

| 계열 | 통합 대상 |
|---|---|
| **UTM** | 여러 보안 **기능**을 하나의 장비로 통합 (방화벽+IPS+AV+VPN). 장점 관리 편의, 단점 단일 장애점(SPOF) |
| **ESM** | 여러 장비의 **로그**를 통합 관제·상관분석 |
| **SIEM** | ESM 확장. 빅데이터 기반 장기 로그 분석·상관 |

- **IPS ⊄ IDS.** 기능이 포함되는 것처럼 보이지만 배치(인라인/미러링)가 달라 별개 솔루션이다.
- **UTM(장비 통합) ↔ ESM(로그 통합)** 은 통합의 대상이 다른 병렬 관계다.

**함정 포인트**
- IDS를 인라인, IPS를 미러링으로 바꿔 낸다. 배치가 정답 근거로 쓰인다.
- IPS의 단점으로 **오탐 시 정상 서비스 차단**이, UTM의 단점으로 **SPOF**가 출제된다.
- ESM을 "통합 보안 장비"로 서술한 선지는 UTM과 바꿔 낸 오답이다.

📍 [2과목 네트워크보안] 3. 네트워크 보안 기술 > 네트워크 보안기술 및 응용(보안 솔루션)

## 지도 0-7. 개인정보 유형 — 포함 관계

- **개인정보 보호법 적용 대상**
  - **개인정보** — 살아 있는 개인 + 식별 가능
    - 일반 개인정보
    - **민감정보** — 별도 동의
    - **고유식별정보** — 4종, 별도 동의. 주민등록번호는 원칙적 처리 금지 + 암호화 의무
    - **가명정보** — 추가 정보 없이는 식별 불가. 여전히 개인정보 ✓ (법 적용)
- **적용 대상 아님**
  - **익명정보** — 결합해도 식별 불가 → 개인정보 ✗
  - 법인·단체 정보 / 사망자 정보 → 개인정보 ✗

### 고유식별정보는 4종으로 고정

**주민등록번호 · 여권번호 · 운전면허번호 · 외국인등록번호**
→ 이 4개를 먼저 못 박고, 나머지 특별 항목은 **민감정보**로 처리하면 분류 문항이 정리된다.

**민감정보**: 사상·신념, 노조·정당 가입·탈퇴, 정치적 견해, 건강, 성생활, 유전정보, 범죄경력, 생체인식정보(식별 목적), 인종·민족

### 처리 주체의 관계 (계층)

- **개인정보처리자** — 업무 목적으로 파일을 운용하는 자 = 법적 책임 주체
  - **개인정보취급자** — 지휘·감독을 받아 실제로 처리하는 임직원
  - **개인정보 보호책임자(CPO)** — 지정 의무
  - **수탁자** — 위탁받아 처리 (위탁자에게 관리·감독 의무)

**함정 포인트**
- **가명정보는 개인정보, 익명정보는 아니다.** 최다 출제 지점. 다이어그램에서 경계선의 안/밖으로 기억한다.
- 민감정보와 고유식별정보 항목을 섞어 낸다. **고유식별정보 4종부터** 고정한다.
- 개인정보처리자(책임 주체) ↔ 취급자(실제 처리자) 정의 뒤집기.
- 사망자·법인 정보는 개인정보가 아니다.
