# 4과목. 정보보안 일반 — 9장

> **약점 영역, 최우선 학습.** 숫자·분류가 가장 밀집되어 있어 백지 복원 효과가 가장 크다.

## 시트 4-1. 암호 기술 전체 트리

- **암호 기술**
  - **대칭키** — 키 1개, 빠름, 키 배송 문제 有, 부인방지 ✗
    - **블록 암호**
      - Feistel 구조 — DES · 3DES · SEED
      - SPN 구조 — AES · ARIA
      - 경량(국산) — LEA · HIGHT
      - 운영 모드 — ECB · CBC (패딩 필요) / CFB · OFB · CTR (스트림형, 패딩 불필요)
    - **스트림 암호** — RC4 · A5/1 · LFSR 기반
  - **공개키** — 키 쌍, 느림, 키 배송 해결, 부인방지 ✓
    - 소인수분해 기반 — RSA(암호+서명) · Rabin
    - 이산대수 기반 — DH(키교환만) · ElGamal · DSA(서명만) · KCDSA(서명만)
    - 타원곡선 기반 — ECC · ECDSA · ECDH (짧은 키로 동일 안전성)
  - **해시 함수** — 일방향, 고정 길이 출력
    - **MDC** (키 ✗) — MD5 · SHA-1 · SHA-2 · SHA-3 · HAS-160 → 무결성만
    - **MAC** (키 ✓, 대칭키 공유) — HMAC(해시 기반) · CMAC/CBC-MAC(블록암호 기반) · GMAC → 무결성 + 송신자 인증, 부인방지 ✗

### 이 트리에서 곧바로 도출되는 정답 근거

| 트리상의 위치 | 도출되는 결론 |
|---|---|
| MAC이 해시 아래에 있으면서 **키를 쓴다** | 무결성 + 인증은 되고, 양측이 키를 공유하므로 **부인방지는 불가** |
| MDC는 키가 없다 | 무결성만. 송신자 인증도 불가 |
| CMAC이 **블록암호 기반** 가지에 있다 | 이름에 MAC이 있지만 해시 기반이 아니다 |
| DH가 이산대수 가지의 **키교환 전용** 노드 | "암호화 알고리즘"으로 분류한 선지는 오답 |
| 운영모드가 **블록 암호의 하위** | AES와 CBC는 같은 층이 아니다 (층 어긋남 함정) |
| 대칭키 가지에 부인방지 ✗ | 부인방지가 필요하면 공개키/전자서명으로 올라가야 한다 |

### 하이브리드 구조 (두 가지가 만나는 지점)

- 데이터 본문은 **대칭키**로 암호화한다 (빠름)
- 세션키는 **수신자 공개키**로 암호화해 전달한다 (키 배송 문제 해결)
- 전자서명: 메시지 **해시** → 해시값을 **송신자 개인키**로 서명 (해시 + 공개키의 결합)
- 인증 암호(AEAD): **CCM = CTR + CBC-MAC**, **GCM = CTR + GMAC** (대칭키 모드 + MAC의 결합)

**함정 포인트**
- 층 어긋남 선지가 전형이다. "AES는 스트림 암호", "CBC는 블록 암호의 한 종류" 같은 형태로 한 층을 건너뛴다.
- 말단 노드 하나만 바꿔 오답을 만든다. **ElGamal을 소인수분해 가지에**, **Rabin을 이산대수 가지에** 옮긴 선지를 확인한다.
- 암호화는 **수신자 공개키**, 서명은 **송신자 개인키**. 공개키 가지에서 방향이 반대임을 트리에 표시해둔다.

📍 [4과목 정보보안일반] 2. 암호학 > 암호 알고리즘(용어 및 암호시스템 구성, 대칭키, 공개키, 인수분해 기반, 이산로그 기반) / 해시함수(MAC의 원리·구조)

## 시트 4-2. 대칭키 알고리즘 스펙표

| 알고리즘 | 블록 크기 | 키 크기 | 라운드 | 구조 | 비고 |
|---|---|---|---|---|---|
| **DES** | 64 | **56** (64 중 8은 패리티) | 16 | Feistel | 키 길이 취약 |
| **3DES** | 64 | 112 / 168 | 48 (16×3) | Feistel | EDE 방식 |
| **SEED** | 128 | 128 (SEED-128) | 16 | Feistel | 국내 표준(KISA) |
| **AES (Rijndael)** | 128 | 128 / 192 / 256 | **10 / 12 / 14** | **SPN** | 미국 표준 |
| **ARIA** | 128 | 128 / 192 / 256 | **12 / 14 / 16** | Involutional SPN | 국내 표준 |

### 이름·특징만 알면 되는 것

- **LEA** — 국산 **경량·고속** 블록 암호(블록 128, 키 128/192/256), ARX 구조
- **HIGHT** — 국산 **경량**(RFID·센서용), **블록 64**로 국산 중 유일한 예외
- **IDEA** — PGP에 사용, 블록 64 / 키 128
- **Blowfish · RC5** — 가변 키 길이가 특징인 Feistel 계열. 스펙 암기 불필요

### 압축 규칙 (외울 개수 줄이기)

- **AES 라운드 = (키 비트 ÷ 32) + 6** → 계산으로 해결, 암기 불필요
- **ARIA = AES + 2** (12/14/16)
- **국산 알고리즘 블록은 모두 128** — 단, **HIGHT만 64**
- **SEED = DES와 같은 16라운드**, 블록만 두 배(128)

### 스트림 암호

| 알고리즘 | 특징 |
|---|---|
| **RC4** | 가변 키 스트림 암호. WEP·초기 SSL에 사용, 현재 취약 |
| A5/1 | GSM 이동통신 |
| LFSR 기반 | 선형 피드백 시프트 레지스터 |

- 블록 암호 vs 스트림 암호: 처리 단위(블록/비트), 속도, 오류 전파, 하드웨어 적합성

**함정 포인트**
- **DES의 키는 56비트**다. "64비트"는 단골 오답 선지(8비트는 패리티).
- **블록 / 키 / 라운드 / 출력**을 서로 뒤섞어 낸다. 시트를 만들 때 열을 반드시 분리해서 인출한다.
- **Feistel(DES·3DES·SEED) vs SPN(AES·ARIA)** 구조를 짝지어 외운다.
- ARIA·LEA·SEED·HIGHT는 모두 국내 표준이지만 **HIGHT만 블록 64**다.

🟡 경계: 스펙표 숫자 문항은 **DES·3DES·AES·SEED·ARIA** 5개에 집중된다. LEA·HIGHT·IDEA·Blowfish·RC5는 "어떤 알고리즘인가"를 고르는 선지 수준으로만 나오므로 라운드·구조 세부는 외우지 않는다.

📍 [4과목 정보보안일반] 2. 암호학 > 암호 알고리즘 > 대칭키(종류, 구조)

## 시트 4-3. 블록 암호 운영 모드 5

| 모드 | 정식 명칭 | IV 필요 | 패딩 필요 | 암호화 병렬 | 복호화 병렬 | 오류 전파 | 성질 |
|---|---|---|---|---|---|---|---|
| **ECB** | Electronic CodeBook | **불필요** | 필요 | O | O | 해당 블록만 | 동일 평문 → **동일 암호문** (패턴 노출, 가장 취약) |
| **CBC** | Cipher Block Chaining | 필요 | 필요 | **X** (순차) | O | **해당 + 다음 블록** | 가장 널리 사용, 이전 암호문 XOR |
| **CFB** | Cipher FeedBack | 필요 | **불필요** | X | O | 해당 + 이후 블록 | 블록 암호를 **스트림처럼** 사용 |
| **OFB** | Output FeedBack | 필요 | **불필요** | X | X | **해당 비트만** | 키스트림 사전 생성 가능, 오류 전파 없음 |
| **CTR** | Counter | 필요(Nonce+카운터) | **불필요** | **O** | **O** | 해당 비트만 | 완전 병렬, 랜덤 액세스 가능 |

### 수식으로 외우기
- P 평문 · C 암호문 · E 암호화 · K 키 · S 키스트림

```
ECB: C = E(K, P)
CBC: C = E(K, P XOR 이전 C)
CFB: C = P XOR E(K, 이전 C)
OFB: S = E(K, 이전 S)        C = P XOR S
CTR: S = E(K, Counter)      C = P XOR S
```
- ECB·CBC는 **평문을 E에 넣는다** → 블록 단위, 패딩 필요
- CFB·OFB·CTR은 **E의 출력을 P와 XOR** → 스트림 방식, 패딩 불필요
- OFB·CTR의 S는 P와 무관 → 사전 생성 가능, 오류 전파 없음

### 정리 규칙
- **패딩이 필요한 모드는 ECB·CBC 두 개뿐** (나머지는 스트림 방식)
- **IV가 불필요한 모드는 ECB뿐**
- **완전 병렬 처리 가능한 모드는 ECB·CTR**
- 인증 결합 모드: **CCM (CTR + CBC-MAC)**, **GCM (CTR + GMAC)** → 기밀성 + 무결성 동시 제공

**함정 포인트**
- **CBC는 암호화가 병렬 불가, 복호화는 병렬 가능**. 방향을 구분해 묻는다.
- ECB의 결정적 치명점은 "동일 평문 블록 → 동일 암호문 블록"이다.
- OFB·CTR은 **오류 전파가 없다**. CBC는 두 블록에 영향을 준다.
- GCM/CCM은 암호화 모드에 **MAC이 결합된** 인증 암호(AEAD)라는 점이 출제 포인트.

📍 [4과목 정보보안일반] 2. 암호학 > 암호 알고리즘 > 대칭키(운영 모드)

## 시트 4-4. 해시함수 · MAC

### 해시함수 스펙표

| 알고리즘 | 출력 크기 | 블록 크기 | 라운드 | 안전성 |
|---|---|---|---|---|
| **MD5** | **128** | 512 | 64 (4×16) | 충돌 발견, 사용 금지 |
| **SHA-1** | **160** | 512 | 80 (4×20) | 충돌 발견, 폐기 권고 |
| **SHA-224 / SHA-256** | 224 / 256 | **512** | 64 | 현행 권고 |
| **SHA-384 / SHA-512** | 384 / 512 | **1024** | 80 | 현행 권고 |

### 이름·특징만 알면 되는 것

- **SHA-3 (Keccak)** — Merkle-Damgård가 아닌 **스펀지(Sponge) 구조**. "SHA-2의 후속" 정도만
- **HAS-160** — 국산 해시(160비트), **KCDSA**용

### 압축 규칙
- **이름에 숫자가 있으면 그것이 출력 크기** (SHA-256 → 256비트)
- 예외로 새로 외울 것: **MD5=128 / SHA-1=160** 두 개뿐
- **SHA-2: 블록 512 → 64라운드, 블록 1024 → 80라운드**
- 예외: SHA-1은 블록 512인데 라운드 80

### 해시함수 요구조건

| 요구조건 | 내용 |
|---|---|
| 압축성 | 임의 길이 입력 → 고정 길이 출력 |
| 계산 용이성 | 해시 계산이 빠름 |
| **일방향성 (역상 저항성)** | 해시값 h로부터 원문 m을 찾기 어려움 |
| **약한 충돌 저항성 (제2 역상 저항성)** | 주어진 m에 대해 H(m)=H(m')인 **다른** m'을 찾기 어려움 |
| **강한 충돌 저항성 (충돌 저항성)** | H(m1)=H(m2)인 **임의의 쌍**을 찾기 어려움 |

- **생일 공격**: n비트 해시의 충돌을 찾는 데 약 **2^(n/2)** 회 → 강한 충돌 저항성의 안전도 기준
- 일방향성 공격 복잡도는 2^n

### MAC vs MDC vs 전자서명

| 구분 | MDC | MAC | 전자서명 |
|---|---|---|---|
| 사용 키 | **없음** (해시만) | **대칭키(공유 비밀키)** | 개인키(공개키 암호) |
| **무결성** | 제공 | 제공 | 제공 |
| **송신자 인증** | **미제공** | 제공 | 제공 |
| **부인 방지** | 미제공 | **미제공** (키를 양측이 공유) | **제공** |

### MAC 구현 방식

| 방식 | 기반 |
|---|---|
| **HMAC** | 해시함수 기반. `H( (K⊕opad) || H( (K⊕ipad) || M ) )` |
| **CMAC / CBC-MAC** | 블록 암호(CBC 모드) 기반 |
| GMAC | 갈루아 필드 곱셈 기반 (GCM에 사용) |

**함정 포인트**
- **MAC은 부인 방지를 제공하지 않는다.** 최다 출제 지점. 이유는 양측이 같은 키를 공유하기 때문이다.
- 출력 크기 vs 블록 크기 혼동: **SHA-512의 512는 출력이고 블록은 1024**다.
- **약한 충돌(m이 고정) vs 강한 충돌(쌍을 자유 선택)** 의 정의를 바꿔 낸다.
- SHA-3만 스펀지 구조, MD5·SHA-1·SHA-2는 Merkle-Damgård다.
- 생일 공격의 복잡도는 2^n이 아니라 **2^(n/2)** 다.

📍 [4과목 정보보안일반] 2. 암호학 > 해시함수(개요 및 요구사항 / 해시함수별 특징·구조 / MAC의 원리·구조)

## 시트 4-5. 공개키 암호 분류

### 수학적 난제별 분류

| 기반 난제 | 알고리즘 | 용도 |
|---|---|---|
| **소인수분해 (Factorization)** | **RSA**, Rabin | 암호화 + 서명 |
| **이산대수 (Discrete Logarithm)** | **Diffie-Hellman**, ElGamal, DSA, KCDSA | DH=키 교환 / DSA·KCDSA=서명 전용 |
| **타원곡선 이산대수 (ECDLP)** | **ECC**, ECDSA, ECDH | 짧은 키로 동일 안전성 → 경량 환경 |
| 배낭 문제 | Merkle-Hellman | 취약(파기됨) |
| 격자(Lattice) | NTRU 등 | 양자 내성(🟡 경계) |

### 키 개수 공식

| 방식 | 필요한 키 개수 (n명) |
|---|---|
| **대칭키** | **n(n-1)/2** 개 |
| **공개키** | **2n** 개 (각자 공개키 1 + 개인키 1) |

### 대칭키 vs 공개키

| 항목 | 대칭키 | 공개키 |
|---|---|---|
| 키 | 암·복호 동일 | 공개키/개인키 쌍 |
| 속도 | **빠름** | 느림 (수백~수천 배) |
| 키 배송 문제 | **있음** | 해결 |
| 부인 방지 | 불가 | **가능** |
| 용도 | 대용량 데이터 암호화 | 키 교환, 전자서명, 소량 데이터 |
| 하이브리드 | 데이터는 대칭키, **세션키는 공개키로** 전달 | |

### RSA 핵심 절차
1. 큰 소수 p, q 선택 → n = p × q
2. φ(n) = (p-1)(q-1)
3. gcd(e, φ(n)) = 1 인 공개 지수 e 선택
4. d ≡ e⁻¹ mod φ(n) → 개인키
5. 암호화 C = M^e mod n / 복호화 M = C^d mod n

- 공개키 = (e, n), 개인키 = (d, n)
- **전자서명 시에는 개인키로 서명, 공개키로 검증** (암호화와 키 사용이 반대)

### Diffie-Hellman
- 목적: **키 교환만** (암호화·서명 불가)
- 취약점: **중간자 공격(MITM)** — 상호 인증 수단이 없음 → 인증 결합 필요
- 변형: ECDH, DHE(순방향 비밀성)

**함정 포인트**
- **DH는 키 교환 전용**이다. "암호화 알고리즘"으로 분류한 선지가 오답.
- DSA·KCDSA는 **서명 전용**으로 암호화에 쓸 수 없다.
- 키 개수 공식 n(n-1)/2 ↔ 2n을 바꿔 낸다. 인원수를 대입해 계산하는 문제로 나온다.
- RSA는 소인수분해, ElGamal·DSA는 이산대수. 난제 소속을 바꿔 낸다.
- 암호화는 **수신자 공개키**, 서명은 **송신자 개인키**. 방향 문제가 반복 출제된다.

📍 [4과목 정보보안일반] 2. 암호학 > 암호 알고리즘 > 공개키(종류, 구조, 특징) / 인수분해 기반 / 이산로그 기반

## 시트 4-6. 전자서명 · PKI

### 전자서명 요구조건 5

| 요건 | 내용 |
|---|---|
| **위조 불가** | 서명자만 서명 생성 가능 |
| **서명자 인증** | 서명자 신원 확인 가능 |
| **부인 방지** | 서명 사실을 부인할 수 없음 |
| **변경 불가** | 서명된 문서 내용 변경 불가 |
| **재사용 불가** | 다른 문서에 서명을 옮겨 붙일 수 없음 |

### 서명 방식

| 알고리즘 | 기반 |
|---|---|
| RSA 서명 | 소인수분해 |
| **DSA** | 이산대수 (미국 표준, 서명 전용) |
| **KCDSA** | 이산대수 (국내 표준, HAS-160과 조합) |
| ECDSA / EC-KCDSA | 타원곡선 |

- **서명 순서**: 메시지 해시 → 해시값을 **개인키로 서명** → 검증은 공개키로
- 메시지 전체가 아니라 **해시값에 서명**하는 이유: 속도, 서명 크기 고정

### 특수 전자서명 응용

| 종류 | 목적 |
|---|---|
| **은닉서명 (Blind Signature)** | 서명자가 **내용을 모른 채** 서명 → **익명성** (전자화폐) |
| **이중서명 (Dual Signature)** | 두 정보를 분리 보관하며 연관성 증명 (**SET**) |
| 부인방지 서명 | 서명자 동의 없이 검증 불가 |
| 위임서명 | 대리인이 서명 수행 |
| 다중서명 | 여러 서명자가 하나의 문서에 서명 |

### X.509 v3 인증서 필드

버전 / **일련번호(Serial Number)** / 서명 알고리즘 식별자 / **발급자(Issuer, CA)** / **유효기간(Validity)** / **주체(Subject)** / **주체 공개키 정보** / 발급자·주체 고유 식별자 / **확장 영역(Extensions)** / **CA의 전자서명**

### 인증서 폐지 확인

| 방식 | 특징 |
|---|---|
| **CRL** (인증서 폐지 목록) | **주기적** 배포, 오프라인 확인 가능, **실시간성 부족**, 목록 크기 증가 |
| **OCSP** (온라인 인증서 상태 프로토콜) | **실시간** 질의·응답, 응답자(Responder) 부하·가용성 의존 |
| Delta CRL | 변경분만 배포해 크기 축소 |

- 폐지 사유: 개인키 유출, 소속 변경, 정보 변경, 발급 오류 등

### PKI 신뢰 모델

| 모델 | 구조 |
|---|---|
| **계층 구조 (Hierarchical)** | 단일 루트 CA → 하위 CA. 경로가 단순·유일, **루트 침해 시 전체 영향** |
| **네트워크(그물) 구조** | CA 간 **상호 인증**. 유연·확장성, **경로 탐색 복잡** |
| **혼합형(복합형)** | 계층 + 네트워크 결합 |

- PKI 구성요소: 정책승인기관(PAA) / 정책인증기관(PCA) / **인증기관(CA)** / **등록기관(RA)** / 검증기관 / 디렉터리(LDAP) / 사용자
- RA는 **신원 확인·등록 대행**, 인증서 발급은 CA가 한다.

**함정 포인트**
- **CRL(주기적) ↔ OCSP(실시간)** 를 바꿔 낸다.
- 인증서에 들어가는 것은 **주체의 공개키**다. 개인키는 절대 포함되지 않는다.
- 은닉서명 = 익명성(전자화폐), 이중서명 = SET. 짝을 고정한다.
- 서명은 개인키, 검증은 공개키. 암호화와 반대 방향임을 반복 확인한다.
- **RA는 발급 권한이 없다** (등록·신원확인만).

📍 [4과목 정보보안일반] 1. 보안요소 기술 > 디지털서명(인증서 구조, 종류·요구조건·서명 방식, PKI 구성·관리(CRL·OCSP), 응용(은닉서명·이중서명))

## 시트 4-7. 접근통제 모델

### 3개의 독립된 축 (계층 아님)

> 여기가 축 혼합 함정의 최대 발생 지점이다. 아래 세 절을 표로만 나열하면 같은 층처럼 보인다.

| 축 | 묻는 질문 | 구성원 |
|---|---|---|
| **① 정책** | 누가 권한을 **결정**하나 | **DAC**(소유자·신분) / **MAC**(관리자·보안등급) / **RBAC**(직무) |
| **② 기법** | 어떻게 **구현**하나 | 접근통제 행렬 / **ACL**(객체 기준) / **CL**(주체 기준) |
| **③ 모델** | 무엇을 **지키나** | **BLP**(기밀성) / **Biba·Clark-Wilson**(무결성) / **Chinese Wall**(이해충돌) / Lattice |

- **ACL은 DAC의 하위가 아니다.** 다른 축의 구현 수단이며, MAC 환경에서도 쓰인다.
- MAC(강제적 접근통제)과 MAC(메시지 인증 코드)은 **약어 충돌**이다. 같은 트리에 넣지 않는다.
- 원칙(최소 권한 / 직무 분리 / 알 필요성)은 축이 아니라 **모든 축에 걸쳐 적용되는 요구사항**이다.

### ① 정책 — 접근통제 3대 정책

| 정책 | 결정 주체 | 기준 | 특징 |
|---|---|---|---|
| **DAC** (임의적) | **소유자(Owner)** | **신분(Identity)** | 유연, 트로이목마에 취약, 대부분 상용 OS |
| **MAC** (강제적) | **관리자/시스템** | **보안 등급(Label)** | 규칙 기반, 매우 엄격, 군·정부. 성능·구현 부담 |
| **RBAC** (역할기반) | 관리자 | **직무(Role)** | 인사 이동 대응 용이, 최소권한·직무분리 구현에 적합 |

### ② 기법 — 접근통제 구현 기법

| 기법 | 내용 |
|---|---|
| **접근통제 행렬** | 주체 × 객체 2차원 표 |
| **ACL (접근통제 목록)** | **객체** 기준으로 접근 가능한 주체 나열 |
| **CL (자격 목록, Capability List)** | **주체** 기준으로 접근 가능한 객체 나열 |
| 보안 등급(Label) | 주체의 인가 등급 vs 객체의 분류 등급 비교 |

### ③ 모델 — 보안 모델

| 모델 | 목표 | 규칙 |
|---|---|---|
| **BLP (Bell-LaPadula)** | **기밀성** | **No Read Up** (단순 보안 속성) + **No Write Down** (*-속성) |
| **Biba** | **무결성** | **No Read Down** + **No Write Up** (BLP와 정반대) |
| **Clark-Wilson** | 무결성 + **상업적 무결성** | 잘 구성된 트랜잭션(Well-formed Transaction), **직무 분리**, 무결성 검증 절차 |
| **Chinese Wall (Brewer-Nash)** | **이해 충돌 방지** | 과거 접근 이력에 따라 동적으로 접근 제한 (컨설팅·금융) |
| Lattice 모델 | 등급 격자 구조 | 상·하한 등급 범위 내 접근 |
| 무결성 3원칙 | — | 무단 변경 방지 / 부적절한 변경 방지 / 내·외부 일관성 |

### 최소권한 관련 원칙
- **최소 권한(Least Privilege)**: 업무 수행에 필요한 최소한만 부여
- **직무 분리(Separation of Duty)**: 한 사람이 전 과정을 수행하지 못하게 분리
- **알 필요성(Need to Know)**: 필요한 정보에만 접근

**함정 포인트**
- **BLP와 Biba는 방향이 정반대**다. 백지에서 가장 많이 뒤집히는 짝이다. "**기밀성=Read Up 금지 / 무결성=Read Down 금지**"로 고정한다.
- BLP의 *-속성은 **Write Down 금지**이고, 단순 보안 속성이 Read Up 금지다.
- **ACL(객체 기준) ↔ CL(주체 기준)** 을 바꿔 낸다.
- DAC은 신분 기반, MAC은 규칙(등급) 기반. "MAC=소유자 결정"은 오답.
- Clark-Wilson의 키워드는 **직무 분리 + 잘 구성된 트랜잭션**이다.
- "DAC과 ACL 중 상위 개념은?"에 막히면 축을 섞은 상태다. 답은 **"상하 관계가 아니다"**.
- "다음 중 접근통제 **정책**이 아닌 것"에 ACL이나 BLP를 끼워 넣는다.

📍 [4과목 정보보안일반] 1. 보안요소 기술 > 접근통제(정책의 이해 및 구성요소 / 특징 및 적용 범위(임의적·강제적·역할기반) / 기법과 각 모델의 특징)

## 시트 4-8. 인증 · 키 분배 · 암호 공격

### 사용자 인증 4요소

| 요소 | 영어 | 예 |
|---|---|---|
| **지식** | Something you **know** | 패스워드, PIN, 패스프레이즈 |
| **소유** | Something you **have** | OTP 토큰, 스마트카드, 인증서 |
| **존재(생체)** | Something you **are** | 지문, 홍채, 얼굴, 정맥 |
| **행위** | Something you **do** | 서명 필기, 음성, 걸음걸이 |
| (추가) 위치 | Somewhere you are | GPS, IP 기반 |

- **2요소 인증(2FA)**: 서로 **다른 범주**에서 2개. 패스워드 + PIN은 2요소가 아니다.

### 생체인증 평가 지표

| 지표 | 의미 |
|---|---|
| **FAR (오인식률, Type II)** | 타인을 본인으로 **잘못 수락** → 보안상 더 위험 |
| **FRR (오거부율, Type I)** | 본인을 **잘못 거부** → 사용성 저하 |
| **CER / EER** | FAR = FRR이 되는 지점. **낮을수록 우수한 시스템** |

- 생체정보 요구조건: 보편성, 유일성, 지속성, 획득성, 정확성, 수용성, 기만 불가능성

### 챌린지-리스폰스 / Kerberos

| 항목 | 내용 |
|---|---|
| 챌린지-리스폰스 | 서버가 난수(challenge)를 보내고, 클라이언트가 비밀키로 응답 생성 → **재전송 공격 방지**, 패스워드 미전송 |
| **Kerberos** | **대칭키 기반** 티켓 인증, 포트 88 |
| 구성 | **KDC = AS(인증 서버) + TGS(티켓 발급 서버)** |
| 흐름 | ① AS에 인증 요청 → **TGT** 수신 ② TGT로 TGS에 요청 → **서비스 티켓** 수신 ③ 서비스 티켓으로 서버 접근 |
| 특징 | SSO 지원, **타임스탬프**로 재전송 방지 |
| 단점 | **KDC 단일 실패점(SPOF)**, 시간 동기 필수, 패스워드 추측 공격에 취약 |

### 키 분배

| 방식 | 내용 |
|---|---|
| 대칭키 기반 | KDC를 통한 세션키 분배 (Needham-Schroeder, Kerberos) |
| 공개키 기반 | **Diffie-Hellman** 키 합의, 공개키로 세션키 암호화 전달 |
| 키 관리 단계 | 생성 → 분배 → 저장·사용 → 갱신 → 폐기 |
| **PFS(순방향 비밀성)** | 장기키가 유출되어도 과거 세션키는 안전 (DHE·ECDHE) |

### 암호 공격 유형 (공격자가 가진 정보 기준)

| 공격 | 공격자가 가진 것 |
|---|---|
| **COA (암호문 단독 공격)** | 암호문만 |
| **KPA (기지 평문 공격)** | 일부 평문–암호문 **쌍** |
| **CPA (선택 평문 공격)** | 임의의 **평문을 선택**해 그 암호문을 얻을 수 있음 |
| **CCA (선택 암호문 공격)** | 임의의 **암호문을 선택**해 그 평문을 얻을 수 있음 |

### 암호 분석 기법

| 기법 | 내용 |
|---|---|
| 전수 조사(Brute Force) | 모든 키 시도 |
| 통계적 분석 | 문자 출현 빈도 이용 (고전 암호) |
| **차분 분석(Differential)** | 평문 차이 → 암호문 차이의 확률 편중 이용 |
| **선형 분석(Linear)** | 선형 근사식의 편향 이용 |
| **부채널 공격(Side Channel)** | 소비 전력·시간·전자파·소리 등 **물리 정보** 이용 |
| 중간자 공격(MITM) | 통신 경로에 개입해 양측을 각각 속임 |
| 중간 일치 공격(Meet-in-the-Middle) | 2DES 무력화 → 3DES 채택 근거 |
| 사전 공격 / 레인보우 테이블 | 해시 역추적 → **솔트(Salt)** 로 대응 |

**함정 포인트**
- **FAR(오인식, Type II)가 보안상 더 위험**하다. FRR과 Type 번호를 바꿔 낸다.
- CER/EER은 **낮을수록** 좋은 시스템이다.
- **CPA(평문 선택) ↔ CCA(암호문 선택)** 를 바꿔 낸다. 이름 그대로 선택 대상이 다르다.
- Kerberos는 **대칭키 기반**이다. "공개키 기반"은 오답. 단점으로는 SPOF와 시간 동기가 정답으로 쓰인다.
- 부채널 공격은 알고리즘의 수학적 약점이 아니라 **구현·물리 정보**를 이용한다.

📍 [4과목 정보보안일반] 1. 보안요소 기술 > 인증(사용자·메시지·디바이스 인증) / 키 분배 프로토콜 / 2. 암호학 > 암호 공격 유형별 특징

## 시트 4-9. 오답 메모 — 헷갈린 짝

> 실제로 틀린 문항에 남긴 대조 메모만 모았다. **메모 수가 가장 많은 과목**이다.

### 운영 모드

| 항목 | 구분 |
|---|---|
| **동기식** | 키스트림을 평문·암호문과 **독립적으로** 생성 → **OFB, CTR** |
| **자기동기식(비동기식)** | **이전 암호문**을 이용해 생성 → **CFB** |
| 이전 값 의존 | CBC·CFB = 이전 **암호문 블록** / OFB = 이전 **암호화 출력** |
| 비트 오류 전파 | ECB 해당 블록 전체 / CBC 현재 블록 전체 + **다음 블록** / CFB 현재 블록 전체 + 이후 일정 구간 / **OFB·CTR 대응 비트 하나만 반전** |
| 권장 | **CBC**(안정적), **CTR**(병렬 가능·빠름). 나머지 비권장, 특히 **ECB** |
| **CCM / GCM** | CTR + **CBC-MAC** / CTR + **GHASH(GMAC)** |
| **링크 / 종단 간 암호화** | 홉마다 복호화 / **최종 수신자만** 복호화 |

### 암호 해독

| 항목 | 해독 방법 |
|---|---|
| **치환 암호** | 빈도 분석 |
| **전치 암호** | 문자 배열·순서 분석 |
| **차분 암호해독** | 평문의 차이와 암호문의 차이 **사이의 관계** 분석 |
| **선형 암호해독** | 평문·암호문·키 비트 사이의 **선형 근사식** 이용 |

### 공개키 · 키 관리

| 항목 | 내용 |
|---|---|
| **RSA** | **소인수분해** 기반 + 암호화 + 전자서명 |
| **DSA** | **이산로그** 기반 + **전자서명 전용**(암호화 ✗) |
| 기반 문제 | 소인수분해 = RSA·Rabin / 이산로그 = DH·ElGamal·DSA |
| RSA 키 생성 | 소수 p, q → n = pq. **Φ(N) = (p−1)(q−1)**, 공개키 e / 개인키 d. `C = Pᵉ mod n` |
| 타원곡선 조건 | **4a³ + 27b² ≠ 0** — 곡선에 특이점이 없어야 함 |
| **DEK / KEK** | 대량 데이터를 암호화하는 키 / **DEK 자체를 암호화**해 저장하는 키 |
| **KDC / 사전 공유** | 신뢰하는 제3자와 각 사용자가 키 공유 / 통신 당사자끼리 직접 공유 |
| **하이브리드(전자봉투)** | 본문은 **대칭키**, 그 대칭키는 **수신자 공개키**로 암호화 |
| **Blom / Kerberos** | 노드들이 **자체적으로** 세션키 생성 / **KDC가** 티켓과 세션키를 직접 발급 |
| Kerberos 분류 | 티켓 기반 **인증 시스템**이며 키 분배에 KDC를 이용한다 — **키 분배 방식 자체로 분류하지 않는다** |

### 인증 프로토콜

| 항목 | 내용 |
|---|---|
| **Needham-Schroeder** | KDC + **Nonce(비표 Ra, Rb, Rb−1)** 기반 상호인증 |
| **Kerberos** | KDC(AS/TGS) + TGT·서비스 티켓 + **Timestamp** 중심 |
| **AS / TGS** | 티켓 발급 티켓(**TGT**) 발급 / TGT를 검증하고 **서비스 티켓** 발급 |
| 구성요소 | **PKI** = CA, RA, 저장소(Repository) / **Kerberos** = AS, TGS |
| **PAA → PCA → CA → RA** | 최상위 정책 승인 → 자기 도메인 정책과 CA 관리 → 인증서 발급 → 사용자 등록·신원확인 |
| 시간 동기화 | → 타임스탬프 검증 가능 → **재전송 공격 방지** |

### 해시 · 무결성

| 항목 | 구분 |
|---|---|
| **MDC / MAC** | 키 **없음**, 무결성 확인 / **비밀키** + 무결성 + 메시지 인증 |
| **역상 저항성** | 해시값 → 원문을 찾을 수 없음 |
| **제2역상 저항성** | 원문 고정 → 같은 해시가 되는 **짝**을 찾을 수 없음 |
| **충돌 저항성** | 같은 해시값이 되는 **서로 다른 두 입력**을 찾을 수 없음 |
| **생일 공격** | = 충돌 공격. n비트 해시 → **2^(n/2)** |
| 성질 ↔ 공격 | 충돌 저항성 → 생일 공격 / 역상 저항성 → 무차별 대입 / 패스워드 해시 → 사전 공격·레인보우 테이블 |
| **레인보우 테이블** | 비밀번호와 해시값을 미리 대량 계산해 둔 표 → **Salt**로 방어 |
| 공격 ↔ 대응 | 재전송 → nonce·timestamp / 중간자 → 인증된 키 교환·TLS / 세션 하이재킹 → TLS·토큰 관리 |
| 무결성 수단 구분 | **CRC·패리티** = 우연한 전송 오류 검출 / **OTP** = 로그인 인증 / **메시지 인증** = 무결성 + 송신자 인증 |

### 전자서명 · 인증서

| 항목 | 내용 |
|---|---|
| **전자서명** | 인증 + 무결성 + **부인방지**까지 포함해야 한다 |
| **전자봉투** | 메시지는 대칭키, 그 대칭키는 공개키로 암호화 |
| **DSS / DSA** | 전자서명 **표준** / DSS에서 사용하는 서명 **알고리즘** |
| **의뢰 부인방지 서명** | 지정된 제3자가 부인·검증 절차를 수행 |
| **위임 서명** | 다른 사람에게 서명 권한을 위임 |
| **CRL / OCSP** | 폐지 인증서 **목록**을 받아 확인 / 서버에 물어 **실시간** 상태 확인 |
| OCSP 응답 | **good**(정상) / **revoked**(폐지됨) / **unknown**(알 수 없음) |

### 개념 구분

- **위협** = 원인·행위 / **위험** = 가능성과 그 영향
- **스테가노그래피** = 정보은닉. 정상 활용은 기밀 메시지 전달·저작권 보호, 악용하면 이미지 안에 악성코드를 숨긴다
- **방사(Emanation)** = 장비에서 나오는 전자파·소리·전기 신호를 도청하는 공격

**함정 포인트**
- **동기식(OFB·CTR) ↔ 자기동기식(CFB)** 소속을 뒤집어 낸다. 기준은 "이전 암호문에 의존하는가"다.
- **DSA는 서명 전용**이다. "RSA와 달리 암호화도 가능하다"는 선지는 오답.
- **Blom(자체 생성) ↔ Kerberos(KDC 발급)** 는 세션키를 누가 만드느냐가 다르다.
- **FAR(오인증) ↔ FRR(거부)** 은 백지에서 가장 자주 뒤집힌다.
- **SSD(배정) ↔ DSD(활성화)** 는 금지 시점이 다르다.
