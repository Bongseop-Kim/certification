# 1과목. 시스템 보안 — 4장

> 학습자 강점 영역. **정의 1줄 + 명칭**까지만 복원한다. 실습·코드는 범위 밖.

## 시트 1-1. Windows 시스템 구조

### 인증 구성요소

| 구성요소 | 역할 |
|---|---|
| WinLogon | 로그온 요청 처리, 사용자 인터페이스 담당 |
| LSA (Local Security Authority) | 사용자 계정 검증, 접근토큰(Access Token) 생성, 감사 로그 기록 |
| SAM (Security Account Manager) | 사용자·그룹 계정 정보 DB (`%SystemRoot%\System32\config\SAM`) |
| SRM (Security Reference Monitor) | 객체 접근 권한 판단(SID 기반), 접근 허용/거부 결정 |

**로그온 순서**

1. WinLogon
2. LSA
3. SAM 조회
4. LSA가 접근토큰 발급
5. SRM이 객체 접근 통제

### 레지스트리 5대 루트키

| 루트키 | 내용 |
|---|---|
| HKEY_LOCAL_MACHINE (HKLM) | 하드웨어·설치 SW·서비스 등 시스템 전역 설정 |
| HKEY_CURRENT_USER (HKCU) | 현재 로그온 사용자 환경 설정 |
| HKEY_USERS (HKU) | 모든 사용자 프로파일 |
| HKEY_CLASSES_ROOT (HKCR) | 파일 확장자 연결, COM 객체 등록 정보 |
| HKEY_CURRENT_CONFIG (HKCC) | 현재 하드웨어 프로파일 |

### FAT vs NTFS

| 항목 | FAT32 | NTFS |
|---|---|---|
| 접근통제(ACL) | 미지원 | **지원** |
| 암호화 | 미지원 | **EFS 지원** |
| 압축 | 미지원 | 지원 |
| 저널링(복구) | 미지원 | **지원** |
| 디스크 쿼터 | 미지원 | 지원 |
| 최대 파일 크기 | 4GB | 사실상 볼륨 크기 |

**SID 구조**: `S-1-5-21-<도메인>-<RID>` / RID 500=Administrator, 501=Guest, 512=Domain Admins

**함정 포인트**
- SAM은 계정 정보 저장, LSA는 검증·토큰 발급, SRM은 접근 판단 — 세 개의 역할을 서로 바꿔 낸다.
- 보안 기능(ACL·EFS·저널링)은 **전부 NTFS 전용**이다.

## 시트 1-2. UNIX/Linux 권한과 계정 파일

### 퍼미션 8진수

| 권한 | 값 | 파일에서 의미 | 디렉터리에서 의미 |
|---|---|---|---|
| r (read) | 4 | 파일 내용 읽기 | 목록 조회(ls) |
| w (write) | 2 | 내용 수정 | 파일 생성·삭제 |
| x (execute) | 1 | 실행 | 진입(cd), 내부 접근 |

### 특수 권한

| 권한 | 8진수 | 표기 | 의미 |
|---|---|---|---|
| SetUID | 4000 | `rws------` (소유자 x 자리 s) | 실행 시 **소유자 권한**으로 동작 |
| SetGID | 2000 | `---rws---` (그룹 x 자리 s) | 실행 시 **그룹 권한**으로 동작 |
| Sticky Bit | 1000 | `------rwt` (기타 x 자리 t) | 소유자만 삭제 가능 (예: `/tmp` = 1777) |

- 위험 권한 점검: `find / -perm -4000 -type f` (SetUID 파일 탐색)
- 실행 권한이 없으면 `S`/`T`(대문자)로 표기 → 오설정 신호

### /etc/passwd — 7필드

`username : x : UID : GID : comment : home_directory : login_shell`

| 순번 | 필드 |
|---|---|
| 1 | 사용자명 |
| 2 | 패스워드 자리 (shadow 사용 시 `x`) |
| 3 | UID (root = 0) |
| 4 | GID |
| 5 | 설명(comment/GECOS) |
| 6 | 홈 디렉터리 |
| 7 | 로그인 셸 (`/bin/false`, `/sbin/nologin` = 로그인 차단) |

### /etc/shadow — 9필드

| 순번 | 필드 |
|---|---|
| 1 | 사용자명 |
| 2 | 암호화된 패스워드 (`*`, `!!` = 잠김) |
| 3 | 마지막 변경일 (1970-01-01 기준 일수) |
| 4 | 최소 변경 간격(일) |
| 5 | 최대 사용 기간(일) |
| 6 | 만료 경고 일수 |
| 7 | 비활성(유예) 일수 |
| 8 | 계정 만료일 |
| 9 | 예약 필드 |

### umask

- 기본값 022 → **파일 644**, **디렉터리 755**
- 계산: 파일 `666 - umask`, 디렉터리 `777 - umask`
- 보안 강화 권고값 027 또는 077

**함정 포인트**
- SetUID(4000) ↔ SetGID(2000) 값을 바꿔 낸다. **4가 U, 2가 G**로 기억.
- passwd는 7필드, shadow는 9필드. 개수 자체를 물어본다.
- 파일 권한 계산에서 파일은 666에서, 디렉터리는 777에서 뺀다.

## 시트 1-3. 로그 파일 ↔ 확인 명령어 매핑

| 로그 파일 | 기록 내용 | 확인 명령어 | 형식 |
|---|---|---|---|
| **wtmp** | 로그인·로그아웃 성공 이력, 재부팅 | `last` | 바이너리 |
| **utmp** | **현재** 로그인 중인 사용자 | `who`, `w`, `users`, `finger` | 바이너리 |
| **btmp** (Linux) / loginlog (Solaris) | **로그인 실패** 이력 | `lastb` | 바이너리 |
| **lastlog** | 사용자별 **마지막** 로그인 시각 | `lastlog`, `finger` | 바이너리 |
| **sulog** | `su` 명령 사용 이력 | 텍스트 조회 | 텍스트 |
| **pacct / acct** | 사용자별 실행 명령 이력 | `lastcomm`, `acctcom` | 바이너리 |
| **messages** | 시스템 전반 syslog (부팅, 커널, 서비스) | 텍스트 조회 | 텍스트 |
| **secure** (RedHat) / auth.log (Debian) | 인증·원격접속 관련 | 텍스트 조회 | 텍스트 |
| **xferlog** | FTP 파일 전송 이력 | 텍스트 조회 | 텍스트 |
| **history** | 셸 명령 입력 이력 | `history` | 텍스트 |
| (wtmp 기반 집계) | 로그인 접속 시간 총계 | `ac` | — |

- syslog 설정 파일: `/etc/syslog.conf` (또는 `rsyslog.conf`)
- syslog 형식: `facility.priority  action` (예: `*.info /var/log/messages`)

**함정 포인트**
- **wtmp(성공) / btmp(실패) / utmp(현재) / lastlog(마지막)** — 4개 짝이 핵심 출제 지점이다.
- 바이너리 로그는 `cat`으로 볼 수 없다 → 전용 명령어가 필요하다는 점을 묻는다.
- `last`는 wtmp, `lastb`는 btmp, `lastcomm`은 pacct. 접미사로 구분해 외운다.

## 시트 1-4. 메모리 공격기법과 대응기술

### 공격기법 (정의 1줄)

| 기법 | 정의 |
|---|---|
| **Buffer Overflow (스택)** | 지역 버퍼 경계를 넘겨 **RET(복귀 주소)** 를 덮어써 실행 흐름을 탈취 |
| **Buffer Overflow (힙)** | 동적 할당 영역의 메타데이터·함수 포인터를 변조 |
| **Format String** | `printf(user_input)` 처럼 서식 문자열을 사용자 입력으로 받아 `%n` 등으로 메모리 읽기/쓰기 |
| **Race Condition (TOCTOU)** | 검사 시점과 사용 시점의 시간 차를 이용, 주로 심볼릭 링크 + SetUID 프로그램 악용 |
| **Return-to-libc** | 스택 실행 불가 환경에서 libc의 기존 함수 주소로 복귀시켜 실행 |
| **Integer Overflow** | 정수 자료형 범위 초과로 크기 계산이 왜곡되어 경계 검사 우회 |

### 대응기술 명칭

| 대응기법 | 원리 |
|---|---|
| **스택가드 (Stack Guard) / Canary** | RET 앞에 canary 값을 두고 함수 종료 시 변조 여부 검사 |
| **스택쉴드 (Stack Shield)** | 함수 시작 시 RET를 별도 영역(Global RET Stack)에 복사, 종료 시 비교 |
| **ASLR** | 스택·힙·라이브러리 주소를 실행마다 무작위 배치 |
| **DEP / NX bit** | 데이터 영역(스택·힙)에 실행 권한 제거 |
| **PIE** | 실행 파일 자체 코드 영역도 무작위 배치 |
| **RELRO** | GOT 영역을 읽기 전용으로 변경 |
| 안전 함수 사용 | `strcpy→strncpy`, `sprintf→snprintf`, `gets→fgets` |

### Race Condition 대응
심볼릭 링크 검사, 임시파일 생성 시 배타적 생성(`O_EXCL`), 임시파일명 예측 불가하게, 불필요한 SetUID 제거

**함정 포인트**
- **스택가드 = canary 값 검사 / 스택쉴드 = RET 복사·비교**. 둘을 뒤집어 낸다.
- ASLR은 **주소 무작위화**, DEP/NX는 **실행 권한 제거**. 목적이 다르다.
- BOF의 최종 목표는 "RET 덮어쓰기"라는 점이 정답 근거로 자주 쓰인다.
