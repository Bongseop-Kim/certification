정보보안기사 실기 라디오. 6편. 내부 서버를 부른 이미지 주소 사건.

오늘 나오는 용어는 일곱 개입니다. 에스에스알에프, 아이엠디에스 버전 투, 운영체제 명령어 삽입, 경로 조작, 파일 다운로드 취약점, 로컬 파일 인클루전, 리모트 파일 인클루전. 공통점은 하나입니다. 사용자가 준 값을 서버가 그대로 믿고 무언가를 대신 해 줬다는 것입니다.


첫 번째 장면. 서버가 대신 가져다준 주소.

목요일 아침, 클라우드 보안 알림이 옵니다. 쇼핑몰 서버의 자격 증명이 낯선 해외 아이피에서 사용됐다는 내용입니다. 개발자가 박 선임에게 달려갑니다.

개발자가 말합니다. 서버 키를 코드에 넣은 적은 없는데, 키가 어떻게 밖으로 나갔죠?

박 선임이 웹 로그를 봅니다. 상품 리뷰에 이미지 주소를 넣으면 서버가 그 이미지를 대신 받아 와서 미리보기를 만들어 주는 기능이 있었습니다. 그 기능에 들어온 주소가 이상했습니다. 에이치티티피 콜론 슬래시 슬래시 백육십구 점 이백오십사 점 백육십구 점 이백오십사, 그리고 슬래시 레이티스트 슬래시 메타 데이터 슬래시 아이엠 슬래시 시큐리티 크리덴셜스.

박 선임이 설명합니다. 에스에스알에프, 서버 측 요청 위조예요. 공격자가 서버에게 이 주소 좀 가져와 달라고 시킨 거예요. 바깥에서는 못 들어가는 내부 주소라도, 서버는 내부망 안에 있으니까 접근할 수 있잖아요. 이 백육십구 점 이백오십사로 시작하는 주소는 클라우드 인스턴스 메타데이터 서비스예요. 서버의 아이엠 롤 임시 자격 증명을 알려 주는 곳이죠. 미리보기 기능이 그 응답을 그대로 보여 줬고, 공격자는 키를 얻은 거예요.

여기서 잠깐 떠올려 보세요. 에스에스알에프와 씨에스알에프는 이름이 비슷합니다. 요청을 위조당하는 주체가 각각 누구일까요?

답입니다. 씨에스알에프는 사용자의 브라우저가 원치 않는 요청을 보내게 됩니다. 에스에스알에프는 서버가 원치 않는 요청을 보내게 됩니다. 2025년 1회 실기에 서버가 클라이언트 요청으로 내부 자원에 접근하게 되는 공격이 무엇이냐는 문제로 나왔습니다.

정리합니다. 에스에스알에프. 검증하지 않은 사용자 입력 주소로 서버가 요청을 보내게 해서 내부망 자원에 접근하는 공격.


두 번째 장면. 메타데이터 문에 자물쇠 달기.

개발자가 묻습니다. 클라우드 쪽에서는 막을 방법이 없나요?

박 선임이 답합니다. 아이엠디에스 버전 투를 강제해요. 버전 원은 겟 요청 한 번이면 바로 자격 증명을 줬어요. 버전 투는 먼저 풋 요청으로 세션 토큰을 받아야 하고, 그 토큰을 헤더에 넣어야만 메타데이터를 줘요. 에스에스알에프는 보통 공격자가 주소만 조작할 수 있어서, 요청 방식을 풋으로 바꾸거나 헤더를 넣기 어려워요. 또 응답이 거쳐 갈 수 있는 홉 수를 제한해서 다른 곳으로 넘어가지 못하게 해요.

박 선임이 애플리케이션 쪽 대응도 정리합니다. 이미지를 받아 올 수 있는 도메인을 화이트리스트로 정합니다. 사설 아이피 대역과 백이십칠 점 영 점 영 점 일, 백육십구 점 이백오십사 대역으로 가는 요청은 막습니다. 리다이렉트를 따라가다 내부 주소로 빠지지 않도록 리다이렉트도 따라가지 않습니다.

정리합니다. 아이엠디에스 버전 투. 세션 토큰을 먼저 받아야 메타데이터를 주는 방식이라 에스에스알에프에 의한 자격 증명 탈취를 어렵게 합니다.


세 번째 장면. 핑 기능에 붙은 세미콜론.

같은 공격자가 관리자 페이지의 네트워크 점검 기능도 건드렸습니다. 아이피를 입력하면 서버가 핑을 쳐서 결과를 보여 주는 기능입니다. 입력값은 일 이 칠 점 영 점 영 점 일, 세미콜론, 캣 슬래시 이티씨 슬래시 패스워드였습니다.

박 선임이 말합니다. 운영체제 명령어 삽입이에요. 코드가 핑 명령 뒤에 입력값을 그대로 붙여서 셸에서 실행하고 있었어요. 세미콜론은 앞 명령이 끝나고 다음 명령을 실행하라는 뜻이라, 핑 다음에 패스워드 파일을 읽는 명령이 실행된 거죠. 파이프 기호나 앰퍼샌드 두 개, 백틱도 같은 역할을 해요.

여기서 잠깐 떠올려 보세요. 운영체제 명령어 삽입을 막는 가장 근본적인 방법은 무엇일까요?

답입니다. 외부 입력을 운영체제 명령으로 직접 실행하지 않도록 설계를 바꾸는 것입니다. 자바라면 런타임 점 익젝으로 입력을 바로 넘기지 않습니다. 꼭 필요하면 허용할 값만 화이트리스트로 정하고, 세미콜론이나 파이프 같은 명령 연결 문자를 걸러 냅니다.

정리합니다. 운영체제 명령어 삽입. 입력값에 명령 연결 문자를 넣어 서버에서 임의 명령을 실행하는 공격.


네 번째 장면. 점점 슬래시를 따라 올라가기.

다음은 공지사항 첨부 파일 다운로드 기능이었습니다. 정상 요청은 다운로드 점 제이에스피, 물음표, 파일 이퀄 공지 점 피디에프였습니다. 공격자의 요청은 파일 이퀄 다음에 점점 슬래시가 여러 번 반복되고, 끝에 이티씨 슬래시 패스워드가 붙어 있었습니다.

박 선임이 말합니다. 경로 조작, 그리고 파일 다운로드 취약점이에요. 점 두 개는 상위 디렉터리라는 뜻이에요. 점점 슬래시를 충분히 반복하면 첨부 파일 폴더에서 최상위까지 올라가서, 서버의 아무 파일이나 내려받을 수 있어요.

여기서 잠깐 떠올려 보세요. 이 공격을 막는 방법은 무엇일까요?

답입니다. 파일 이름을 파라미터로 직접 받지 않고, 데이터베이스에 저장한 파일 번호로 받습니다. 경로를 받아야 한다면 점점 슬래시나 백슬래시 같은 경로 문자를 걸러 내고, 정해진 다운로드 폴더 밖으로 나가지 못하게 경로를 검사합니다.

정리합니다. 경로 조작. 점점 슬래시로 상위 디렉터리로 이동해 허용되지 않은 파일에 접근하는 공격.


다섯 번째 장면. 남의 파일을 내 코드로 끼워 넣기.

마지막으로 피에이치피로 만든 옛 이벤트 페이지가 있었습니다. 주소에 페이지 이퀄 메인을 주면, 코드가 인클루드 함수로 메인 점 피에이치피를 불러오는 구조였습니다.

공격자는 두 가지를 시도했습니다. 하나는 페이지 값에 점점 슬래시를 붙여 서버 안의 로그 파일을 불러오게 했습니다. 다른 하나는 페이지 값에 외부 공격자 서버의 주소를 넣었습니다.

박 선임이 말합니다. 앞의 것은 로컬 파일 인클루전, 엘에프아이예요. 서버 안에 있는 파일을 인클루드시켜요. 뒤의 것은 리모트 파일 인클루전, 알에프아이예요. 외부 서버에 있는 악성 스크립트를 인클루드시켜서 우리 서버에서 실행하게 만들어요. 다운로드는 파일을 내주기만 하지만, 인클루전은 그 파일을 코드로 실행한다는 게 무서운 점이에요.

여기서 잠깐 떠올려 보세요. 리모트 파일 인클루전을 막는 피에이치피 설정은 무엇일까요?

답입니다. 피에이치피 설정 파일인 피에이치피 점 아이엔아이에서 얼라우 유알엘 인클루드와 얼라우 유알엘 에프오픈을 오프로 둡니다. 그러면 인클루드나 리콰이어 함수로 외부 주소를 불러올 수 없습니다. 기존 실기 문항에 인클루드와 리콰이어, 피에이치피 점 아이엔아이, 오프를 빈칸으로 채우는 문제가 있었습니다.


여섯 번째 장면. 네 사건의 공통점.

개발자가 말합니다. 하루에 네 가지를 봤는데, 다 비슷한 실수 같아요.

박 선임이 답합니다. 맞아요. 전부 사용자가 준 값을 서버가 그대로 믿었어요. 에스에스알에프는 주소를, 명령어 삽입은 명령 인자를, 경로 조작은 파일 경로를, 인클루전은 불러올 파일 이름을 믿었죠.

박 선임이 공통 원칙을 정리합니다. 첫째, 검증은 서버에서 합니다. 둘째, 막을 값을 나열하는 블랙리스트보다 허용할 값만 정하는 화이트리스트가 안전합니다. 블랙리스트는 인코딩이나 새로운 기호로 우회되기 쉽습니다. 셋째, 웹 서버 프로세스에 최소 권한만 줍니다. 뚫리더라도 읽을 수 있는 파일과 실행할 수 있는 명령이 줄어듭니다.

여기서 잠깐 떠올려 보세요. 블랙리스트와 화이트리스트 중 입력 검증에 더 안전한 쪽은 무엇일까요?

답입니다. 화이트리스트입니다.


오늘의 정리.

에스에스알에프. 서버가 공격자 대신 내부 주소로 요청을 보낸다. 대응은 허용 도메인 화이트리스트, 내부 대역 차단.
아이엠디에스 버전 투. 세션 토큰을 먼저 받아야 메타데이터를 준다.
운영체제 명령어 삽입. 세미콜론, 파이프로 명령을 이어 붙인다. 대응은 외부 입력을 명령으로 직접 실행하지 않기.
경로 조작과 파일 다운로드. 점점 슬래시로 상위 폴더로 올라간다. 대응은 파일 번호로 받기, 경로 문자 필터링.
로컬 파일 인클루전은 서버 안의 파일을, 리모트 파일 인클루전은 외부 파일을 인클루드해 실행.
대응은 얼라우 유알엘 인클루드와 얼라우 유알엘 에프오픈을 오프로.

다음 편은 아파치 점검의 날입니다. 디렉터리 리스팅과 서버 정보 노출을 만납니다.
