정보보안기사 실기 라디오. 1편. 웹셸 업로드 사건.

오늘 나오는 용어는 일곱 개입니다. 파일 업로드 취약점, 웹셸, 액세스 로그, 리버스 셸, 셋유아이디, 더블유티엠피, 피에이씨씨티. 사건을 따라가면서 하나씩 만나 보겠습니다.


첫 번째 장면. 이상한 이미지 파일.

월요일 아침, 쇼핑몰 서버의 시피유 사용률이 밤새 백 퍼센트였다는 알림이 왔습니다. 개발자가 보안팀 박 선임을 찾아갑니다.

개발자가 말합니다. 밤사이 누가 서버에서 뭘 돌린 것 같아요. 그런데 관리자 계정으로 로그인한 기록은 없어요.

박 선임이 답합니다. 로그인 없이 서버에서 명령을 실행했다면, 먼저 웹으로 들어온 길부터 의심해야 해요. 게시판에 첨부 파일 올리는 기능 있죠? 업로드 폴더를 열어 봐요.

업로드 폴더에는 사진 파일들 사이에 이름이 이상한 파일이 하나 있었습니다. 셸 점 피에이치피. 이미지가 아니라 피에이치피 스크립트 파일입니다.

개발자가 묻습니다. 우리 게시판은 이미지만 올라가게 막아 놨는데요?

박 선임이 코드를 확인합니다. 업로드 검사 코드는 요청에 들어 있는 콘텐츠 타입 헤더만 보고 있었습니다. 이미지 지아이에프라고 적혀 있으면 통과시키는 방식입니다.

박 선임이 설명합니다. 콘텐츠 타입은 브라우저가 보내는 값이라서 공격자가 프록시 도구로 얼마든지 바꿀 수 있어요. 파일은 피에이치피인데 헤더만 이미지라고 속인 거예요. 이게 파일 업로드 취약점이에요.

정리합니다. 파일 업로드 취약점. 업로드 파일의 종류를 제대로 검증하지 않아서, 서버에서 실행되는 스크립트 파일이 올라가는 취약점입니다. 우회 방법으로는 콘텐츠 타입 변조, 이중 확장자, 파일 앞부분의 매직 바이트 위조가 있습니다.


두 번째 장면. 명령을 받아 실행하는 파일.

개발자가 셸 점 피에이치피 파일을 열어 봅니다. 코드는 단 한 줄입니다. 주소창으로 들어온 씨엠디 값을 셸 익스펙 함수로 실행하라는 내용입니다.

박 선임이 말합니다. 이게 웹셸이에요. 웹 브라우저 주소창이 그대로 서버의 명령창이 되는 거죠. 공격자는 주소 끝에 물음표 씨엠디 이퀄 다음에 명령어만 붙이면 돼요.

여기서 잠깐 떠올려 보세요. 웹셸이 실행되려면 두 가지 조건이 필요합니다. 무엇일까요?

답입니다. 첫째, 업로드된 파일을 외부에서 주소로 호출할 수 있어야 합니다. 둘째, 그 폴더에서 피에이치피 같은 서버 스크립트가 실행될 수 있어야 합니다. 그래서 대응도 이 두 조건을 끊는 쪽으로 갑니다.

정리합니다. 웹셸. 웹 서버에 올린 악성 스크립트로, 원격에서 서버 명령을 실행하게 해 주는 파일입니다.


세 번째 장면. 로그에 남은 발자국.

개발자가 묻습니다. 그럼 언제 올라왔고 뭘 했는지는 어떻게 알아요?

박 선임이 답합니다. 아파치 웹 서버의 액세스 로그를 봐요. 웹으로 들어온 요청은 전부 한 줄씩 남아요. 접속한 아이피, 시간, 요청 방식, 주소, 응답 코드가 기록돼요.

로그를 보니 새벽 두 시 십 분, 한 외부 아이피가 게시판 글쓰기 주소로 포스트 요청을 보냈습니다. 응답 코드는 이백, 성공입니다. 일 분 뒤 같은 아이피가 업로드 폴더의 셸 점 피에이치피를 겟 요청으로 호출했습니다. 주소 끝에는 씨엠디 이퀄 아이디, 씨엠디 이퀄 유네임이 붙어 있었습니다.

박 선임이 말합니다. 포스트로 파일을 올리고, 겟으로 웹셸을 불러서 명령을 실행한 거예요. 처음에 아이디랑 유네임을 친 건 내가 어떤 계정인지, 어떤 시스템인지 확인한 거고요.

액세스 로그와 짝이 되는 파일이 하나 더 있습니다. 에러 로그입니다. 액세스 로그는 들어온 요청, 에러 로그는 서버에서 난 오류를 기록합니다.

정리합니다. 아파치 액세스 로그. 웹 요청 기록. 에러 로그. 웹 서버 오류 기록. 공격 흔적을 찾을 때는 액세스 로그에서 업로드 요청과 의심스러운 파라미터를 찾습니다.


네 번째 장면. 서버가 먼저 전화를 건다.

로그 마지막 줄의 씨엠디 값은 길었습니다. 에스에이치 하이픈 아이, 그리고 슬래시 데브 슬래시 티씨피 슬래시 다음에 외부 아이피와 포트 번호가 붙어 있었습니다.

개발자가 묻습니다. 이건 뭐예요?

박 선임이 답합니다. 리버스 셸이에요. 우리 서버가 공격자 컴퓨터로 먼저 접속해서, 자기 셸을 넘겨주는 명령이에요. 방화벽은 보통 밖에서 들어오는 연결은 막지만, 안에서 나가는 연결은 잘 안 막잖아요. 그 틈을 노린 거예요.

여기서 잠깐 떠올려 보세요. 웹셸과 리버스 셸은 접속 방향이 반대입니다. 각각 누가 누구에게 접속할까요?

답입니다. 웹셸은 공격자가 웹 서버로 요청을 보냅니다. 리버스 셸은 피해 서버가 공격자에게 접속합니다.

정리합니다. 리버스 셸. 피해 서버가 공격자 쪽으로 연결을 맺고 셸을 넘겨주는 기법. 대응은 서버에서 밖으로 나가는 연결을 제한하는 이그레스 필터링입니다.


다섯 번째 장면. 루트가 되는 지름길.

웹셸로 들어온 공격자의 계정은 아파치였습니다. 권한이 낮은 웹 서비스 계정입니다. 그런데 서버에는 이상한 계정이 하나 새로 생겨 있었습니다. 계정을 만들려면 루트 권한이 필요합니다.

개발자가 묻습니다. 아파치 계정으로 어떻게 루트가 됐죠?

박 선임이 답합니다. 셋유아이디 파일을 찾았을 거예요. 셋유아이디가 걸린 파일은 누가 실행하든 파일 주인의 권한으로 돌아요. 주인이 루트면 실행하는 동안 루트 권한을 갖는 거죠. 그런 파일에 취약점이 있으면 루트 셸을 얻을 수 있어요.

박 선임이 셋유아이디 파일을 찾는 명령을 알려 줍니다. 파인드 슬래시, 하이픈 펌, 하이픈 사천, 하이픈 타입 에프. 사천은 셋유아이디를 뜻하는 숫자입니다. 셋지아이디는 이천, 스티키 비트는 천입니다.

여기서 잠깐 떠올려 보세요. 필요 없는 셋유아이디를 없애는 명령은 무엇일까요?

답입니다. 시에이치모드 하이픈 에스. 실제로 2026년 2회 실기에 이 명령과 사천, 이천 숫자가 그대로 나왔습니다.

정리합니다. 셋유아이디, 사천. 실행하는 동안 파일 소유자 권한을 얻습니다. 셋지아이디, 이천. 소유 그룹 권한을 얻습니다. 스티키 비트, 천. 공유 폴더에서 남의 파일을 지우지 못하게 합니다.


여섯 번째 장면. 로그인 기록이 없는 이유.

개발자가 처음 품었던 의문으로 돌아갑니다. 그런데 왜 로그인 기록이 없었을까요?

박 선임이 답합니다. 로그인 기록은 더블유티엠피 파일에 남아요. 라스트 명령으로 보죠. 그런데 공격자는 로그인을 한 적이 없어요. 웹셸로 명령만 실행했으니까 더블유티엠피에는 아무것도 안 남은 거예요. 로그인 기록이 깨끗하다고 안심하면 안 되는 이유예요.

개발자가 묻습니다. 그럼 공격자가 친 명령은 어디서 봐요?

박 선임이 답합니다. 피에이씨씨티요. 프로세스 어카운팅 기록이에요. 사용자가 실행한 명령이 남고, 라스트컴 명령으로 봐요. 다만 미리 켜 둬야 기록돼요. 켜는 명령은 액셉톤이에요.

라스트컴 결과에는 아파치 계정이 실행한 아이디, 유네임, 파인드, 그리고 유저애드 명령이 차례대로 찍혀 있었습니다.

여기서 잠깐 떠올려 보세요. 로그인 실패 기록은 어느 파일에, 어떤 명령으로 볼까요?

답입니다. 비티엠피 파일, 라스트비 명령입니다. 짝으로 외우세요. 더블유티엠피는 라스트, 비티엠피는 라스트비, 피에이씨씨티는 라스트컴입니다.


일곱 번째 장면. 문 닫기.

박 선임이 대응 순서를 정리합니다.

첫째, 웹셸 파일을 지우기 전에 증거로 복사하고 해시값을 남깁니다.
둘째, 업로드는 허용할 확장자만 받는 화이트리스트 방식으로 바꿉니다. 콘텐츠 타입만 믿지 않습니다.
셋째, 업로드 폴더에서는 스크립트가 실행되지 않게 합니다. 피에이치피라면 피에이치피 어드민 플래그 엔진 오프 설정입니다.
넷째, 업로드 파일은 웹 루트 바깥에 저장해서 주소로 직접 부를 수 없게 합니다.
다섯째, 필요 없는 셋유아이디를 시에이치모드 하이픈 에스로 제거합니다.
여섯째, 서버에서 밖으로 나가는 연결을 제한해서 리버스 셸을 막습니다.

개발자가 말합니다. 결국 업로드 하나 뚫린 게 루트 권한까지 이어졌네요.

박 선임이 답합니다. 그래서 실무형 문제가 로그 한 장을 주고 처음부터 끝까지 따라가 보라고 하는 거예요.


오늘의 정리.

파일 업로드 취약점. 실행 가능한 스크립트가 올라가는 취약점. 콘텐츠 타입 변조로 우회.
웹셸. 주소창으로 서버 명령을 실행하게 하는 악성 스크립트.
아파치 액세스 로그. 웹 요청 기록. 에러 로그는 오류 기록.
리버스 셸. 피해 서버가 공격자에게 먼저 접속. 대응은 이그레스 필터링.
셋유아이디 사천, 셋지아이디 이천, 스티키 비트 천. 찾기는 파인드 하이픈 펌, 제거는 시에이치모드 하이픈 에스.
더블유티엠피는 라스트, 비티엠피는 라스트비, 피에이씨씨티는 라스트컴.

다음 편은 디도스 사건입니다. 스머프, 랜드, 티어드롭, 그리고 엔티피 증폭 공격을 만납니다.
