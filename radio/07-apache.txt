정보보안기사 실기 라디오. 7편. 아파치 점검의 날.

오늘 나오는 용어는 여덟 개입니다. 디렉터리 리스팅, 인덱시스, 팔로우 심 링크스, 서버 토큰스, 서버 시그니처, 트레이스 메서드, 에이치티 액세스 인증, 로봇츠 점 텍스트. 이번 편은 사고가 아니라 점검입니다. 사고가 나기 전에 아파치 설정 파일을 한 줄씩 고쳐 봅니다.


첫 번째 장면. 폴더 안이 다 보인다.

금요일 오전, 외부 보안 점검 업체가 결과 보고서를 보냅니다. 첫 번째 지적 사항은 이렇습니다. 쇼핑몰 주소 뒤에 슬래시 업로드 슬래시를 붙이면, 폴더 안의 파일 목록이 전부 보인다.

개발자가 직접 접속해 봅니다. 화면에는 인덱스 오브 슬래시 업로드라는 제목과 함께 고객이 올린 파일 이름이 줄줄이 나왔습니다.

박 선임이 말합니다. 디렉터리 리스팅 취약점이에요. 폴더에 인덱스 점 에이치티엠엘 같은 기본 페이지가 없으면, 아파치가 대신 폴더 안의 파일 목록을 만들어 보여 줘요. 공격자는 이 목록으로 백업 파일이나 설정 파일 같은 걸 찾아내요.

박 선임이 아파치 설정 파일, 에이치티티피디 점 콘프를 엽니다. 디렉터리 설정 안에 옵션스 인덱시스 팔로우 심 링크스라는 줄이 있었습니다.

여기서 잠깐 떠올려 보세요. 디렉터리 리스팅을 없애려면 이 줄에서 무엇을 지워야 할까요?

답입니다. 인덱시스입니다. 지우거나 앞에 하이픈을 붙여 하이픈 인덱시스로 씁니다. 2025년 2회 실기에 이 설정 블록을 그대로 주고 삭제할 구문을 쓰게 했습니다.

정리합니다. 디렉터리 리스팅. 기본 페이지가 없는 폴더의 파일 목록이 노출되는 취약점. 대응은 옵션스에서 인덱시스 제거.


두 번째 장면. 링크를 따라 웹 루트 밖으로.

같은 줄에 남은 팔로우 심 링크스도 점검 대상이었습니다.

박 선임이 설명합니다. 팔로우 심 링크스는 웹 폴더 안의 심볼릭 링크를 따라가도록 허용하는 옵션이에요. 누군가 웹 폴더 안에 루트 디렉터리를 가리키는 링크를 만들어 두면, 웹으로 서버 전체 파일을 볼 수 있게 돼요. 필요 없으면 이것도 지워요.

점검 보고서는 상위 디렉터리 접근도 함께 지적했습니다. 웹 루트 밖 폴더에 대해서는 디렉터리 블록에 리콰이어 올 디나이드를 걸고, 에이치티 액세스 파일로 설정을 바꿀 수 있는 범위를 정하는 얼라우 오버라이드도 필요한 만큼만 열어 두도록 했습니다.

정리합니다. 팔로우 심 링크스. 심볼릭 링크를 따라가는 옵션. 웹 루트 밖 파일이 노출될 수 있어 제거합니다.


세 번째 장면. 묻지도 않았는데 알려 주는 버전.

두 번째 지적 사항은 서버 정보 노출이었습니다. 존재하지 않는 페이지를 요청하자, 사백사 오류 화면 맨 아래에 아파치 버전과 운영체제 이름이 찍혔습니다. 응답 헤더의 서버 항목에도 같은 정보가 있었습니다.

박 선임이 말합니다. 버전을 알면 공격자는 그 버전의 알려진 취약점부터 찾아요. 정보를 줄여야 해요. 서버 토큰스를 프로드로 바꾸면 응답 헤더에 아파치라는 이름만 나가요. 서버 시그니처를 오프로 바꾸면 오류 페이지 아래의 서버 정보가 사라져요.

여기서 잠깐 떠올려 보세요. 피에이치피를 쓰는 서버라면 응답 헤더에 피에이치피 버전도 나갈 수 있습니다. 이걸 숨기는 설정은 무엇일까요?

답입니다. 피에이치피 점 아이엔아이의 익스포즈 피에이치피를 오프로 둡니다. 오류 내용이 화면에 나오지 않도록 디스플레이 에러스도 오프로 둡니다.

정리합니다. 서버 토큰스 프로드, 서버 시그니처 오프. 서버 버전 정보 노출을 줄이는 설정.


네 번째 장면. 쓰지 않는 메서드.

세 번째 지적 사항은 불필요한 에이치티티피 메서드였습니다. 점검 업체는 텔넷으로 웹 서버에 접속해서 옵션스 요청을 보냈고, 응답의 얼라우 헤더에 겟, 헤드, 포스트, 옵션스, 트레이스가 모두 나왔습니다.

박 선임이 설명합니다. 옵션스는 서버가 어떤 메서드를 허용하는지 알려 줘요. 점검할 때는 편하지만 공격자에게도 정보를 줘요. 트레이스는 받은 요청을 그대로 되돌려 주는 메서드인데, 엑스에스에스와 엮이면 쿠키 같은 헤더가 노출될 수 있어서 크로스 사이트 트레이싱 공격에 쓰여요. 트레이스 이네이블 오프로 끕니다. 그리고 리밋 익셉트로 겟과 포스트처럼 꼭 필요한 메서드만 허용해요.

여기서 잠깐 떠올려 보세요. 서버의 응답 헤더만 받아 보고 바디는 받지 않는 메서드는 무엇일까요?

답입니다. 헤드입니다. 겟과 같지만 응답에 바디가 없고 상태와 헤더만 돌아옵니다.

정리합니다. 불필요한 메서드 제한. 트레이스 이네이블 오프, 리밋 익셉트로 필요한 메서드만 허용.


다섯 번째 장면. 관리자 페이지와 로봇에게 보내는 안내문.

네 번째 지적 사항은 관리자 페이지였습니다. 주소 뒤에 슬래시 어드민만 붙이면 관리자 로그인 화면이 누구에게나 열렸습니다.

박 선임이 말합니다. 관리자 페이지 노출 취약점이에요. 첫째, 주소를 추측하기 어렵게 바꿔요. 둘째, 회사 아이피에서만 접속되게 리콰이어 아이피로 제한해요. 셋째, 한 겹 더 인증을 걸어요. 그게 에이치티 액세스 인증이에요.

박 선임이 관리자 폴더에 점 에이치티 액세스 파일을 만들며 설명합니다. 어스 타입 베이직으로 기본 인증을 쓰겠다고 정합니다. 어스 네임은 로그인 창에 보일 영역 이름입니다. 어스 유저 파일은 아이디와 비밀번호를 저장한 파일의 경로입니다. 리콰이어 밸리드 유저는 그 파일에 있는 사용자만 들어올 수 있다는 뜻입니다. 비밀번호 파일은 에이치티패스워드 명령으로 만듭니다.

마지막 지적 사항은 로봇츠 점 텍스트였습니다. 파일 안에 디스얼라우 슬래시 어드민, 디스얼라우 슬래시 백업이 적혀 있었습니다.

박 선임이 말합니다. 로봇츠 점 텍스트는 검색 엔진 로봇에게 이 경로는 수집하지 말라고 알려 주는 규약이에요. 검색 결과에 관리자 페이지가 뜨지 않게 하는 데는 도움이 돼요. 그런데 강제력은 없고, 누구나 열어 볼 수 있어요. 숨기고 싶은 경로를 여기 적으면 오히려 공격자에게 지도를 주는 셈이에요.

여기서 잠깐 떠올려 보세요. 에이치티 액세스 인증에서 인증 사용자 목록이 담긴 파일 경로를 지정하는 지시어는 무엇일까요?

답입니다. 어스 유저 파일입니다. 기존 실기 문항에 어스 네임, 어스 유저 파일, 리콰이어 세 개를 빈칸으로 채우는 문제가 있었습니다.


여섯 번째 장면. 누구의 권한으로 도는가.

점검 보고서의 마지막 장은 웹 서비스 운영 계정이었습니다. 아파치 프로세스 일부가 루트 권한으로 요청을 처리하고 있었습니다.

박 선임이 설명합니다. 웹 서버가 루트로 요청을 처리하면, 웹셸 하나만 올라가도 공격자가 바로 루트가 돼요. 그래서 에이치티티피디 점 콘프의 유저와 그룹 지시어에 권한이 낮은 전용 계정, 예를 들어 아파치나 노바디를 지정해요. 포트를 여는 처음 프로세스만 루트로 시작하고, 실제 요청을 처리하는 프로세스는 이 계정으로 돌아요.

박 선임이 덧붙입니다. 설치할 때 따라온 매뉴얼 폴더와 샘플 파일도 지워요. 버전을 알려 주고, 오래된 샘플 스크립트에는 취약점이 있는 경우가 많아요. 업로드 용량은 지난 편에서 본 리밋 리퀘스트 바디로 제한하고요.

여기서 잠깐 떠올려 보세요. 아파치 요청 처리 프로세스의 실행 계정을 정하는 지시어는 무엇일까요?

답입니다. 유저와 그룹입니다. 루트가 아닌 전용 계정을 지정합니다.


오늘의 정리.

디렉터리 리스팅. 폴더 파일 목록 노출. 옵션스에서 인덱시스 제거.
팔로우 심 링크스. 심볼릭 링크로 웹 루트 밖 파일 노출. 필요 없으면 제거.
서버 토큰스 프로드, 서버 시그니처 오프. 버전 정보 노출 차단. 피에이치피는 익스포즈 피에이치피 오프.
옵션스로 허용 메서드 확인. 트레이스 이네이블 오프, 리밋 익셉트로 필요한 메서드만.
관리자 페이지. 아이피 제한, 에이치티 액세스 인증. 어스 타입, 어스 네임, 어스 유저 파일, 리콰이어 밸리드 유저.
로봇츠 점 텍스트. 검색 로봇 수집 제한 규약. 보안 수단은 아니다.

다음 편은 새벽 3시 침입 사건입니다. 리눅스 로그 파일과 확인 명령어를 짝지어 만납니다.
